# T7.2 — Make the gallery media-aware (videos included)

## Goal

The profile gallery must show every media attachment, not just still images.
On `onlyfans/39058172` it currently renders 18 275 images and hides 756 videos
and 3 MP4-backed "gifs". After this ticket, `/c/2/gallery` shows videos in the
same grid, with a kind filter and a lightbox that can actually play them.

## Scope

**Data layer (`db.py`)**

- [ ] Replace the literal `f.kind IN ('image', 'gif')` in `_gallery_where` with
      `GALLERY_KINDS`, extended to include `video` (and decide `audio`:
      recommended: include it as a tile with a play glyph, or exclude it and say
      so in the UI).
- [ ] Add a `kind` filter to `GalleryFilters` / `_gallery_where`:
      `all` (default), `image`, `video`, `gif`, `audio`. Validate against a
      known set; unknown values fall back to `all`.
- [ ] `list_gallery_images` keeps one row per `sha256` and returns `kind`,
      `mime_type`, `duration_ms` and `variants`/`variants_json` so the template
      can decide still vs video without extra queries.
- [ ] `gallery_stats` returns `images`, `videos`, `gifs`, `audio`, `posts`
      and `files`; "posts" means posts contributing at least one eligible file.
- [ ] `gallery_tag_facets` uses the same eligible-kind set instead of
      `('image','gif')`.
- [ ] Keep the query shape index-friendly (`files_kind` on `(kind, post_id)`);
      confirm no full scan on the reference archive.

**Rendering (`gallery.html`, `style.css`)**

- [ ] Header: `18275 images · 756 videos · 3 gifs · across N posts` (omit zero
      segments). Never call the whole archive "images".
- [ ] Add a `Kind` select with All / Images / Videos / GIFs / Audio; it composes
      with the existing search, tag, orientation, size and date filters.
- [ ] Video tiles use the existing `img.cum.st/thumbnail/<sha>/preview.webp`
      thumbnail. Nothing from `e1/e2/e3.cum.st` may load on page render.
- [ ] Video tiles get a duration badge and a play glyph; GIF tiles keep the GIF
      badge.
- [ ] Tile filename fallback uses the real extension (`original.mp4` for video,
      `original.gif` for gif, `original.jpg` for image), not always `.jpg`.
- [ ] A "Videos" entry point on the creator page (header button or stat link)
      points at `/c/{id}/gallery?kind=video`. Bookmarkable and visible without
      JavaScript.

**Lightbox (`app.js`)**

- [ ] Extend the existing image lightbox with a `<video controls playsinline
      preload="none">` element, or build the media element on demand.
- [ ] Clicking a video tile sets the video `src` only then; closing removes the
      `src`, pauses playback and empties the element. No background downloads.
- [ ] Prev/next across mixed image/video results must switch element type
      correctly (hide the image while a video is active and vice versa).
- [ ] Keyboard `←`/`→`/`Esc`, click-outside, focus return and "Open original"
      keep working for both types.
- [ ] "Go to post" still links to the post containing the media.
- [ ] Without JavaScript, a video tile's `href` falls back to the edge URL (or
      the post page) and is labelled accordingly; no dead `#` link.

**Tests**

- [ ] Gallery with image + video rows: both counts and both tiles appear.
- [ ] `?kind=video` returns only the video(s); `?kind=image` excludes them;
      unknown `kind` is treated as `all`.
- [ ] `?kind=video&orientation=portrait` composes correctly.
- [ ] Dedupe still works when the same video sha appears in two posts.
- [ ] Header stats count videos separately and the old image-only assertion is
      updated.
- [ ] No full-size edge URL appears in `src=` on load; it only appears in
      `data-*` attributes.
- [ ] `?quiet=1` still produces a static grid.

## Acceptance criteria

- [ ] On creator 2, `GET /c/2/gallery` reports at least 756 videos and renders
      756 distinct video tiles across pages (up to the 60-per-page limit).
- [ ] `GET /c/2/gallery?kind=video` page 1 contains only video tiles.
- [ ] Opening a video tile plays it in the lightbox; closing stops it and
      removes the `src`.
- [ ] Page load issues zero requests to `e1/e2/e3.cum.st`.
- [ ] The default gallery total equals a direct SQL count of distinct eligible
      `sha256` values for creator 2 after T7.1.
- [ ] Default and `?kind=video` pages render in under 300 ms locally on the
      reference archive.
- [ ] Existing gallery tests (render, dedupe, pagination, filters, empty state,
      404) pass after being updated for the all-media default.

## Out of scope

- Downloading or mirroring videos.
- A global cross-creator gallery.
- Slideshow/autoplay mode.
- Reworking the post page (T7.4).

## Notes

- T4.7 explicitly deferred video tiles; this ticket supersedes that line and
  should update T4.7's "Out of scope" note.
- Three SQLite rows still have `kind='gif'` until T7.1 runs. This ticket must be
  tested after the normalization so MP4-backed gifs land in the video branch.
- `audio` support is optional if it complicates the lightbox; if excluded, the
  kind filter must not offer it and the stats must not count it.
