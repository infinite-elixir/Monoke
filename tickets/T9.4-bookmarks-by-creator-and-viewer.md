# T9.4 — Group bookmarks by creator and add a bookmark-only viewer

## Goal

Make `/bookmarks` read like a library of creators rather than one flat archive
dump: every creator gets a section with a **short preview of their bookmarks**
(6 items), plus a clear "view all" link for that creator.

Media bookmarks become playable in the fullscreen viewer. Opening one starts
on that exact bookmark, and previous/next move **bookmark to bookmark** in the
library order. Unbookmarked media in those posts and unbookmarked posts are
never destinations.

## Current behaviour

- T9.3 renders one flat **Posts** section and one flat **Media** section for
  every creator, capped by `PER_PAGE` / `GALLERY_PER_PAGE`, with a creator
  filter `<select>`.
- Media bookmark tiles are plain links to the remote file (`target="_blank"`),
  so T8's fullscreen viewer is not used from the library.
- T8's viewer is creator- and post-scoped. It embeds one post's media and
  crosses to neighbouring posts with `previous_post` / `next_post`. That model
  would walk every image in a post and every media post, including items the
  user never bookmarked.
- `media_bookmarks` is keyed by `(creator_id, sha256)` and carries
  `created_at`; `list_media_bookmarks()` already returns the fields the viewer
  needs, plus `missing` when the attachment disappeared upstream.

## Decisions

- **6** is the preview cap: `BOOKMARKS_PER_CREATOR_PREVIEW = 6` in
  `web/filters.py`.
- The cap applies only to the **unfiltered overview** (`/bookmarks` with no
  `creator`). Selecting a creator removes the cap and shows that creator's full
  paginated list using the existing tabs and pagers.
- `view=all` previews mix post and media bookmarks, newest bookmark first.
  `view=posts` previews only post bookmarks; `view=media` previews only media
  bookmarks. A creator section only appears if it has an item in the active
  view.
- The viewer playlist is **all media bookmarks in the current scope**, not the
  6-item preview: when opened from a creator section or a creator-filtered
  page, the scope is that creator; otherwise it spans creators. Order is
  `media_bookmarks.created_at DESC, id DESC`.
- The viewer is a flat playlist in this mode. It does not cross posts, preload
  neighbouring posts, or expose unbookmarked media.

## Scope

**Repository and grouping (`db.py`, `web/filters.py`)**

- [x] Add `BOOKMARKS_PER_CREATOR_PREVIEW = 6`; do not change `PER_PAGE` or
      `GALLERY_PER_PAGE`.
- [x] Add a repository function for the overview: given
      `view=all|posts|media`, return the creators that have qualifying
      bookmarks, their total count for that view, and at most 6 preview items
      per creator. A single windowed query (or at most two queries for posts
      and media merged in Python) is acceptable; **no query per creator**.
- [x] Preview items expose the same shapes the existing post cards and media
      tiles consume, plus a stable `bookmark_id` and `kind` (`post` or
      `media`). Media previews reuse `_decorate_library_media()`.
- [x] Creator sections are ordered by their newest qualifying bookmark
      (`created_at DESC, id DESC`), then creator name, then creator id. This
      deliberately differs from the alphabetical filter list.
- [x] Keep `bookmark_creator_facets()` for the filter dropdown.
- [x] Add `bookmark_viewer_state(conn, bookmark_id, creator_id=None)`:
      - resolve the bookmark row and its creator;
      - reject a bookmark outside `creator_id` when that scope is supplied;
      - build the media playlist in library order with `missing = 0`;
      - include items from other creators when unscoped;
      - return `None` for an unknown bookmark id.
- [x] Playlist items carry per-item `bookmark_id`, `creator_id`,
      `creator_name`, `creator_url`, `post_title`, `post_url`, `sha256`,
      `kind`, `mime_type`, `url`, `thumb_url`, `width`, `height`,
      `duration_ms`, `bytes`, `original_filename`, `bookmarked=True`.
      There is no single `state.post` that can stand in for a mixed-creator
      playlist.
- [x] Use the existing `media_bookmarks_creator` index. Add an index only if
      `EXPLAIN QUERY PLAN` shows a scan that the index cannot serve.

**Overview page (`/bookmarks`)**

- [x] With no `creator` filter, replace the flat Posts/Media sections with
      **creator sections**:
      - header: creator name (linked to `/c/<id>`), per-view count, and a
        "View all N bookmarks" link;
      - body: up to 6 bookmark items for the active view, newest bookmark
        first;
      - `view=all` mixes post cards and media tiles; `view=posts` shows post
        cards; `view=media` shows media tiles.
- [x] The "View all" link preserves the active tab and targets
      `/bookmarks?view=<view>&creator=<id>` (`view=all` may omit the view
      parameter). It must land on the creator's full, paginated list, not
      another 6-item preview.
- [x] With a `creator` filter, keep T9.3's full **Posts** and **Media**
      sections and their independent pagers. The preview cap is lifted.
- [x] Keep the `view` tabs, creator filter, counts, empty states and removal
      forms. Removing a bookmark re-renders the same view/filter/page.
- [x] A creator whose 6 previews include a missing media bookmark still shows
      the existing "No longer attached" placeholder.
- [x] Mobile: one creator section per row; previews scroll or wrap without
      horizontal page overflow.

**Media bookmarks open the viewer**

- [x] Change a media bookmark tile from a remote-file link to a link to
      `/bookmarks/viewer?b=<bookmark_id>&view=<view>&creator=<id>&next=<current_url>`.
      Include `creator` when the item belongs to a specific creator section or
      the page is creator-filtered. The same URL is used from every tab.
- [x] Add `GET /bookmarks/viewer` (HTML). Required `b`; optional `creator`,
      `view`, `next`, `hint`, `quiet`. Unknown `b`, or `b` outside the supplied
      creator, is a 404. A missing attachment is still viewable as the existing
      viewer "Media unavailable" state and remains in the playlist.
- [x] Reuse `viewer.html` / `viewer.js` with a new payload discriminator, e.g.
      `"mode": "bookmarks"`, and a flat `media` array. Do not fake
      `previous_post` / `next_post`.
- [x] `mode=bookmarks` behaviour:
      - left/right, swipe and the left/right zones move to the previous/next
        **media bookmark** in the playlist; clamp at both ends with the normal
        toast, no wrap;
      - up/down and the top/bottom zones are disabled (hidden or inert) because
        there is no post axis;
      - the counter is `index + 1 / playlist length`;
      - alt text and the live announcer use the **current item's** post title
        and creator, not a stale `state.post`;
      - bookmark toggles post to `/c/<item.creator_id>/media/<sha>/bookmark`
        so mixed-creator playlists work;
      - the viewer never prefetches `viewer/data?post=` payloads; there are no
        intermediate posts to preload.
- [x] First-run hint copy in this mode says "Previous bookmark" / "Next
      bookmark" for left/right. Existing fullscreen, close, ESC and `F`
      behaviour is unchanged.
- [x] Toggling the current item's bookmark removes it from the library but does
      not eject the viewer mid-view; the library reflects the removal after
      closing. Navigating away skips it naturally on the next load.
- [x] The close/return URL comes from `next` only when it is a `/bookmarks`
      path (with its query string), otherwise fall back to `/bookmarks`.
      Preserve `view`, `creator` and `page`.

- [x] The tabs still narrow all three views, and the creator filter shows the

- [x] Clicking any media bookmark opens the fullscreen viewer on that exact

- [x] Across creators, each item opens/toggles its own creator's post and

## Out of scope

- New bookmark tables or toggle endpoints (T9.1), and adding bookmarks from
  the library.
- Search inside bookmarks, bulk select/remove, collections or notes.
- Changing the creator/gallery viewer's post-crossing behaviour (T8.6–T8.8) or
  implementing T8.9 fluid transitions and T8.10 finger-following swipe; the
  bookmark viewer should inherit those when they land.
- A bookmark-only "post bookmarks" viewer. Post bookmarks continue to open
  their post page.
- Paginating the viewer playlist itself; bookmarks are user-curated and the
  payload contains URLs/metadata only.

## Notes

- `list_media_bookmarks()` already filters missing rows only by keeping them in
  the list. The viewer playlist excludes `missing = 1` so users never land on
  an unpaintable item as a destination; the `b` item is the one exception so a
  stale tab does not 404 unnecessarily.
- Do not sum `PER_PAGE` and `GALLERY_PER_PAGE` for the 6-item mixed preview.
  Trim the merged, ordered items to 6 in Python or with the window function.
- The flat playlist changes the viewer's assumption that `state.creator`,
  `state.post` and `state.media` all describe one post. Audit every use in
  `viewer.js` (counter, alt text, announcer, toast, bookmark toggle, preload,
  neighbour jumps) before wiring the new mode.
- Keep the `?b=` parameter stable across refreshes; do not use a numeric index
  alone because removals reorder the library.
