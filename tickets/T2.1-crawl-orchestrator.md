# T2.1 — Full crawl orchestrator

## Goal
One call: URL in, complete creator archive out.

## Scope

- [x] `async crawl_full(ref, *, concurrency=4, progress=None) -> RunResult`.
- [x] Steps:
      1. `profile()` → upsert creator (display name, avatar/header URLs, timestamps).
      2. Page walk `offset = 0, 50, 100, …` **until an empty page**; read `total` from every
         response; dedupe IDs preserving first-seen order.
      3. Reconcile `len(ids)` vs `total`; attach a warning, never fail.
      4. Hand unseen IDs to the detail fan-out (T2.2).
      5. Store `post_count = total`, `last_synced_at`; finish the run.
- [x] Skip the list fetch entirely if the first page is empty (`total == 0`).
- [x] `RunResult`: `pages, posts_seen, posts_new, posts_updated, links_found, files_count,
      duration_s, warnings, error`.

## Acceptance criteria

- [x] Against fixtures: 782 ids, 16 list calls, no duplicates.
- [x] Empty-page termination: a fixture where `total` lies (e.g. 999) still stops at the first
      empty page and returns a warning.
- [x] Live run on `patreon/274608` stores exactly 782 posts in under 10 minutes at
      concurrency 4.
- [x] Re-running a completed crawl stores zero duplicates and reports `posts_new = 0`.
- [x] A hard network failure marks the run `failed` with the error message, not a traceback.

## Notes
- Offset pagination shifts when posts are added/deleted. ID dedupe handles adds; the `total`
  reconciliation surfaces deletions as a warning.
- Never trust `total` for loop termination.
