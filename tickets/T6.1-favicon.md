# T6.1 — Missing favicon.ico returns 404 on every page load

## Goal
Browsers request `/favicon.ico` automatically; the app has no route or file for it, producing a 404 in the server log on every page load and an extra failed request the browser retries.

## Scope
- [x] Add a static `favicon.ico` (or an SVG favicon) under `static/`.
- [x] Or add a route `GET /favicon.ico` returning 204/empty.
- [x] Update cache-busting `?v=` handling if needed.

## Acceptance criteria
- [x] `GET /favicon.ico` returns 200 (or 204) instead of 404.
- [x] No favicon 404 in server log during normal browsing.

## Resolution

`src/monoke/web/static/favicon.ico` (16 px + 32 px, 32-bit) is generated by
`tools/make_favicon.py` — no image library needed. `src/monoke/web/static/favicon.svg`
is the scalable version.

`GET /favicon.ico` now serves the real icon (`200`, `image/x-icon`,
`Cache-Control: public, max-age=86400`) instead of an empty `204`, and the
shell links both icons.

Verified by `tests/test_debug_ux.py::test_favicon_is_served_instead_of_404`
and a Firefox run over the index and creator pages: no `/favicon.ico` request
fails and no favicon line appears in the server log.
