# T11.9 — Media bookmark in the viewer top bar, no hint overlay

## Goal

Make bookmarking from the lightbox mean **bookmark this medium**, not
"bookmark the post". The visible bookmark control moves to the top-right of the
overlay beside the close button and writes a media bookmark for the current
image, GIF or video. The three-dot menu loses its post-bookmark action, so the
viewer can no longer add a post card to the library by accident.

Also remove the onboarding hint entirely. It only dismisses on arrow
navigation today, which makes tapping the screen look broken.

## Locked decisions (2026-10-22)

| Question | Decision |
|---|---|
| Top bookmark target | The current medium only (`sha256`), via the existing media bookmark endpoint. |
| Placement | Top-right, immediately left of the close button. |
| Post bookmarks in the viewer | Removed entirely; keep post bookmarking on creator rows, post pages and gallery/post cards. |
| Bookmarks library | Media bookmarks appear only in the **Media** section/tab. Post bookmarks appear only in **Posts**. |
| Gallery tile menu | The three-dot disclosure on a gallery card becomes a direct **media bookmark** button. No dropdown panel. |
| Hint | Remove the hint markup, styles, controller and its tests. No replacement onboarding UI. |

## Current behaviour

- The only visible bookmark control in the lightbox lives in the overflow menu
  and is a **post** bookmark (`data-bookmark-target="post"`). Clicking it adds a
  post card to `/bookmarks` **Posts**, even while an image/video is on screen.
- Media bookmarking exists in the viewer only behind the `b` keyboard shortcut;
  gallery tiles and post pages have their own media bookmark controls.
- The database already stores `post_bookmarks` and `media_bookmarks` separately;
  a media bookmark never inserts a post bookmark. The cross-section symptom is
  the menu control, not a repository bug.
- `viewer-hint` is shown on open in expanded/browser mode. Only an arrow/wheel/
  swipe navigation dismisses it; tapping or clicking the stage does not.
- There are `hint` and `quiet` query flags and hint-specific tests to remove.

## Scope

**Top media bookmark**

- [ ] Add exactly one media bookmark control to the overlay chrome, near the
      top-right and adjacent to `[data-lightbox-close]`. Use a dedicated hook
      such as `data-lightbox-media-bookmark`.
- [ ] The control is icon-only with an accessible label that names the current
      kind, e.g. **Bookmark image**, **Bookmark video**, **Bookmark GIF**, and
      **Remove bookmark** when pressed. Keep `aria-pressed` in sync.
- [ ] It applies to the visible item in compact, expanded and browser
      fullscreen modes, and stays available when the bottom bar is hidden.
- [ ] On activation, toggle
      `/c/{creator_id}/media/{sha256}/bookmark?format=json` for the current
      item, reusing the existing fetch/announce logic.
- [ ] Disable it only when there is no creator or no `sha256` for the visible
      item (for example a placeholder file); otherwise a missing attachment
      whose sha is known can still be un-bookmarked.
- [ ] After bookmarks change, update `currentItem`, the current payload item and
      any cached payloads exactly as the existing `b` shortcut does.
- [ ] Navigating to another medium re-syncs the pressed/label state. The top
      control must not keep the previous item's state.
- [ ] Keep a keyboard route to the same action (`b`). Do not add a separate
      post-bookmark shortcut or menu item back into the viewer.

**Remove the post bookmark from the viewer**

- [ ] Delete the post bookmark form/button from the overflow menu in
      `partials/lightbox.html`, including its action, `next` input and macro
      import if no longer needed there.
- [ ] Remove viewer click handling that toggles a post bookmark. Post
      bookmarking outside the overlay (creator rows, post page, post cards) is
      unchanged.
- [ ] Do not create a post bookmark as a side effect of a media bookmark.

**Gallery tile: three-dot menu becomes a bookmark button**

- [ ] Replace the per-tile `<details class="gallery-menu" data-gallery-menu>`
      disclosure (the `⋮` summary plus its panel) with a single direct
      **media bookmark** button in the same top-right position of the card.
- [ ] The button is the shared `bookmark_button` macro (compact) pointing at
      `/c/{creator_id}/media/{sha256}/bookmark` with `next` = the current
      gallery URL, so the no-JS form POST contract and the progressive JSON
      enhancement keep working.
- [ ] Its state is the tile's own media bookmark: `aria-pressed`, the
      `is-bookmarked` class, a filled glyph, and a label naming the kind
      ("Bookmark image: …", "Remove bookmark" when pressed).
- [ ] Clicking it must not open the viewer, navigate, or change the gallery
      filters/page. The tile thumbnail link keeps its own behaviour.
- [ ] It stays reachable by keyboard and has a comfortable touch target
      (44 px on coarse pointers) without covering the play badge or the tile
      title.
- [ ] Delete the now-dead dropdown plumbing: `data-gallery-menu` markup,
      `.gallery-menu`, `.gallery-menu-trigger`, `.gallery-menu-panel` rules and
      the `app.js` block that closes open `[data-gallery-menu][open]` details
      on outside click / Escape.
- [ ] Update the gallery tests that assert two `data-gallery-menu` triggers and
      two panels: each tile now has exactly one bookmark control and no
      three-dot trigger.

**Remove the hint**

- [ ] Delete `viewer-hint` markup from the overlay partial.
- [ ] Delete all `.viewer-hint*` rules, reduced-motion and narrow-screen hint
      rules from `style.css`.
- [ ] Delete the hint controller: `hint`, `hintDismissed`, `dismissHint`,
      `suppressHintForQuery`, `setMode()` hint reveal logic, and the
      `hint`/`quiet` query handling.
- [ ] Remove hint-specific tests and replace them with absence assertions.

**Tests**

- [ ] Template: exactly one top media bookmark hook beside the close button;
      the overflow menu has no `data-bookmark-form`, post action or
      `data-bookmark-target="post"`.
- [ ] Template: the media bookmark control has an icon-only label, pressed state
      and is not inside the hideable bottom controls.
- [ ] JS source/behaviour: the top control calls the media bookmark endpoint
      with the current `sha256`; menu/open paths never call the post bookmark
      endpoint; state re-syncs on `render`/`updateChrome`.
- [ ] Endpoint/library regression: bookmarking the current medium adds it to
      `view=media` and does not add a card to `view=posts` or the overview's
      post preview.
- [ ] Template: each gallery tile renders exactly one media bookmark control
      and no `data-gallery-menu` trigger/panel; the bookmark form action points
      at the media endpoint and keeps the gallery `next` URL.
- [ ] JS/CSS: no `data-gallery-menu` closing logic remains in `app.js` and no
      `.gallery-menu*` rules remain in the stylesheet.
- [ ] Template/CSS/JS: no `viewer-hint`, `data-lightbox-hint`, `hintDismissed`,
      `suppressHintForQuery` or `hint`/`quiet` query handling remains.
- [ ] `node --check src/monoke/web/static/lightbox.js` and `uv run pytest` pass.

## Acceptance criteria

- [ ] With an image, GIF or video open, the top-right bookmark icon saves or
      removes that medium.
- [ ] After bookmarking, the item appears under **Bookmarks → Media** and never
      as a post card under **Posts**.
- [ ] The overflow menu no longer contains a bookmark action.
- [ ] The pressed state follows prev/next to the new item.
- [ ] A gallery card shows a bookmark button instead of a three-dot menu, and
      bookmarking from a card adds that medium to **Bookmarks → Media**.
- [ ] No hint overlay appears on open, in any viewer mode.
- [ ] Tapping, clicking, swiping or pressing any key never reveals a hint.

## Out of scope

- Changing post bookmark controls outside the viewer.
- Changing the bookmark database schema, endpoints or library grouping beyond
  the regression checks above.
- Auto-bookmarking a post when one of its media is bookmarked.
- New onboarding or gesture-discovery UI.
- Changes to fullscreen, swipe navigation or the loading pill.

## Notes

- Reuse the existing `bookmark_button` macro styles for the top control if the
  markup stays simple; otherwise use the same `.lightbox-icon` button language
  as close/fullscreen so the 390 px top row does not overflow.
- The close button is always visible while the overlay is open, so the bookmark
  button should follow the same lifecycle rather than the hideable bar.
- The gallery tile menu only ever contained the media bookmark, so collapsing
  it into a direct button loses no action; keep the same endpoint and `next`
  value it used inside the panel.
- Removing the menu bookmark also removes the last viewer path that could
  produce the reported "media bookmark showed up as a post" confusion.
- Finish by deleting hint assertions in `tests/test_viewer.py` instead of
  leaving dead selectors in the test suite.
