# T12.10 — Pawchive fixtures, offline tests, live smoke, and docs

## Goal

Make pawchive support reproducible and reviewable: fixtures instead of live
probes, a live smoke test that is opt-in, and documentation that states the
limitations honestly.

## Scope

**Fixtures and harness**

- [ ] `tests/fixtures/pawchive/` is populated from T12.1 and checked in.
- [ ] `tests/conftest.py` fixture loader takes a source:
      `fixture("pawchive", "post_...json")` (keep the old call shape working).
- [ ] No offline test opens a socket; the existing autouse guard stays.

**Offline coverage**

- [ ] URL/registry tests for both sources.
- [ ] Adapter tests: profile, list, detail, tags, attachments, preview-only,
      dedupe, timestamps, errors.
- [ ] Transport tests: two bases, cache, retry, 403 HTML/JSON, 429 backoff.
- [ ] Crawler tests: pawchive list walk without total, incremental edit
      detection, blocked run, cancellation.
- [ ] Extraction/media tests: source-aware URLs, `preview_only`, null metadata.
- [ ] DB migration tests: v6 → v7, source coexistence, cascade, preview flag.
- [ ] Web tests: add/sync/browse/gallery/post/bookmarks for pawchive.
- [ ] Existing cum.st suites stay green without weakened assertions.

**Live smoke (opt-in)**

- [ ] `tests/live/test_live_pawchive.py`, marked `live`, skipped unless
      `MONOKE_LIVE=1`.
- [ ] Reads a creator URL from `MONOKE_LIVE_PAWCHIVE_CREATOR`; skips if unset.
- [ ] Uses `--limit`-style bounded sync (10–20 posts) and asserts profile,
      post rows, files, links and a second list-only pass.
- [ ] Never writes to `data/`; uses a temp data dir.
- [ ] Respects pacing; no parallel live tests.

**Docs**

- [ ] `README.md`: supported sources, pawchive URL examples, limitations
      (preview-only, no dimensions/duration, no total, rate limits).
- [ ] `docs/INSTALL_AND_USAGE.md`: add-creator flow for both sources, env vars,
      troubleshooting 403/blocked.
- [ ] `PLAN.md`: update the target-site section and architecture diagram.
- [ ] `docs/SOURCES.md`: final adapter contract and per-source capability table.
- [ ] `tickets/README.md`: statuses and build order reflect what shipped.
- [ ] `tickets/todo.md`: mark the pawchive item as tracked/shipped.

## Acceptance criteria

- [ ] `uv run pytest` is green offline.
- [ ] `MONOKE_LIVE=1 uv run pytest -m live` is green for cum.st and, when
      configured, pawchive.
- [ ] A reader can add a pawchive creator using only the README/usage docs.
- [ ] Every known pawchive limitation is documented in one place.
- [ ] No live URL or token is required for the default test run.

## Out of scope

- Product acceptance on a large archive (T12.11).

## Notes

- Keep the live test bounded. A 173-attachment post is not a smoke test.
- Prefer recording fixtures once and pinning them; do not re-probe the API in
  CI.
