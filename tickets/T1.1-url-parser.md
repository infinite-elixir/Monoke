# T1.1 — cum.st URL parser and service registry

## Goal
Turn anything the user pastes into a validated `(service, creator_id[, post_id])`.

## Scope

- [x] `KNOWN_SERVICES = {patreon, fansly, onlyfans, fanbox, fantia, afdian, boosty, gumroad,
      subscribestar, dlsite, discord}` used for hints only; the parser accepts any
      `^[a-z0-9_-]+$` slug and lets the API reject unknown ones.
- [x] Accept:
      - `https://cum.st/creators/patreon/274608`
      - `https://cum.st/creators/patreon/274608/`
      - `https://cum.st/creators/patreon/274608?page=2`
      - `https://cum.st/creators/patreon/274608/post/172189145`
      - bare `creators/patreon/274608`
      - `http://` and `www.` variants
- [x] Return `CumstRef(service, creator_id, post_id=None)`.
- [x] Build helpers:
      - `post_url(ref, post_id)` → `https://cum.st/creators/{service}/{id}/post/{pid}`
      - `api_path(ref)` → `/{service}/user/{id}`
- [x] Reject with a specific, user-facing error: unknown shape, missing id, non-numeric id,
      non-http scheme, `kemono.cr` / old-format URLs with a message saying the site moved.
- [x] Normalize: strip whitespace, trailing `/`, fragment; keep IDs as strings.

## Acceptance criteria

- [x] Table-driven tests over all accepted forms.
- [x] A pasted `https://kemono.cr/patreon/user/2793377` fails with
      "That link is from the old site; use a cum.st/creators/... URL."
- [x] `?page=2` and `#x` do not change the parsed result.
- [x] A post URL yields `post_id` and is marked "single post".
- [x] `creators/patreon/abc` fails with a message naming the bad segment.

## Notes
- The web path uses `creators/{service}/{id}`; the API path uses `{service}/user/{id}`.
  Keep both builders in this module so no route ever string-concatenates URLs.
