# T0.2 — SQLite schema and repositories

## Goal
The whole persistent model, created idempotently, with a thin repository layer shared by the
crawler and the UI.

## Scope

- [ ] Connection helper: `sqlite3`, `check_same_thread=False`, WAL, `foreign_keys=ON`,
      `row_factory=sqlite3.Row`.
- [ ] Migration runner keyed on `PRAGMA user_version`; ordered SQL string list in `db.py`.
- [ ] Schema:

```sql
CREATE TABLE creators (
  id INTEGER PRIMARY KEY,
  service TEXT NOT NULL,
  service_id TEXT NOT NULL,
  name TEXT,
  display_name TEXT,
  avatar_url TEXT,
  header_url TEXT,
  indexed_at INTEGER,          -- unix seconds from the API
  updated_at INTEGER,
  content_updated_at INTEGER,
  bookmarked INTEGER,
  post_count INTEGER,          -- from the list response `total`
  last_synced_at TEXT,
  UNIQUE(service, service_id)
);

CREATE TABLE posts (
  id INTEGER PRIMARY KEY,
  creator_id INTEGER NOT NULL REFERENCES creators(id) ON DELETE CASCADE,
  service_id TEXT NOT NULL,
  service TEXT NOT NULL,
  title TEXT,
  caption_html TEXT,           -- sanitized captionHtml from the API (re-sanitized by us)
  caption_text TEXT,           -- plain text, for search
  published INTEGER,           -- unix seconds
  added INTEGER,
  bookmarked INTEGER,
  prev_id TEXT,
  next_id TEXT,
  revisions_count INTEGER DEFAULT 0,
  linked_count INTEGER DEFAULT 0,
  raw_json TEXT,
  fetched_at TEXT,
  missing_upstream INTEGER NOT NULL DEFAULT 0,
  UNIQUE(creator_id, service_id)
);
CREATE INDEX posts_pub ON posts(creator_id, published DESC);

CREATE TABLE files (
  id INTEGER PRIMARY KEY,
  post_id INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  position INTEGER,
  sha256 TEXT NOT NULL,
  kind TEXT NOT NULL,          -- image | gif | video | audio | file
  mime_type TEXT,
  bytes INTEGER,
  width INTEGER,
  height INTEGER,
  duration_ms INTEGER,
  original_filename TEXT,
  storage_key TEXT,
  variants_json TEXT,          -- [{"name","bytes"}]
  url TEXT NOT NULL,           -- edge original URL
  thumb_url TEXT,              -- img.cum.st preview
  UNIQUE(post_id, sha256)
);
CREATE INDEX files_post ON files(post_id);

CREATE TABLE links (
  id INTEGER PRIMARY KEY,
  post_id INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  url TEXT NOT NULL,
  normalized_url TEXT NOT NULL,
  label TEXT,
  category TEXT NOT NULL,
  origin TEXT NOT NULL,        -- caption | api_links
  resolved_url TEXT,
  UNIQUE(post_id, normalized_url)
);
CREATE INDEX links_cat ON links(category);
CREATE INDEX links_post ON links(post_id);

CREATE TABLE tags (
  post_id INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  slug TEXT NOT NULL,
  label TEXT,
  PRIMARY KEY (post_id, slug)
);

CREATE TABLE runs (
  id INTEGER PRIMARY KEY,
  creator_id INTEGER NOT NULL REFERENCES creators(id) ON DELETE CASCADE,
  mode TEXT NOT NULL,          -- full | sync | deep
  status TEXT NOT NULL,        -- running | done | failed | cancelled
  started_at TEXT,
  finished_at TEXT,
  pages INTEGER NOT NULL DEFAULT 0,
  posts_seen INTEGER NOT NULL DEFAULT 0,
  posts_new INTEGER NOT NULL DEFAULT 0,
  posts_updated INTEGER NOT NULL DEFAULT 0,
  links_found INTEGER NOT NULL DEFAULT 0,
  files_count INTEGER NOT NULL DEFAULT 0,
  error TEXT
);

CREATE TABLE api_cache (
  url TEXT PRIMARY KEY,
  fetched_at TEXT NOT NULL,
  body TEXT NOT NULL
);

CREATE TABLE link_resolutions (
  url TEXT PRIMARY KEY,
  final_url TEXT,
  resolved_at TEXT
);
```

- [ ] Repositories (plain functions, no ORM):
      `upsert_creator`, `get_creator`, `list_creators`,
      `upsert_post`, `get_post`, `list_posts(creator_id, filters…)`,
      `replace_files(post_id, rows)`, `replace_links(post_id, rows)`, `replace_tags(post_id, rows)`,
      `create_run`, `finish_run`, `list_runs`,
      `cache_get(url)`, `cache_put(url, body)`.
- [ ] `replace_*` are transaction-scoped and idempotent (delete-then-insert per post).
- [ ] `upsert_post` keeps identity stable and updates `fetched_at`.
- [ ] Deduplicate attachments by `sha256` before insert (the API repeats the same file).

## Acceptance criteria

- [ ] Fresh DB creates all tables; re-running migrations is a no-op.
- [ ] Deleting a creator cascades to posts, links, files, tags, runs.
- [ ] `upsert_post` twice with the same `(creator_id, service_id)` yields one row.
- [ ] Inserting the same `sha256` twice for one post yields one file row.
- [ ] `list_posts` supports: category, tag, `has_links`, `has_attachments`, date range, text
      query, sort (`published desc|asc`, `title`), limit/offset — parameterized SQL only.
- [ ] Unit tests cover every repository function against a temp DB.

## Notes
- Timestamps are unix seconds as returned by the API; `fetched_at` is ISO-8601 UTC.
- `posts.raw_json` is the safety net: extraction can be re-run without refetching.
- Comment bodies and revision bodies are never stored; only `revisions_count` is kept.
  Comment counts are not stored either — comments are out of scope.
