# T8.3 — Invisible directional controls: images, posts and input methods

## Goal

Map the four screen directions to the viewer's media. The controls are invisible
buttons covering the media area, and the same actions are available by keyboard,
wheel and touch swipe. Right/left move within the current post; up/down jump to
the neighbouring post's first media.

## Direction contract

With the current item at index `i` in a post containing `n` items:

| Direction | Action | Boundary |
|---|---|---|
| Right | `i + 1` — next media in the same post | At `i = n - 1`: T8.6 opens the next post's item 0; no-op at the oldest |
| Left | `i - 1` — previous media in the same post | At `i = 0`: T8.6 opens the previous post's last item; no-op at the newest |
| Up | **next post** = older post; load its item `0` | At the oldest media post: no-op |
| Down | **previous post** = newer post; load its item `0` | At the newest media post: no-op |

- "First media" means the lowest `files.position` + `files.id` in the target
  post, regardless of whether it is an image of a video.
- No wrapping at the archive ends. Within the archive, right/left cross into the
  neighbouring post at the edges (T8.6); Up/Down remain the explicit post jumps.
- Text-only posts are skipped by T8.1's neighbour lookup.

## Scope

**Invisible buttons**

- [ ] Render four transparent `<button type="button" class="viewer-zone">`
      elements over the stage:
      - `data-viewer-action="prev-image"` — left 20% strip, full height
      - `data-viewer-action="next-image"` — right 20% strip, full height
      - `data-viewer-action="prev-post"` — top 20% band, centre 60% width
      - `data-viewer-action="next-post"` — bottom 20% band, centre 60% width
- [ ] No background, border, icon or persistent hover style. `cursor: default`.
      They are invisible but accessible: each has an `aria-label` and a
      `:focus-visible` outline for keyboard users.
- [ ] Clicking/tapping a zone performs its action and also dismisses the
      first-run hint (T8.4).
- [ ] Clicks on the close control, video native controls, links or other real UI
      must not trigger a direction. Stop propagation on those controls.
- [ ] For `<video>`, the bottom zone is lifted above the native control bar
      (at least 56–64 px) so play/seek/volume remain clickable. If the video is
      short and the zone has no room, omit the bottom zone and rely on
      keyboard/swipe for the post jump.
- [ ] The centre of the stage is not a navigation zone; a click there only
      dismisses the hint.

**Keyboard**

- [ ] `ArrowLeft` / `ArrowRight` / `ArrowUp` / `ArrowDown` perform the actions
      above.
- [ ] Ignore modified keys (`Ctrl`, `Alt`, `Meta`) and key events from inputs,
      buttons, links or a focused `<video>` control, except `Escape` (T8.4).
- [ ] `preventDefault()` only for handled arrows, so browser scrolling cannot
      fight the viewer.
- [ ] Throttle repeated navigation to one action per 150 ms; holding a key must
      not fire dozens of requests per second.

**Wheel / trackpad**

- [ ] Listen for `wheel` on the stage with `{passive: false}` and
      `preventDefault()`.
- [ ] Dominant delta axis decides direction: horizontal → image prev/next;
      vertical → post older/newer. Sign convention: wheel down / deltaY > 0
      follows the table's Down (newer post); wheel up = older.
- [ ] Threshold: ignore `abs(delta) < 24`; coalesce bursts for 250 ms. A single
      trackpad flick must produce at most one navigation.
- [ ] Do not hijack wheel events over the native video control bar.

**Touch**

- [ ] Swipe threshold: 40 px; horizontal vs vertical chosen by the larger
      absolute delta.
- [ ] Swipe left → next image; right → previous image; up → next (older)
      post; down → previous (newer) post.
- [ ] Suppress the synthetic click after a swipe so one gesture never navigates
      twice. No pinch/zoom handling in this ticket.
- [ ] Multi-touch gestures are ignored.

**State and requests**

- [ ] Within-post moves update the in-memory index instantly; no network call.
- [ ] Post jumps `fetch()` `/c/{id}/viewer/data?post=<id>`, show an
      `aria-busy` state, then render the target post's item 0.
- [ ] Use `AbortController`; a late response from an older jump must never
      overwrite a newer one.
- [ ] A failed jump shows a non-blocking error flash and keeps the current media
      and controls. It must not blank the viewer.
- [ ] After every move, update the URL with `history.replaceState` to
      `?post=<service_id>&i=<index>`. Do not push one history entry per image.
- [ ] Direct-loading a URL restores the exact post and index (T8.1).
- [ ] Do not preload the next/previous media in this ticket (implemented by
      [T8.7](T8.7-viewer-neighbour-image-preload.md)).

**Tests**

- [ ] Markup test: four zones exist with the four aria-labels.
- [ ] Markup test: zones have no visible text/icon and the viewer markup still
      has no persistent toolbar.
- [ ] Server test for the neighbour chain: newest → older → older, and
      older → newer, skipping text-only posts.
- [ ] `node --check src/monoke/web/static/viewer.js` passes.
- [ ] Browser acceptance on creator 2:
      - Right/left walk a 5-image post and stop at both ends.
      - Down lands on the first media of the next older media post.
      - Up returns to the first media of the newer post (not the previous image
        index of the old post).
      - Wheel, trackpad, swipe and all four arrow keys produce exactly one
        action per gesture.
      - Holding an arrow key does not flood the API.
      - A video's native play button still works.

## Acceptance criteria

- [ ] Four invisible zones cover the media edges; no directional button is
      visible at rest.
- [ ] Right/left navigate inside the current post and cross into the
      neighbouring post at the edges (T8.6); never wrap at the archive ends.
- [ ] Up/down always land on item 0 of the newer/older post.
- [ ] Starting at the newest media post, Up does nothing; starting at the
      oldest, Down does nothing.
- [ ] Keyboard, wheel, touch and click all use the same action functions; there
      are not four separate navigation implementations.
- [ ] One gesture = one move (no double-fire from click-after-touch).
- [ ] URL reflects post and index after every move; refresh restores it.
- [ ] Failed post fetches leave the current item intact.
- [ ] No request is made for in-post right/left moves.

## Out of scope

- The first-run hint and its dismissal animation (T8.4).
- Preloading (T8.7), slideshow/autoplay, looping at the ends.
- Zoom/pan, drag-to-navigate.
- Caption-image or cross-creator navigation.

## Notes

- The four edge buttons and the wheel/touch hit testing should call one
  `go(kind)` dispatcher, not duplicate boundary logic.
- Keep `viewer.js` dependency-free and ES5-ish to match `app.js` (no build
  step).
- The "previous = newer" choice is intentional: with the archive sorted newest
  first, Up moves toward the newest post and Down toward the oldest. Label the
  first-run hint accordingly (T8.4) so it is not mistaken for chronological
  previous/next.
- **Superseded at the horizontal edges by [T8.6](T8.6-viewer-horizontal-post-crossing.md):**
  right on a post's last media now opens the next post, and left on the first
  opens the previous post's last media. The no-wrap statement above still holds
  only at the archive ends.
- **Touch threshold superseded by [T8.10](T8.10-viewer-finger-following-swipe.md):**
  the direction mapping and one-gesture-one-move rule stay, but the
  `touchend`-only 40 px check becomes a continuous pointer drag with snap,
  velocity commit and rubber-band edges. The two-axis model remains horizontal
  = media, vertical = post.

## Resolution

All input methods call one `go(action)` dispatcher, so boundary logic exists
once. In-post moves only change the in-memory index; post jumps `fetch()` the
T8.1 data route with an `AbortController` and a token guard, then render item 0.

**Code**

| File | Change |
|---|---|
| `src/monoke/web/templates/viewer.html` | four invisible `viewer-zone` buttons with aria labels |
| `src/monoke/web/static/style.css` | 20% edge strips, 60% centre bands, focus outline, video bottom zone lifted 64 px |
| `src/monoke/web/static/viewer.js` | dispatcher, arrows, wheel, touch, `replaceState`, busy state, non-blocking error flash |
| `tests/test_viewer.py` | four zones/labels, neighbour chain in both directions, id tie-breaking |

Keyboard arrows ignore modifiers, form/button/link targets and a focused video;
handled arrows call `preventDefault()`. Navigation is throttled to 150 ms,
wheel bursts to 250 ms with a 24 px threshold, and swipes need 40 px on the
dominant axis. A synthetic click after a swipe is suppressed. `f` is reserved
for fullscreen. After every move the URL is
`?post=<service_id>&i=<index>` via `history.replaceState`; a failed post fetch
leaves the current media untouched and shows a flash.

Browser acceptance (creator 2's archive) was not run in this environment; the
markup/server contract is covered by tests and the script passes
`node --check`.

## Superseded in part by T8.11

T8.11 removes the four invisible `.viewer-zone` buttons: the markup, their
click handler, the `afterTouch()` click suppression, the `.viewer-zone` focus
special case and the zone CSS (including the video `next-post` bottom offset)
are all gone. Touching or clicking the stage now only dismisses the hint.

Everything else in this ticket stands: the direction contract
(right = next media, left = previous media, up = older post, down = newer
post), the keyboard, the wheel thresholds, the post-boundary behaviour and the
`go(action)` dispatcher are unchanged. The 40 px touch threshold mentioned
here was already replaced by the pointer-events gesture in T8.10 and refined
in T8.11.

### Vertical direction (implemented by T8.12)

T8.12 flips the vertical axis to the direct-manipulation model, because the
drag reveal and the keyboard must mean the same thing:

| Direction | Action |
|---|---|
| Up | **older post** (comes from below) |
| Down | **newer post** (comes from above) |

That applies to the swipe, `ArrowUp`/`ArrowDown`, the wheel and the first-run
hint. The horizontal contract (right = next media, left = previous media) and
the post-boundary behaviour are unchanged.
