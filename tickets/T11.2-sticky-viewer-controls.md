# T11.2 — Sticky viewer controls, visible post buttons and hide control

## Goal

Give the merged lightbox/viewer one **sticky bottom control bar**. The bar is
visible on open, auto-hides while the user is idle, and can be pinned hidden
with a dedicated hide button. A small handle at the bottom edge brings it back.

The invisible left/right click zones stay for media navigation. The invisible
top/bottom zones for changing posts are replaced by visible **Newer post** and
**Older post** buttons in the bar. A hide button lives in the same bar.

## Locked layout

```
┌──────────────────────────────────────────────────────────────┐
│                                                    [Close]   │
│                                                              │
│                  media / video stage                         │
│      [invisible left zone]        [invisible right zone]     │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  ↑ Newer post   ↓ Older post   3 / 12 · title          │  │
│  │                        [bookmark] [expand] [⛶] [hide]  │  │
│  └────────────────────────────────────────────────────────┘  │
│                    [Show controls ˄]  (only when hidden)     │
└──────────────────────────────────────────────────────────────┘
```

- The bar is one row on desktop; on narrow screens the post buttons and the
  title/counter wrap into two rows without horizontal page overflow.
- Post buttons always show their labels and disabled state; do not hide them
  behind hover or a menu.
- `expand` appears only when the overlay is compact/expanded on a wide screen;
  `⛶` is the browser-fullscreen toggle. On mobile the expand control is hidden.
- `hide` collapses the whole bar and exposes the **Show controls** handle.
- Close stays at the top-right so the bar can be entirely hidden.

## Current behaviour

- The old viewer reveals only the fullscreen button for 2500 ms after activity;
  `viewer-zone` buttons cover the left/right/top/bottom edges and are invisible.
- The gallery lightbox has a bottom caption bar with counter, post/original
  links and always-visible prev/next/close buttons.
- There is no shared control bar and no hide/show control.

## Scope

**Markup**

- [ ] Add `data-lightbox-controls` as the sticky bar inside the merged overlay.
      It contains, in order:
      - older/newer post buttons (labelled, with `aria-label` and `disabled`
        states);
      - a live status area with the media counter and current title, truncated
        to one line on desktop and two on mobile;
      - the icon-only bookmark toggle (T4.9 macro contract);
      - the expand control (wide screens only);
      - the browser-fullscreen control (existing fullscreen glyphs);
      - the **Hide controls** button.
- [ ] Add a separate `data-lightbox-controls-handle` button at the bottom edge,
      hidden while the bar is visible, labelled **Show controls**. Activating it
      restores the bar and moves focus to the first control.
- [ ] Keep the left/right invisible `data-viewer-action="prev-image"` /
      `"next-image"` zones. Remove the `prev-post` / `next-post` invisible zone
      buttons and their CSS.
- [ ] Keep the close button at the top-right.
- [ ] Keep the toast, announcer, hint and original/post links, but move the
      user-visible post/original links into the bar or the caption attached to
      it; do not duplicate the same controls in two bars.
- [ ] The bookmark control keeps `aria-pressed`, the target-specific
      accessible name and the form POST / `next` contract.

**Visibility state**

- [ ] The bar starts visible on open. After 2500 ms without pointer movement,
      keyboard input or focus inside the bar, it fades/slides out and the handle
      appears.
- [ ] Any pointer movement, key press, wheel, touch or focus inside the bar
      reveals it and restarts the timer.
- [ ] **Hide controls** hides the bar immediately and pins it hidden for the
      rest of the session/layer; movement does not reveal it. Only the handle
      (or `H`, if added) restores it.
- [ ] Restoring with the handle clears the pin and restarts the normal timer.
- [ ] The auto-hide timer must not fire while focus is inside the bar or while
      a video is using its native controls.
- [ ] `prefers-reduced-motion: reduce` makes hide/show instant, with no
      transition and no layout shift.
- [ ] Hiding the controls never disables keyboard shortcuts, edge zones or the
      close/fullscreen Escape behaviour.

**Styling**

- [ ] Bar: centred, width `min(100% - 2rem, 980px)`, solid theme background,
      border, shadow, rounded corners, `z-index` above the media and edge zones.
- [ ] `padding-bottom` includes `env(safe-area-inset-bottom)` on phones.
- [ ] Buttons keep a visible `:focus-visible` ring and at least 44 × 44 px touch
      targets on coarse pointers.
- [ ] At 390 px wide the bar and handle stay inside the viewport, never cover
      the fullscreen glyphs, and never cause horizontal scrolling.
- [ ] The expanded/fullscreen state reserves bottom space so the bar does not
      cover the bottom of the media.

**Behaviour**

- [ ] Post buttons call the same `prev-post` / `next-post` actions as the old
      keyboard path and disable at the first/last post.
- [ ] The fullscreen button reflects enter/exit state with the existing
      `aria-pressed`, label and icon swap.
- [ ] The expand button reflects compact/expanded state and is hidden on mobile.
- [ ] Mobile immediate fullscreen from T11.1 still works; the bar remains
      visible inside browser fullscreen.
- [ ] Focus order follows the visual order; after hiding, focus moves to the
      handle instead of being lost.
- [ ] No page-load timers or observers: the hide timer starts only when the
      overlay opens.

**Tests**

- [ ] Template: exactly one sticky bar, one hide button, one handle, two post
      buttons, one bookmark control, one fullscreen control and no
      `data-viewer-action="prev-post"` / `"next-post"` zone buttons.
- [ ] JS source/behaviour: hide pins the bar, movement does not reveal it, the
      handle restores it, and focus moves to the handle on hide.
- [ ] Keyboard: left/right zones and arrow keys still step media; up/down keys
      and the visible post buttons cross posts.
- [ ] Accessibility: post buttons and hide/show controls have accessible
      names, `aria-pressed`/`disabled` states and visible focus rings.
- [ ] CSS assertions: bottom bar positioning, safe-area padding, reduced-motion
      block, no top/bottom zone rules.
- [ ] `node --check src/monoke/web/static/lightbox.js` and `uv run pytest` pass.

## Acceptance criteria

- [ ] The merged viewer has one visible sticky bottom bar with labelled post
      buttons, status, bookmark, expand/fullscreen and hide.
- [ ] The bar auto-hides, the hide button pins it hidden, and the handle brings
      it back.
- [ ] Invisible left/right media zones remain; invisible up/down post zones are
      gone.
- [ ] The layout works at 390 px and on desktop without horizontal overflow or
      covered controls.
- [ ] Keyboard, touch and no-JS bookmark behaviour remain intact.

## Out of scope

- Changing the fullscreen state machine or entry points (T11.1).
- Bookmark-library entry points (T11.3).
- Black-flash image painting (T11.4).
- Configurable bar position or per-user preferences.

## Notes

- Reuse the existing 2500 ms chrome timer idea, but track a pinned-hidden flag
  separately from the timer.
- Keep the bar as normal buttons/links, not an ARIA menu. The hide control is a
  toggle, not a popover.
- The handle must be reachable by keyboard at the bottom edge and must not
  trigger the left/right zones.
