# T6.4 — Debug mode: verbose logging to file

## Goal
Add a `--debug` flag to `monoke serve` (and `MONOKE_DEBUG=1`) that enables verbose server-side logging and writes a debug log file, plus a small client-side debug overlay capturing console errors and failed requests.

## Scope
- [x] `serve --debug` enables DEBUG log level and writes to `data/monoke.debug.log`.
- [x] Log request method/path/status and timing.
- [x] Client: capture `console.error`, unhandledrejection, htmx:responseError and append to debug panel.
- [x] Document in README.

## Acceptance criteria
- [x] `uv run monoke serve --debug` creates and writes the log file.
- [x] Errors during browsing are recorded with enough context to diagnose T6.2/T6.3.

## Resolution

**Server.** `monoke serve --debug` (or `MONOKE_DEBUG=1`) sets the flag for the
process, configures one root logger for the console *and* a rotating
`data/monoke.debug.log`, and turns on a request middleware that records
method, path, status and duration:

```
2026-10-21 14:55:27,742 DEBUG    monoke.web.app: GET /c/1 -> 200 in 6.1 ms
```

Unhandled errors are logged with a traceback and the browser still gets the
500 page.

**Client.** The server marks the page with `data-debug="1"`, so the debug
panel opens automatically when the app runs in debug mode — no query string
needed. `?debug=1` and `#debug` still work on a normal server. The panel
records `console.error`, uncaught errors, unhandled promise rejections,
`htmx:responseError`, `htmx:sendError` and every htmx request with its
status and duration.

**Before this change the flag was mostly cosmetic:** `log_config=None` was
passed to uvicorn in *both* modes, so a normal server printed nothing at all
(no banner, no access log, no errors). That is fixed: normal mode logs to the
console, debug mode logs to the console and the file.
