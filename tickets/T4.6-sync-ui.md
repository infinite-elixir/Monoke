# T4.6 — Live sync progress

## Goal
No dead spinner. The user sees pages, posts, and links accumulate.

## Scope

- [x] `GET /events/{run_id}` — `text/event-stream` fed by the event bus (T2.3).
      Heartbeat every 15 s; closes on `done`/`error`.
- [x] Sync button: `POST /c/{creator_id}/sync` → `{run_id}` → the page opens an `EventSource`.
- [x] Progress component on the creator page: phase label ("Fetching page 3/16"),
      posts bar (`120 / 782`), links counter, elapsed time, cancel button.
- [x] On completion: swap in the run summary
      (`782 posts · 812 links · 912 files · 14.2 s`) and refresh the post list via htmx.
- [x] Cancel: `POST /runs/{run_id}/cancel` → cooperative cancellation, run recorded as
      `cancelled`, partial data kept.
- [x] If a run is already active for that creator, the button shows "Syncing…" and does not
      start a second run.
- [x] Fallback when SSE is unavailable: poll `/runs/{run_id}` every 2 s.

## Acceptance criteria

- [x] Starting a sync shows page and post progress within 1 s, updating at least every 2 s.
- [x] Closing the tab does not kill the crawl; reopening the creator page shows the active run.
- [x] Cancel stops within ~2 s and leaves consistent data (no half-written post).
- [x] Two rapid clicks on Sync create exactly one run.
- [x] Errors (403, network) surface as a red banner with the API's message, not a JSON dump.

## Notes
- SSE is one-way and sufficient; do not add websockets.
- The event bus is in-process, so `uvicorn --workers 1` is a hard requirement for now.
  Document it in the README.
