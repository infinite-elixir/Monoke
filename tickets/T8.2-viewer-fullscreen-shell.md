# T8.2 — Fullscreen shell and media rendering

## Goal

Render the viewer as an immediate full-viewport surface, show exactly one media
item at a time (image, real GIF or video), and attempt real browser fullscreen
with an in-page overlay fallback. No visible chrome except the first-run hint
from T8.4.

## Scope

**Template (`viewer.html`)**

- [ ] New `viewer.html` extending the shared base for theme/NSFW/static assets,
      with a body class that hides the normal site header, footer, flash region
      and page padding while the viewer is active.
- [ ] Root markup:
      `<main id="viewer" class="viewer" data-viewer-root aria-label="Media viewer">`
      with a stage, one media element, a live counter and the hidden close
      control.
- [ ] No page scrolling: `html, body { overflow: hidden; height: 100%; }` while
      active; restore the previous scroll position on close.
- [ ] Stage background is near-black in both themes; media is centred with
      `object-fit: contain`, never cropped, respecting `100dvh` and safe-area
      insets on phones.
- [ ] The initial state from T8.1 is embedded as
      `<script type="application/json" id="viewer-initial">` (or equivalent),
      not fetched again on first paint.
- [ ] Page-specific script: add a `{% block scripts %}` hook to `base.html` and
      load `static/viewer.js` only on this page. `app.js` must not grow another
      thousand lines of gallery code.

**Media rendering (`viewer.js`)**

- [ ] Render one item at a time from the `media[index]` payload.
- [ ] `kind='image'` or `kind='gif'` → `<img>` with the full `url`, `alt` built
      from the post title/filename, `decoding="async"`. Real GIFs animate.
- [ ] `kind='video'` → `<video controls playsinline preload="metadata"
      poster="<thumb_url>">` with `src=url`. **No autoplay and no autoplay with
      sound.** The user presses play.
- [ ] `kind='audio'` is not part of the viewer (`VIEWER_KINDS` excludes it).
- [ ] Switching items removes the previous element's `src`/`srcset`, pauses and
      unloads video, then creates the new element. No hidden video keeps
      downloading or playing.
- [ ] Use the `original.*` variant by default. Do not add a variant selector in
      this ticket.
- [ ] Show the native video controls only; do not draw custom play/pause chrome.
- [ ] Missing media URL or failed load: show a neutral “Media unavailable”
      state with a link to the post, never a broken image icon.

**Fullscreen lifecycle**

- [ ] The in-page overlay is the default. It fills the viewport immediately, so
      no layout jump occurs if real fullscreen is granted later.
- [ ] On the **first user gesture after load** (pointerdown, touchstart or
      keydown), call `root.requestFullscreen({navigationUI: "hide"})` once if
      supported and not already fullscreen. Swallow permission errors.
- [ ] Browsers require a gesture for fullscreen, so do not pretend the page can
      force it on navigation. Record this limitation in the ticket resolution.
- [ ] Listen to `fullscreenchange`: update a class/`aria` state and keep the
      viewer usable if the user exits fullscreen with the browser's own Esc.
- [ ] Add `f` as an optional toggle between fullscreen and overlay, announced in
      the hint (T8.4). It must not fire while an input or video control has focus.
- [ ] If the Fullscreen API is unavailable, the overlay still fills the
      viewport; no error UI.

**Close / return**

- [ ] A visually hidden but focusable `Close viewer` button is the first
      focusable element. It is not persistently visible.
- [ ] Closing exits fullscreen when active, releases media `src`, restores
      `body` scroll and returns to the URL supplied by T8.1
      (`/c/{id}` or `/c/{id}/gallery`).
- [ ] Browser Back does not leave a trail of image states; T8.3 uses
      `replaceState`.

**Blur / theme**

- [ ] The full-size media is shown **unblurred**: opening the viewer is the
      explicit reveal, same rule as the existing gallery lightbox. The global
      NSFW toggle continues to blur thumbnails elsewhere; do not add a second
      blur mechanism.
- [ ] Both themes are supported; the stage remains dark for correct contrast.
- [ ] `prefers-reduced-motion: reduce` disables transitions.

**Tests**

- [ ] Route test: viewer HTML contains one stage, one initial-state JSON block
      and a page-specific script tag.
- [ ] Route test: newest item is rendered as `<img>` when its kind is `image`.
- [ ] Route test: a video item produces a `<video>` with `poster`, `controls`,
      `playsinline` and no `autoplay` attribute.
- [ ] Route test: a real gif produces an `<img>`.
- [ ] Route test: no shell header/footer is visible in the viewer page markup
      (or is marked `hidden`/excluded).
- [ ] `node --check src/monoke/web/static/viewer.js` passes.
- [ ] Existing pages still load only `app.js`; `viewer.js` is not global.

## Acceptance criteria

- [ ] `/c/2/viewer` fills the viewport with the newest media, no site header or
      footer visible, no page scrollbar.
- [ ] A portrait image and a landscape image both fit without cropping or
      horizontal scroll; phone viewport (390×844) is usable.
- [ ] A video shows its thumbnail poster, does not autoplay, and plays when the
      user presses the native play button.
- [ ] Navigating to another item unloads the previous video (no audio keeps
      playing in the background).
- [ ] The first gesture attempts true fullscreen; if denied, the overlay still
      fills the screen.
- [ ] Esc/close returns to the creator page (or gallery when entered there) and
      restores scroll.
- [ ] No full-size media is fetched for any item other than the current one.
- [ ] `?quiet=1` does not break the viewer (it may disable transitions/hint; it
      must not add timers or observers).

## Out of scope

- Directional input and post jumps (T8.3).
- The hint overlay, focus trap and dismissal rules (T8.4).
- Preloading neighbouring images/videos.
- Caption/metadata chrome, slideshows, zoom/pan and download buttons.

## Notes

- The current gallery lightbox already proves the "no bytes until opened"
  pattern. This viewer is a route, so the current item is expected to load on
  arrival; everything else must stay lazy.
- Do not reuse the existing `#gallery-lightbox` markup; it is image-only and
  coupled to the gallery grid. A separate viewer keeps both behaviours simple.

## Resolution

`viewer.html` extends the shared base and marks the body `viewer-page`; the
header, footer, flash region, skip link and page padding are hidden and
`html`/`body` overflow is locked. The stage is a fixed `100dvh` near-black
surface with safe-area padding and `object-fit: contain` media.

**Code**

| File | Change |
|---|---|
| `src/monoke/web/templates/base.html` | `body_attrs` and page-specific `scripts` blocks |
| `src/monoke/web/templates/viewer.html` | stage, counter, hidden close button, one server-rendered media element, `viewer-initial` JSON |
| `src/monoke/web/static/viewer.js` | item rendering, media unload on switch, fullscreen lifecycle, close/return, unavailable state |
| `src/monoke/web/static/style.css` | full-viewport shell, dark stage, zones, focus styles, reduced-motion inherited from the global rule |
| `tests/test_viewer.py` | one stage + one JSON block + page script, image/gif/video markup, no autoplay, unavailable state, `viewer.js` not global |

Videos use native controls, `preload="metadata"` and the thumbnail poster; the
element never has `autoplay`. Switching items pauses, removes `src` and calls
`load()` on the previous video before the node is replaced. Fullscreen is
requested on the first pointerdown/touchstart/keydown gesture only, because
browsers require a trusted gesture; denial leaves the overlay filling the
viewport. `f` toggles fullscreen after that first gesture, and Esc/close unloads
media and returns to the creator or gallery URL.
