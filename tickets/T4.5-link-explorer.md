# T4.5 — Link explorer

## Goal
The "just list the links out cleanly" view: every link, one table, filterable, exportable.

## Scope

- [x] `GET /links` (all creators) and `GET /c/{creator_id}/links` (scoped).
- [x] Table columns: category badge · label · URL (monospace, copy button) · post title ·
      date. Row click → post page.
- [x] Controls: category checkboxes (all on by default), creator filter (global view),
      text search (label + URL), `has_resolved` filter for shorteners, sort
      (`date_desc`, `category`, `host`), page size 100.
- [x] Group-by-category toggle (default: grouped, with sticky group headers and counts).
- [x] Export buttons: `CSV`, `JSON` → `GET /c/{id}/links.csv`, `GET /c/{id}/links.json`
      (same filters applied), plus archive-wide variants.
- [x] Header stats: total links, per-category counts, unresolved shorteners.
- [x] Empty state with a link to sync.

## Acceptance criteria

- [x] The link explorer shows every link (no default category filter hides rows).
- [x] `?category=mega,direct_media&q=mp4` returns only those rows, and the CSV export of the
      same URL contains exactly those rows.
- [x] 10 000 rows paginate in < 300 ms (indices on `category`, `post_id`).
- [x] Copy button copies the **resolved** URL when available, otherwise the original;
      the tooltip says which.
- [x] Export filenames follow T3.5's convention and set `Content-Disposition: attachment`.
- [x] No link is dropped for having an unknown category — `other` is a real row.

## Notes
- This page is the answer to "I just need them listed out more cleanly". Optimise for
  scanning speed, not decoration.
