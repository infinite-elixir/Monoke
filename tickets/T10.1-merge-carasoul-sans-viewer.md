# T10.1 — Merge `carasoul-swiping-viewer` without the viewer rewrite

## Goal

Port the non-viewer work from `carasoul-swiping-viewer` into
`better-viewer-and-lightbox-fullscreen`, while keeping the target branch's
fullscreen viewer and gallery lightbox as they are.

The only viewer changes allowed are the T4.9 fullscreen **icon** (plus keeping
the bookmark shortcut/toast the target already has). Everything else in the
Viewer epic stays out.

## Baseline

| Ref | Commit | Notes |
|---|---|---|
| `better-viewer-and-lightbox-fullscreen` (target) | `75241b0` | same tree as `main` |
| `carasoul-swiping-viewer` (source) | `0dfa333` | one commit on top of `75241b0` |

The merge base is `75241b0`, so this is a content port, not a three-way merge.
The source commit is a single squashed commit of ~11k insertions across 40
files; splitting happens at file/hunk level.

## The one allowed viewer change

Target state today:

```html
<button type="button" class="viewer-fullscreen" data-viewer-fullscreen
        aria-pressed="false" aria-label="Enter fullscreen">Fullscreen</button>
```

Required:

- [ ] Replace the `Fullscreen` text node with an inline `<svg>` glyph
      (`aria-hidden="true" focusable="false"`). Keep the class,
      `data-viewer-fullscreen`, `type="button"`, `aria-pressed="false"` and
      `aria-label="Enter fullscreen"`.
- [ ] `viewer.js` `updateFullscreenControl()` stops writing `textContent`.
      It keeps `aria-pressed`, sets `aria-label`/`title` to
      `Enter fullscreen` / `Exit fullscreen`, and toggles a class (for example
      `is-fullscreen`) so the icon can switch between enter and exit.
- [ ] Change nothing else in `viewer.js`. In particular keep
      `updateCachedBookmarks`, the `b` / `Shift+B` keys, the toast, the `F`
      key, the reveal-on-activity behaviour and the 2500 ms timer.
- [ ] `style.css`: keep the existing `.viewer-fullscreen` positioning,
      reveal and reduced-motion rules; add only icon sizing/fill rules.
- [ ] `tests/test_viewer.py`: replace the single
      `assert ">Fullscreen</button>" in body` with an assertion that the button
      contains an `<svg>` and no visible `Fullscreen` text. Leave every other
      viewer test untouched.

Expected diff against `75241b0` after the port:

```
src/monoke/web/templates/viewer.html   ~1 button
src/monoke/web/static/viewer.js        updateFullscreenControl only
src/monoke/web/static/style.css        icon rules only
tests/test_viewer.py                   icon assertion only
```

If the diff is larger, the port went too far.

## Keep the lightbox (the tricky part)

The source branch deleted the gallery lightbox and replaced tile links with
viewer links. That is **not** wanted. Rebuild the gallery by starting from the
target template and re-applying the grouped layout:

- [ ] Keep `#gallery-lightbox` and all `data-lightbox-*` markup from the
      target `gallery.html`.
- [ ] Keep the single `[data-gallery]` container. `app.js` collects
      `[data-gallery-item]` from it; grouped `<section>` wrappers are fine, but
      every tile must remain inside that container.
- [ ] Every tile keeps the target hooks:
      `data-gallery-item`, `data-kind`, `data-full`, `data-title`,
      `data-post-url`, plus the `href` fallback. Without these the lightbox
      breaks.
- [ ] Add the source's post-group sections, post headers, kind tabs, duration
      sort and pagination around those tiles.
- [ ] The tile action menu keeps **bookmark** only. Drop "start viewer here" /
      "open in viewer" items and their URLs.
- [ ] Keep the target's page-level "Open viewer" button
      (`/c/{id}/viewer?from=gallery`); it is target behaviour, not part of the
      excluded work.
- [ ] Do not add `data-viewer-open` or `data-viewer-focus` to tiles.
