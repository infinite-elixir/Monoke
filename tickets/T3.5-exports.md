# T3.5 — CSV and JSON exporters

## Goal
Get the data out for later classification, exactly as stored.

## Scope

- [ ] `extract/export.py`: pure functions returning `str`/`bytes` from a query result.
- [ ] Links export columns (fixed order):
      `creator,service,post_id,post_title,published,category,label,url,resolved_url,origin`
- [ ] Formats: `csv` (UTF-8, `\n`, RFC 4180 quoting) and `json`
      (`[{...}]`, stable key order, ISO dates).
- [ ] Whole-archive JSON export: `{creator, exported_at, posts: [...], links: [...]}`.
- [ ] Streaming for large sets (use `csv.writer` on an `io.StringIO` per row batch, yield bytes).
- [ ] Filename convention: `monoke-{service}-{creator_id}-links-{YYYYMMDD}.csv`.

## Acceptance criteria

- [ ] CSV parses with `python -c "import csv;list(csv.DictReader(...))"` and has the exact headers.
- [ ] Round-trip: export → JSON parse → same row count as the DB query.
- [ ] 5 000 synthetic rows export in < 1 s and do not blow memory (streamed).
- [ ] Unicode titles (`日本語`, emoji) survive both formats.
- [ ] No HTML in exported fields.

## Notes
- Exporters take a list of rows/dicts, not a DB connection, so they can be reused by the UI
  endpoints and the CLI.
