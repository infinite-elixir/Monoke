# T12.9 — Web UI and media presentation for multiple sources

## Goal

Make pawchive archives feel native without pretending they have cum.st's
metadata, and stop the UI from saying "cum.st" everywhere.

## Scope

**Adding and identifying creators**

- [ ] Index form accepts both URL shapes and shows one example per source, e.g.
      `cum.st/creators/patreon/274608` or `pawchive.pw/patreon/user/30500811`.
- [ ] `POST /creators` stores `source` and redirects to the existing creator.
- [ ] `POST /c/{id}/sync` rebuilds a `SourceRef` with the creator's `source`.
- [ ] Creator cards and creator pages show a small source badge
      (`cum.st` / `pawchive`).
- [ ] Dashboard/creator lists group or label by source; no mixed-source
      ambiguity when the same service/id exists twice.
- [ ] Replace global copy such as "Local cum.st archive" with "Local creator
      archive" or list the supported sources.

**Links out**

- [ ] Original creator/post URLs are built by the adapter, not
      `settings.site_base`.
- [ ] The post page "Original" link works for both sources.
- [ ] Caption images are allowlisted per source:
      `img.cum.st` for cum.st, `img.pawchive.pw`/`pawchive.pw` for pawchive.
      Do not leave pawchive captions stripped empty.

**Preview-only media**

- [ ] Gallery tiles, post attachment rows and the viewer use `thumb_url` for
      preview-only files.
- [ ] Show a "Preview only" badge/label; do not offer a "Load original" action
      that is guaranteed to 404.
- [ ] The "Open" action goes to the pawchive post or the thumbnail, whichever
      is honest for that file.
- [ ] Bookmarks still work for preview-only media; the bookmark stores sha256
      as today and surfaces "missing" only if the file row disappears.

**Missing metadata**

- [ ] Orientation/size filters handle `NULL` width/height (pawchive) without
      crashing; unknown media is excluded from orientation filters rather than
      silently bucketed.
- [ ] Duration sorting treats `NULL` duration as unknown, not zero.
- [ ] The gallery still renders image/video/gif tabs; classification comes from
      filenames because pawchive supplies no mime type.
- [ ] Empty-state copy names the source:
      "No tags provided by pawchive for this creator." (and cum.st likewise).

**Tests**

- [ ] Web test: paste a pawchive URL, creator is created with
      `source='pawchive'`, redirect works.
- [ ] Post page renders pawchive caption links and the correct original URL.
- [ ] Gallery/creator/bookmarks pages render a pawchive archive without
      template errors when dimensions/duration are `NULL`.
- [ ] Preview-only tile shows the badge and does not expose a broken original
      link.
- [ ] Existing cum.st UI tests pass.

## Acceptance criteria

- [ ] A pawchive creator can be added, synced, browsed, filtered, bookmarked and
      viewed entirely from the web app.
- [ ] No page claims a pawchive archive is hosted on cum.st.
- [ ] The app still binds `127.0.0.1` and adds no external frontend assets.
- [ ] `uv run pytest` is green offline.

## Out of scope

- New design work; reuse the existing Tokyo Night components and STYLE.md.
- Downloading preview-only originals or ZIP archives.

## Notes

- Keep the UI quiet: one badge, one honest "Preview only" label. Do not add a
  source filter bar until there is a demonstrated need.
