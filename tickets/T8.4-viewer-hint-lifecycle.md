# T8.4 — First-run control hint, dismissal and viewer lifecycle

## Goal

On first paint the viewer shows the four directional controls as a one-off hint;
the first interaction anywhere dismisses it and the viewer becomes completely
chrome-free. Also finish the close/focus/accessibility lifecycle so the viewer
is usable with a keyboard and a screen reader.

## Hint behaviour

- [ ] On every fresh viewer page load, show a centred hint overlay:
      - `↑` — newer post (first media)
      - `↓` — older post (first media)
      - `←` — previous image
      - `→` — next image
      - a smaller line: `Esc to close · F for fullscreen · first move hides this`
- [ ] The hint must be readable against both bright and dark media; use a
      translucent scrim and strong text, not an image-dependent colour.
- [ ] The hint is shown **once per viewer load**, not on every image move. It
      must not reappear after dismissal until the page is reloaded.
- [ ] Dismissal: the first `pointerdown`, `touchstart`, `keydown`, `wheel` or
      button activation removes the hint immediately. If that event maps to a
      direction, the direction still runs; dismissal must not swallow the
      action.
- [ ] No auto-hide timer. No `setInterval`. The hint stays until the user acts.
- [ ] `?quiet=1` and `prefers-reduced-motion: reduce` skip the fade transition;
      `?hint=0` suppresses the hint (useful for tests/screenshots).
- [ ] Do not persist "seen" in `localStorage`; every new page load starts with
      the hint. If this proves noisy in daily use, a `sessionStorage` flag can
      be a follow-up, not part of this ticket.

## Scope

**Hint markup (`viewer.html`)**

- [ ] `<div class="viewer-hint" data-viewer-hint role="status">` with four
      labelled arrow groups and the close/fullscreen line.
- [ ] The hint has `pointer-events: none` so it can never block a click; the
      first real input on the stage dismisses it.
- [ ] Add `aria-hidden="true"` after dismissal or remove it from the DOM; do not
      leave stale overlaid text for screen readers.

**Focus and keyboard lifecycle**

- [ ] Mark the viewer root as a labelled region/dialog that receives focus on
      load, so arrow keys work immediately without clicking.
- [ ] Make the four T8.3 zones reachable by Tab with clear `:focus-visible`
      outlines and `aria-label`s. The hint explains that arrows work globally.
- [ ] Trap focus inside the viewer while it is open; Tab from the last control
      returns to the first. Do not let focus escape to the hidden site header.
- [ ] Provide a visually hidden `Close viewer` button as the first focusable
      element. It is not persistently visible.
- [ ] `Escape`:
      - if browser fullscreen is active, let the browser exit fullscreen and
        keep the viewer open;
      - if not in fullscreen, close the viewer and return to the entry URL.
      Handle the `fullscreenchange` event so this behaves predictably.
- [ ] `F` toggles fullscreen when focus is not inside a video control or text
      input; the hint documents it.
- [ ] On close, pause/unload media, exit fullscreen, restore body scroll, and
      return focus to the element that opened the viewer (or the creator page
      heading after a direct load).
- [ ] If the user arrived by direct URL, close returns to `/c/{id}`; if opened
      from the gallery, the `from=gallery` return URL from T8.1 is used.

**Announcements**

- [ ] `aria-live="polite"` counter updated on each move:
      `Image 2 of 5 in this post · 14 of 264 media posts` (wording may be
      shortened, but it must announce both within-post position and item kind).
- [ ] Announced kind is truthful from T7.1: `video` for MP4-backed gifs, `gif`
      only for real GIFs.
- [ ] Do not announce every wheel tick if the gesture is throttled; announce
      only the resulting item.

**Reduced motion / performance**

- [ ] Transitions are CSS-only, ≤ 160 ms, disabled under
      `prefers-reduced-motion: reduce`.
- [ ] No `MutationObserver`, no polling, no timers after the hint is dismissed.
- [ ] Event listeners are removed on close/unload; repeated open/close must not
      accumulate listeners (T6.5 regression check).

**Tests**

- [ ] Route test: hint markup and all four labels are present by default.
- [ ] Route test: `?hint=0` omits the hint.
- [ ] Markup test: close button exists with an accessible name and is not
      visually persistent.
- [ ] Markup test: zones have `aria-label`s and no visible text.
- [ ] `node --check src/monoke/web/static/viewer.js` passes.
- [ ] Browser acceptance:
      - Hint appears on load; the first arrow/click/swipe hides it and performs
        the action.
      - Hint does not return after image/post moves; reload shows it again.
      - Tab cycles only through viewer controls; focus is visible.
      - Esc exits fullscreen first, then closes the viewer.
      - Closing restores scroll and return focus.
      - No timers/observers are added after dismissal (check the performance
        panel or a debug counter).

## Acceptance criteria

- [ ] First open shows the four controls; a single interaction hides them and
      still navigates once.
- [ ] After dismissal the viewer is fully chrome-free: no buttons, arrows,
      progress bars or persistent overlays.
- [ ] Reloading the page shows the hint again.
- [ ] The hint never blocks input.
- [ ] Keyboard-only operation is possible: Tab to controls, arrows navigate,
      Esc closes.
- [ ] A screen reader announces the current item and post position on every
      move.
- [ ] Opening and closing the viewer 20 times adds no listeners, timers or DOM
      nodes (same guardrail as T6.5).
- [ ] No JavaScript errors in the console during normal navigation.

## Out of scope

- Persisting "hint seen" across sessions.
- Custom video controls, captions, zoom/pan.
- On-screen persistent navigation buttons.
- Changing the existing gallery lightbox.

## Notes

- The hint is onboarding, not a toolbar. Once dismissed, nothing visible should
  remain except the media itself.
- Keep the hint text short on phones; use a stacked layout at narrow widths.
- If the browser blocks fullscreen, the hint's "F for fullscreen" line should
  still be accurate: pressing F retries and otherwise the overlay remains.

## Resolution

The hint is server-rendered only when `?hint=0` is absent, so a test or
screenshot can turn it off with no JavaScript. It is a `pointer-events: none`
overlay that the first `pointerdown`, `touchstart`, `wheel`, `keydown` or
control activation dismisses: the same event still runs its navigation because
dismissal only sets `aria-hidden` and fades the overlay out through a CSS
opacity transition (no timers). `?quiet=1` and `prefers-reduced-motion: reduce`
hide it instantly.

The viewer root is a focusable `role="dialog"` and receives focus on load, so
arrows work without a click. Tab is trapped across the visually hidden close
button, the video element and the four zones, with `:focus-visible` outlines on
the zones. Escape exits browser fullscreen first and closes on the next press;
close unloads media, exits fullscreen, removes every listener and hands focus
back through `sessionStorage` to the entry link (or the creator heading after a
direct load). A screen-reader `role="status"` region announces
`Image 2 of 5 in this post · 14 of 264 media posts`; the visible counter is
`aria-hidden`. The post rank/total come from `db.viewer_post_rank`, which uses
the same ordering as Up/Down navigation.
