# T8.10 — Finger-following swipe with rubber-band edges

## Goal

Make touch navigation in the fullscreen viewer feel direct: the current media
follows the finger, reveals the next/previous item as it moves, and either
settles into place or completes the move based on distance and velocity.

Today a swipe is a blind 40 px threshold checked only on `touchend`. Nothing
moves until the finger lifts, so the gesture feels like a button press rather
than a fluid swipe. This ticket keeps the existing one-gesture-one-move rule
but makes the gesture continuous.

## Gesture model (decision)

The viewer keeps a **two-axis Instagram/X hybrid**, because the archive has two
real levels: media inside a post, and posts:

- **Horizontal left/right = previous/next media**, exactly like an Instagram
  carousel or the X media viewer. At a post edge it continues into the
  neighbouring post (T8.6), so the gesture never dead-ends.
- **Vertical up/down = newer/older post**, like a feed pager. It does not step
  one image at a time.
- **Tap zones and tap-left/right remain** for users who do not discover swipe.
- **No swipe-down-to-dismiss.** X uses a downward drag to close its media
  viewer, but here down already means "older post". Closing stays on the close
  button and `Esc`; replacing a navigation axis with dismiss would be a
  regression. This can be revisited only with a different dismiss affordance.

A vertical-only next/previous feed was considered and rejected: it would either
collapse the post/media distinction or fight the existing Up/Down post
semantics. The fluid part users associate with Instagram/X is direct
manipulation, snap and momentum, not a single axis.

## Current behaviour

- `viewer.js` records `touchstart` coordinates and decides on `touchend`:
  dominant axis, 40 px minimum, then calls `go()`.
- There is no `touchmove` handler, no live translation, no velocity estimate
  and no preview of the destination.
- The four invisible zones cover 20% strips and 20% bands; the stage also
  receives wheel, touch and click events.
- T8.9 introduces two-layer directional transitions and a `go()` intent.
  T8.8 provides cached neighbouring payloads and preloaded edge images.
- `afterTouch()` suppresses the synthetic click for 600 ms after a swipe.
- Arrow keys, mouse wheel and zone clicks all funnel through `go(action)`.

## Scope

**Pointer gesture lifecycle**

- [ ] Replace the `touchstart`/`touchend` threshold pair with Pointer Events
      (`pointerdown`, `pointermove`, `pointerup`, `pointercancel`) on the stage,
      supporting touch and pen. Mouse drag may share the code but desktop
      navigation stays wheel/keyboard-first.
- [ ] Set pointer capture on the stage for the duration of the gesture and
      release it on commit, revert, cancel or window blur.
- [ ] Ignore gestures that start on real UI: close, fullscreen, video native
      controls, links, toast/flash, or any `[data-viewer-no-swipe]` element.
      Invisible direction zones may start a swipe.
- [ ] Ignore secondary pointers. A second `pointerdown` cancels the current
      drag and resets it without navigating.
- [ ] Suppress the viewer's own click/zone action after a drag, and update the
      `afterTouch()` suppression window so one swipe never navigates twice.
- [ ] The viewer must not scroll, zoom or bounce the page. Apply
      `touch-action: none` to the stage/media gesture surface, but do not break
      taps or drags on native `<video controls>`; those elements are excluded
      before the gesture starts.

**Direct manipulation**

- [ ] On `pointermove`, coalesce updates through `requestAnimationFrame` and
      translate the current incoming/outgoing layers with
      `translate3d()` only. No layout reads or writes per raw pointer event.
- [ ] Axis lock after an 8–10 px slop: choose the larger absolute delta for the
      whole gesture; do not switch axes mid-drag.
- [ ] Horizontal drag maps to image prev/next; vertical drag maps to
      newer/older post. Signs follow T8.3/T8.6 exactly. This is the decided
      Instagram/X hybrid above, not a vertical-only feed.
- [ ] If the destination is already known (inside the post, or a cached
      neighbouring payload from T8.8), prepare its media layer during the drag
      and reveal it at the correct edge. Do not start a network request merely
      to preview: if the neighbour payload is not cached, show no second image
      and still allow the release to trigger the existing fetch/jump.
- [ ] Do not update the counter, URL or announcer until the move commits.
- [ ] Do not unload or pause the current video until the gesture commits.
- [ ] The drag distance tracks the finger with 1:1 movement inside the archive
      and applies rubber-band resistance (suggest 0.25×) when there is no
      destination in that direction.
- [ ] The preview layer is temporary: at most two media elements exist during
      the gesture.

**Commit / cancel**

- [ ] Commit when the drag exceeds `min(96px, 18% of the stage's relevant
      dimension)` **or** the release velocity exceeds ~0.45 px/ms in the
      gesture direction. A fast short flick counts; a slow long drag counts.
- [ ] Below threshold, or at a rubber-banded archive edge, animate the layer
      back to rest in 160–220 ms and do not navigate.
- [ ] On commit, hand off to the same `go(action)` dispatcher and T8.9
      directional transition. The incoming layer starts from its current drag
      offset; do not snap to centre and restart the animation.
- [ ] If the commit requires a post fetch, keep the dragged layer in place
      while the payload resolves, then complete the T8.9 transition. A failed
      fetch springs back to the current item and shows the existing flash.
- [ ] Throttle commits to one move per gesture. No inertial continuation into
      a second or third item in this ticket.
- [ ] Ignore repeated pointer moves after commit/cancel until the next
      `pointerdown`.

**Reduced motion / performance**

- [ ] `prefers-reduced-motion: reduce` still allows direct finger tracking
      (it is user-controlled), but commit/revert snaps instantly with no
      spring, easing or crossfade. If even direct tracking is undesirable in
      future, the gesture must still navigate with the T8.3 behaviour.
- [ ] Add no idle timers, observers, loops or animation libraries. All
      transform work happens between `pointerdown` and `pointerup`.
- [ ] Clear inline transforms, `will-change` and preview layers after every
      gesture. At most two layers; no leak across repeated swipes.
- [ ] Do not change arrow keys, wheel thresholds, zone clicks, post-boundary
      logic or the T8.8 payload/preload caches.
- [ ] A click in the stage centre after a non-swipe still only dismisses the
      hint; a tap on a zone still performs exactly one action.

**Tests**

- [ ] Extract a pure `resolveSwipe()` helper under `BEGIN/END swipe-plan`
      markers. Node tests cover:
      - axis lock below/above slop,
      - horizontal/vertical direction mapping,
      - distance threshold,
      - high-velocity short flick,
      - rubber-banded edge/no-destination,
      - below-threshold cancel.
- [ ] Static tests that the old `touchend`-only threshold is gone, pointer
      capture and `pointercancel` are handled, and reduced motion bypasses the
      spring.
- [ ] Existing T8.3/T8.6 viewer tests remain green; one gesture still equals one
      `go()` call and no duplicate fetch.
- [ ] Browser acceptance in Chromium and Firefox with touch emulation, plus a
      real phone if available:
      - drag slowly 30% of the width and watch the image follow the finger,
        then release to complete the move;
      - drag below threshold and see it spring back with no navigation;
      - flick quickly with a short distance and complete the move;
      - drag at the newest/oldest archive edge and see rubber-band resistance
        followed by a spring back;
      - drag vertically between posts and horizontally between images; a
        diagonal gesture picks one axis and does not switch;
      - perform a post-edge swipe with a cold/unavailable neighbour payload:
        the current layer stays put during the fetch, then completes or springs
        back on failure;
      - native video play/seek/volume controls still work and do not start a
        drag;
      - repeated swipes never leave more than two media elements or stale
        transforms;
      - emulated reduced motion commits/reverts instantly;
      - a swipe does not also trigger a click/zone navigation;
      - arrow keys, wheel, fullscreen, bookmarks and the hint still work.

## Acceptance criteria

- [ ] A touch swipe visibly tracks the finger and reveals the adjacent item
      when it is already available.
- [ ] Release commits only on sufficient distance/velocity; otherwise the
      media settles back.
- [ ] Archive edges rubber-band and never wrap.
- [ ] Horizontal/vertical mapping and post crossing match T8.3/T8.6.
- [ ] One gesture produces at most one move and one request.
- [ ] The two-axis model feels deliberately Instagram/X-like: horizontal
      carousel within/through media, vertical feed between posts, with a
      continuous finger-following layer and a snap/settle.
- [ ] Swiping down never closes the viewer; close/`Esc` remain the dismiss
      controls, so "older post" is not ambiguous.
- [ ] Slow neighbour fetches keep the current media visible and failure returns
      safely to it.
- [ ] Video controls remain usable; no page scroll/zoom; no DOM or memory
      growth; reduced-motion users get an instant, working gesture.
- [ ] No dependency, no idle work, existing viewer/bookmark tests green.

## Out of scope

- Pinch-to-zoom, pan, rotate, double-tap zoom.
- Inertial flings that continue through several images or posts.
- Swipe-down-to-dismiss (conflicts with vertical "older post"; see the model
  decision above).
- A vertical-only TikTok/Reels-style feed, or collapsing media/post levels.
- A visible filmstrip, page dots or drag handle.
- Drag gestures on the T4.7 gallery lightbox.
- Reworking mouse-wheel thresholds or keyboard navigation.

## Notes

- T8.9's transition layer is the natural drag surface. If both tickets are
  implemented together, share `prepareLayer()`, `commitLayer()` and
  `removeLayer()` rather than building two independent media renderers.
- The preview must never become the source of truth: only `go()` changes
  `state`, `currentIndex`, the URL and the counter.
- Use `pointercancel` and `lostpointercapture` as cancel paths; mobile browsers
  can interrupt a gesture for system UI.
- Velocity should be measured over the last ~100 ms, not from the start of the
  gesture, so a slow start followed by a flick feels natural.
- Keep the existing 40 px `touchend` fallback only if pointer events are
  unavailable; do not run both paths for the same gesture.
