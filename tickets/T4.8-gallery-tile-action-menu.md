# T4.8 — Gallery tile action menu: bookmark and start viewer here

## Goal

Give every gallery tile a small three-dot action menu that contains the local
bookmark toggle and a **Start viewer here** action, opening the fullscreen
viewer at that exact media item instead of at the post's first item.

The current gallery shows a standalone bookmark button in the tile's top-right
corner and sends thumbnail clicks to the T4.7 lightbox. The menu should replace
that one-off button without removing the lightbox, and it must work with
JavaScript disabled.

## Current behaviour

- `gallery.html` renders each tile as a `<figure class="gallery-tile">` with:
  - an `<a class="gallery-thumb" data-gallery-item>` that opens the T4.7
    lightbox,
  - a separate `bookmark_button(...)` form with `extra_class="gallery-bookmark"`
    positioned at the top-right,
  - a figcaption linking to the post.
- `list_gallery_images()` groups by `sha256` and returns `f.post_id`, but not
  the post's `service_id`, and not the file's index among the post's
  viewer-eligible media.
- The viewer accepts `?post=<service_id>&i=<index>` (T8.1), but the gallery
  has no link to that URL today.
- `app.js` remembers `[data-viewer-open]` as a generic selector. That is fine
  for the creator page's single "View latest" link, but it cannot restore focus
  to one of many tile viewer links.
- `_viewer_return_url()` only distinguishes `from=gallery`; it always returns
  to the unfiltered gallery root, losing the current page and filters.
- The T9.2 bookmark form already works without JavaScript and `app.js`
  progressively enhances it. Moving the form inside another container must not
  change that contract.

## Scope

**Repository: deterministic viewer target**

- [ ] Extend the gallery row so each deduplicated media item can open the
      viewer at a real post and index:
      - `post_service_id` — the representative post's `posts.service_id`.
      - `viewer_index` — zero-based index of this file among the post's
        `VIEWER_KINDS` rows ordered by `COALESCE(position, 0), id`.
- [ ] Pick one deterministic representative post when the same `sha256` exists
      on several posts. Use the newest by
      `COALESCE(published, 0) DESC, p.id DESC`, then the file's
      `COALESCE(position, 0), f.id`. This matches T4.7's "newest post" hint and
      must agree with the title/URL rendered on the tile.
- [ ] Compute the index in SQL, not per-row Python queries. A CTE/window
      function or correlated count against the post's viewer rows is fine, but
      a 60-tile page must not issue 60 extra queries.
- [ ] Keep the existing dedupe, sort, filter, pagination and `copies` behaviour
      unchanged. The representative choice must not change the gallery order.
- [ ] Add the fields to the decorated gallery image. Expose a
      `viewer_url` (or equivalent template inputs) shaped as:
      `/c/{creator_id}/viewer?post={post_service_id}&i={viewer_index}&from=gallery`
      plus the return path described below.

**Menu markup**

- [ ] Replace the standalone `.gallery-bookmark` control with one action menu
      per tile, outside the `.gallery-thumb` anchor and inside the
      `<figure class="gallery-tile">`.
- [ ] Use a native `<details class="gallery-menu" data-gallery-menu>` +
      `<summary class="gallery-menu-trigger">` disclosure. Do **not** use
      `role="menu"`; a three-dot disclosure with normal links/buttons is simpler
      and works with the browser's native open/close and keyboard behaviour.
- [ ] The summary includes an `aria-label` naming the target, e.g.
      `Actions for {post title or filename}`, and a decorative `⋮` glyph marked
      `aria-hidden="true"`. The accessible name must not be only "menu" or "…".
- [ ] The panel contains exactly these two actions for this ticket:
      1. the existing bookmark form macro, with its current `next` URL, so the
         form POST still works without JavaScript;
      2. **Start viewer here** linking to the tile's `viewer_url`, with
         `data-viewer-open` and a unique focus-restore target.
- [ ] Keep the bookmark button's real state (`Bookmark` / `Bookmarked`,
      `aria-pressed`) and let `app.js`'s existing `data-bookmark-form`
      enhancement keep updating it in place.
- [ ] The menu must not be inside the thumbnail anchor and must not trigger the
      lightbox. A click on the summary or panel is not a `[data-gallery-item]`
      click.
- [ ] No-JS contract: `<details>` opens, the bookmark form submits and returns
      to the current gallery URL, and **Start viewer here** is a normal link.
- [ ] With JavaScript, `app.js` closes other open tile menus when one opens,
      closes the open menu on `Escape`, and closes it on a click outside the
      menu. No timers, observers or page-load work.
- [ ] Focus stays on the summary when the menu closes with `Escape`; opening
      the menu does not steal focus from a keyboard user.

**Viewer return and focus**

- [ ] The viewer link carries the current gallery URL, including filters and
      `page`, as a local return path. Extend `_viewer_return_url()` to accept
      that path only through `_safe_next()` and only when it starts with
      `/c/{creator_id}/gallery`; otherwise fall back to the normal gallery
      root. No open redirects.
- [ ] Add a unique focus target such as
      `id="gallery-menu-{sha256}"` on the summary and
      `data-viewer-focus="#gallery-menu-{sha256}"` on the viewer link.
      Update `app.js` to store the exact selector when
      `data-viewer-focus`/an id is present, instead of always
      `[data-viewer-open]`.
- [ ] Closing the viewer returns to the same filtered/paged gallery URL and
      focuses that tile's summary. The menu may be closed; the summary is still
      visible and focusable.

**Styling**

- [ ] Put the trigger at the tile's top-right, above the thumbnail, with a
      visible focus ring, sufficient contrast over bright and dark thumbnails,
      and no dependence on hover for discoverability.
- [ ] Remove the summary disclosure marker (`list-style: none` and the WebKit
      pseudo-element) and give the open state a clear background.
- [ ] The panel is absolutely positioned, above neighbouring tiles
      (`z-index`), with a solid theme background, border and shadow. It must
      not be clipped by the tile or the grid.
- [ ] On a 390 px viewport the panel stays inside the viewport and does not
      cover the tile's own menu trigger.
- [ ] The menu must not cover the bottom-right kind/duration badge or the
      centred play glyph at rest.
- [ ] `prefers-reduced-motion: reduce` removes any open/close transition; no
      layout shift and no transition on the thumbnail itself.

**Tests**

- [ ] Repository test: duplicate `sha256` across two posts resolves to the
      newest post; `viewer_index` matches the index the viewer actually renders
      for image, GIF and video mixes (including non-media/audio rows in the
      post).
- [ ] Route/template test: each tile renders one `data-gallery-menu`, one
      summary, one bookmark form and one viewer link; none is inside the
      thumbnail anchor; the viewer URL contains the expected `post`, `i` and
      return path.
- [ ] No-JS form test: the bookmark `action` and hidden `next` still target the
      current gallery filters/page.
- [ ] Focus test: the viewer link exposes a unique focus target; `app.js`
      stores that selector rather than the first `[data-viewer-open]`.
- [ ] Return-path test: accepted local gallery URL with filters; rejected
      `//host`, absolute URL, backslash/CRLF and non-gallery paths fall back.
- [ ] Update the T9.2 gallery assertions that currently expect
      `.gallery-bookmark` and one visible bookmark button per tile; the
      bookmark contract now lives inside the disclosure.
- [ ] Markup/CSS test: panel styles, z-index, focus-visible and reduced-motion
      block exist; `viewer.js` and `app.js` pass `node --check`.
- [ ] Browser acceptance in Chromium and Firefox, with JavaScript disabled for
      one pass: open/close the menu by keyboard and pointer, bookmark from the
      menu, start the viewer on the fifth image, close it, and land back on the
      same filtered page with focus on that tile's trigger.

## Acceptance criteria

- [ ] Every gallery tile has one discoverable three-dot menu with Bookmark and
      Start viewer here.
- [ ] Starting the viewer opens the exact media item selected in the gallery,
      not the post's first item.
- [ ] With JavaScript disabled both menu actions still work; the bookmark is a
      normal POST and the viewer action is a normal link.
- [ ] Closing the viewer returns to the same gallery page/filters and restores
      focus to the originating tile trigger.
- [ ] The lightbox still opens on a thumbnail click; menu clicks never open it.
- [ ] Existing gallery filtering, sorting, dedupe, pagination, bookmark state
      and viewer navigation remain green.

## Out of scope

- Adding the same menu to creator-page post rows, post attachments or the
  bookmarks library grid (possible follow-ups).
- Download, copy-link, hide, delete or share actions.
- Changes to the T4.7 lightbox itself.
- Viewer slide/swipe animation; those are T8.9 and T8.10.
- A command palette, context menu on right-click, or ARIA `role="menu"` roving
  tabindex implementation.

## Notes

- The gallery is deduplicated by `sha256`, but the viewer is post-scoped. The
  representative post and `viewer_index` must be computed together from the
  same row; never pair the newest post title with an index from an arbitrary
  copy.
- `VIEWER_KINDS` is `("image", "gif", "video")`. The viewer index must count all
  three, in `COALESCE(position, 0), id` order, because the viewer moves through
  them as one list.
- Keep the menu's two actions as ordinary controls. A disclosure avoids the
  focus-management burden of a menu widget and degrades better.
- `filters.url_for(creator.id)` already produces the current gallery path and
  query string; reuse it for both the bookmark `next` value and the viewer
  return path.
