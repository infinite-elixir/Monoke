# T11.11 — Media opens fitted to the viewport, and the diagonal expand control is removed

## Goal

Clicking a gallery tile or a media bookmark must open the merged viewer with the
**whole image visible and fitted to the viewport** — never zoomed, cropped,
scrolled or enlarged past its natural size. The viewer opens directly in its
full-viewport (expanded) state, so the **diagonal expand/collapse button is no
longer needed** and must be removed from the control bar.

## Reported behaviour

- Opening media currently lands in a zoom-style presentation instead of a
  fitted one.
- The diagonal arrow button in the bottom bar (the expand/collapse control) is
  not wanted.

## Locked decisions

| Question | Decision |
|---|---|
| Entry state | Every tile/bookmark entry opens the viewer **expanded**, fitted to the viewport. There is no compact intermediate state. |
| Image sizing | `object-fit: contain`; the full image is visible. Preserve aspect ratio. Do not crop, stretch, or upscale beyond the fitted size. |
| Videos | Same fitted box as images, with native controls usable. |
| Expand control | Remove the diagonal arrow button, its SVG icons, its JS handler, and its `compact`/`expanded` toggle. |
| Browser fullscreen | Keep the separate fullscreen control and the Fullscreen API behaviour unchanged. |
| Close | Close button, Escape and the backdrop still close the viewer. Escape must not leave a half-collapsed state. |
| Compact styles | Remove or retire the now-unreachable `.lightbox.is-compact` entry path instead of leaving dead mode-switching code. |

## Scope

**Template (`partials/lightbox.html`)**

- [ ] Remove the `[data-lightbox-expand]` button and its two SVG icons.
- [ ] Keep the three-dot menu, media bookmark, fullscreen, hide and post controls.

**Controller (`lightbox.js`)**

- [ ] `openOverlay()` enters the expanded state directly; no `setMode("compact")` on open.
- [ ] Remove `expandButton` lookup, `toggleExpand()`, the expand click branch and
      any `aria-pressed`/label sync that only served that button.
- [ ] Remove keyboard/backdrop paths that collapse expanded → compact.
- [ ] Escape / close still exits cleanly from expanded and browser-fullscreen states.
- [ ] Keep `object-fit: contain` sizing and the existing safe-area padding.

**Styles (`style.css`)**

- [ ] Delete `[data-lightbox-expand]` rules (including the mobile `display: none` rule).
- [ ] Delete or fold the compact-only stage rules into the expanded layout.
- [ ] Verify a portrait image, a landscape image and a small image all fit without
      cropping or forced upscaling at desktop and mobile widths.

**Tests**

- [ ] Template test asserts there is no `data-lightbox-expand` control.
- [ ] JS source test asserts opening a tile does not reference a compact entry mode.
- [ ] DOM/static test asserts `object-fit: contain` remains for `.viewer-media-el`.
- [ ] `node --check src/monoke/web/static/lightbox.js` and `uv run pytest` pass.

## Acceptance criteria

- [ ] Opening any image from the gallery or `/bookmarks` shows the complete image
      fitted to the screen, with no crop and no horizontal/vertical scrolling.
- [ ] There is no diagonal expand/collapse button in the viewer bar.
- [ ] Fullscreen, bookmark, hide/show, post navigation and close still work.
- [ ] No compact-mode flash on open: the viewer paints expanded immediately.
