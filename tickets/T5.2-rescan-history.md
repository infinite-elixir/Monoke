# T5.2 — Full rescan and run history

## Goal
Make the archive's own history visible and give the user a big red "rebuild everything" lever.

## Scope

- [x] `POST /c/{creator_id}/rescan` → `mode=full` run that re-fetches every detail and
      re-extracts links/files/tags (no schema change, no data loss).
- [x] `GET /c/{creator_id}/runs` — table of runs: started, mode, duration, seen/new/updated,
      links, dead, status, error (truncated with a title attribute).
- [x] Dashboard shows the last run status per creator (`ok`, `failed`, `running`, `cancelled`).
- [x] Retry button on a failed run that starts the same mode.
- [x] Rescan is idempotent: running it twice yields identical row counts and no duplicates.
- [x] Confirmation dialog explaining the cost ("re-fetch 782 posts, ~6 min").

## Acceptance criteria

- [x] Two consecutive full rescans produce identical `posts`, `links`, `files` counts.
- [x] Run history renders 50 runs with pagination and correct durations.
- [x] A failed run shows its stored error and can be retried in one click.
- [x] Rescan while a run is active is refused with a clear message (one run per creator).
- [x] Deleting a creator deletes its run history.

## Notes
- "Full" means details + extraction, not a cache wipe. Add a separate `--no-cache` only for
  debugging.
