# T11.3 — Open media bookmarks in the merged lightbox-viewer

## Goal

Clicking a media bookmark in the library opens the merged lightbox-viewer from
T11.1 on that exact item. Prev/next then walks **all media in the underlying
post**, not just bookmarks, so the post up/down buttons keep working and the
behaviour matches opening the same item from the gallery.

There is no `/bookmarks/viewer` page and no bookmark-only playlist.

## Locked decisions

| Question | Decision |
|---|---|
| Playlist | All media of the underlying post, in `COALESCE(position, 0), id` order. |
| Start item | The bookmarked `sha256`, resolved against the post payload. If the sha is missing from the post, show the existing "Media unavailable" state. |
| Navigation | Left/right stays in the post; up/down crosses posts through the retained `/viewer/data` JSON endpoint. |
| Missing attachment | Still opens the overlay on an unavailable item; prev/next remain available. |
| No-JS | The media tile stays a normal link to its post page. |

## Current behaviour

- `bookmarks.html` `bookmark_media_tile` links the thumbnail and title to
  `item.post_url` (`/c/{creator}/p/{service_id}`).
- `_decorate_library_media()` adds creator/post URLs, kind flags, dimensions
  and duration but no sha/service-id data attributes for a viewer.
- The bookmarks page has no overlay markup. Gallery pages do, and T11.1 makes
  it load from `lightbox.js`.
- `/bookmarks/viewer` and `bookmark_viewer_state()` were removed by T10.1;
  do not bring either back.

## Scope

**Data**

- [ ] Ensure the media bookmark rows used by the bookmarks page expose:
      `creator_id`, `post_service_id` (the underlying post's service id),
      `sha256`, `kind`, `url`, `thumb_url`, `title`, `post_title`,
      `post_url`, `missing`, dimensions/duration and `bookmarked=True`.
- [ ] No new playlist repository function is needed. The overlay resolves the
      post through `/c/{creator}/viewer/data?post={service_id}` and finds the
      item whose `sha256` matches the bookmark.
- [ ] Keep the post-scoped payload shape from T11.1 unchanged.
- [ ] Do not compute a bookmark-only playlist, index or manifest.

**Markup**

- [ ] Include the merged overlay partial/markup on `/bookmarks` (including
      creator-filtered and paginated views) exactly as on the gallery.
- [ ] Load `lightbox.js` on the bookmarks page; do not load `viewer.js` or the
      deleted viewer page.
- [ ] Media tile thumbnail placeholder remains an anchor to the post URL with
      `href` intact. Add the overlay hooks:
      - `data-lightbox-open`
      - `data-post-service-id="{{ item.post_service_id }}"`
      - `data-sha256="{{ item.sha256 }}"`
      - `data-kind`, `data-full`/`data-url`, `data-title`, `data-post-url`.
      Do not add `data-viewer-open` or `data-viewer-focus`.
- [ ] Make a missing media tile (`.is-missing`, "No longer attached") open the
      overlay in the unavailable state only if the sha/service-id are known.
      Otherwise leave it non-interactive, as today.
- [ ] Post bookmark cards keep opening the post page; only media tiles open the
      overlay.

**Overlay integration**

- [ ] Reuse the same controller and root as the gallery. The bookmarks page
      must not ship a second overlay or a second copy of the navigation code.
- [ ] Opening a media bookmark paints the bookmark thumbnail immediately from
      tile data, then hydrates the post playlist from JSON and selects the item
      by `sha256`.
- [ ] If the sha is absent from the payload (file removed/changed upstream),
      keep the overlay open on the unavailable state and allow left/right to
      recover to a real item.
- [ ] Post up/down buttons, bookmark shortcuts, fullscreen, hide controls and
      keyboard behaviour are inherited from T11.1/T11.2 without a special mode.
- [ ] Closing the overlay returns focus to the originating bookmark tile and
      leaves the bookmarks page's filters/page in place; no navigation occurs.
- [ ] Deleting/unbookmarking the current item from the bottom bar does not eject
      the viewer mid-view; the library reflects the removal when the overlay
      closes.

**Tests**

- [ ] Template: each bookmarks media tile renders the overlay hooks and still
      has its post `href`; post tiles do not get media-overlay hooks.
- [ ] Template: `/bookmarks` contains `#gallery-lightbox` and loads
      `lightbox.js`; no `/bookmarks/viewer` or `/viewer` page link appears.
- [ ] Payload test: opening a bookmark selects its sha, not the post's first
      item or the first bookmark.
- [ ] Navigation test: prev/next reaches unbookmarked media in the same post;
      post up/down still crosses posts.
- [ ] Missing-attachment test: unavailable state renders and recovers on next.
- [ ] No-JS test: the tile href still resolves to the post page.
- [ ] Existing bookmark, gallery and viewer tests stay green.

## Acceptance criteria

- [ ] Media bookmarks open the merged lightbox-viewer at the bookmarked item.
- [ ] Prev/next walks the whole underlying post, including unbookmarked media.
- [ ] Post up/down, bookmarks, fullscreen and hide controls work identically to
      the gallery entry point.
- [ ] Missing media opens the unavailable state without a 404 or blank overlay.
- [ ] Without JavaScript, media bookmark tiles still navigate to their post.
- [ ] No bookmark-only viewer route, playlist or manifest exists.

## Out of scope

- A bookmark-only playlist or a `/bookmarks/viewer` route.
- Changing the bookmarks page grouping or pagination (T9.4).
- Opening post bookmarks in the overlay.
- Cross-creator playlists.

## Notes

- The bookmarks tile already has the post URL; adding `post_service_id` and
  `sha256` is enough for the overlay to hydrate by post.
- Resolve by `sha256` rather than a stored index: bookmark rows can outlive file
  ordering changes, and a post can gain or lose attachments.
- If the payload request fails, keep the tile's URL visible and show the
  existing non-blocking flash.
