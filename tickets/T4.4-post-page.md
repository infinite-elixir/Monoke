# T4.4 — Post page

## Goal
The post, everything in it, and every link, cleanly.

## Scope

- [ ] `GET /c/{creator_id}/p/{post_id}`.
- [ ] Layout: title, date (+ "edited" when `added` differs from `published`), tags, then two
      columns on desktop / stacked on mobile:
      - **Caption**: sanitized `caption_html`; images lazy-loaded; links open in a new tab.
      - **Links** (primary column): grouped by category in priority order
        Drive → MEGA → Direct media → Video host → Cloud → Social → Shortener → Site asset →
        Other. Each row: category badge, label, host+truncated path, copy button, open button.
        Unresolved shorteners show the original plus a "not resolved" hint.
- [ ] **Copy all links** button (newline-separated, respecting the visible filter) with a toast.
- [ ] **Attachments** section, one row per file:
      thumbnail (`img.cum.st`), filename, kind badge, MIME, size (human-readable), dimensions,
      duration for video/audio, `open` (edge URL), `copy link`.
      Media is **not** fetched on page load. Each row has a **Load** button that sets
      `img.src` / `video.src` on first click (and only then). Videos get
      `<video controls preload="none">` with a variant selector when `720p.mp4`/`240p.mp4`
      exist. Nothing is written to disk, no service worker, no IndexedDB.
      A post with `attachments: []` shows "no attachments" — there is no dead-file concept.
- [ ] Prev/next navigation using `posts.prev_id` / `posts.next_id`, falling back to
      published-order neighbours when null.
- [ ] "Open original" → `https://cum.st/creators/{service}/{creator_id}/post/{post_id}`.
- [ ] Breadcrumbs back to the creator page with the current filters preserved.

## Acceptance criteria

- [ ] Post 172189145 renders the Drive + MEGA links (labels `Link`, `Backup Link`), the
      `109987`-byte JPEG with dimensions, and a working thumbnail.
- [ ] Post 171761266 (no attachments) shows "no attachments" and still renders its caption.
- [ ] Copy-all produces exactly the visible links, one per line.
- [ ] Caption is sanitized: no `<script>`, no `on*` handlers, links carry
      `rel="noopener noreferrer nofollow"` and `target="_blank"`.
- [ ] Video posts render a `<video>` with no `src` until **Load** is clicked; nothing streams
      before that.
- [ ] Monoke writes no media bytes to disk: no cache directory, no service worker, no IndexedDB,
      no blob persistence. Refresh the page and the media is unloaded again.
- [ ] Prev/next never 404 at the boundaries (first/last post).
- [ ] No outbound request from the page other than `img.cum.st` thumbnails, the edge media the
      user explicitly plays, and user-initiated clicks.

## Notes
- The link table is the product. Keep it dense, monospace for URLs, never truncate the copyable
  value.
- Edge URL host is deterministic (`sha[0] % 3`), so the same file always resolves to the same
  host across pages.
