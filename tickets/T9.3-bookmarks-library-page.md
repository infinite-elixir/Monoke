# T9.3 — Bookmarks library page and navigation

## Goal

Give bookmarks a permanent home: `/bookmarks` lists bookmarked posts and
bookmarked media newest-bookmark first, across every creator, with a tab per
view, a creator filter and one-click removal. A **Bookmarks** entry in the site
nav makes the page reachable from anywhere.

## Current behaviour

- T9.1 provides the tables, list functions and toggle endpoints; T9.2 provides
  the reusable bookmark button and the creator/post/gallery/viewer controls.
- There is no `/bookmarks` route and no nav entry. The primary nav is currently
  `Creators` / `Links` in `templates/base.html`.
- Post cards on the creator page use `partials/post_row.html`, which expects
  per-post facets, tags and filters that the library does not have.

## Scope

**Route and query model**

- [ ] `GET /bookmarks` (HTML) with defaults:
      - `view=all|posts|media` (unknown values fall back to `all`)
      - `creator=<internal creator id>` (optional; unknown → ignore or 404)
      - `page` (1-based, clamped)
- [ ] Three presentations:
      - `all`: a **Posts** section and a **Media** section, each capped and
        linking to its dedicated tab when longer.
      - `posts`: post bookmarks only.
      - `media`: media bookmarks only.
- [ ] Page size reuses the app's existing page constants (post bookmarks use
      `PER_PAGE`, media bookmarks use `GALLERY_PER_PAGE`; document the choice).
- [ ] A creator filter `<select>` appears only when bookmarks exist for more
      than one creator, listing creators that actually have bookmarks.
- [ ] Tabs preserve `creator` and reset `page` to 1 when switched.

**Post bookmarks section**

- [ ] Card list with: thumbnail, title (linked to the post page), creator name
      (linked to the creator), publish date, and a "Bookmarked <relative time>"
      label.
- [ ] Use a library-specific partial; do not force `post_row.html` to render
      facets it does not have.
- [ ] A remove control uses T9.2's `partials/bookmark_button.html` with
      `next` set to the current `/bookmarks` URL, so removal returns to the same
      tab/filter/page.
- [ ] Newest bookmark first; deterministic tie-break on `post_bookmarks.id`.

**Media bookmarks section**

- [ ] Thumbnail grid reusing the gallery tile look (no lightbox requirement;
      clicking opens the media edge URL or the post).
- [ ] Each tile shows kind, optional duration, creator name, and the post title;
      link the caption to the post.
- [ ] Missing-attachment rows (`missing = 1` from T9.1) render a labelled
      placeholder ("No longer attached") with a working remove button instead of
      a broken image.
- [ ] Per-tile remove control via the shared bookmark partial.
- [ ] Newest bookmark first; deterministic tie-break on `media_bookmarks.id`.

**Navigation and pages**

- [ ] Add `Bookmarks` to `.site-nav` in `base.html` with
      `aria-current="page"` when `active_page == "bookmarks"`, matching the
      existing Creators/Links pattern.
- [ ] Add a bookmark count badge in the nav only if it does not shift layout
      noticeably; otherwise omit it (state the choice in the Resolution).
- [ ] Empty states:
      - no bookmarks at all: explain how to bookmark a post or image and link to
        Creators;
      - a tab/filter with no results: offer "Show all" / clear the creator
        filter.
- [ ] The page must work with JavaScript disabled; removal is a normal form
      POST.
- [ ] Mobile layout stays single-column; the tab strip is horizontally
      scrollable rather than overflowing.

**Tests**

- [ ] Empty database renders the global empty state and no broken grid.
- [ ] `view=posts`, `view=media`, unknown `view` fallback, and `view=all`
      sections.
- [ ] Ordering is newest bookmark first, with the documented id tie-break.
- [ ] Creator filter limits both sections and survives tab switches; `page` is
      preserved within a tab and reset when switching tabs.
- [ ] Removal POST redirects back to `/bookmarks` with the same query string and
      the item disappears on the next GET.
- [ ] A media bookmark whose file is gone renders the missing placeholder and
      can still be removed.
- [ ] Nav link present on every page and `aria-current` only on `/bookmarks`.
- [ ] No N+1 queries: list pages fetch creators/thumbnails in batch.
- [ ] Existing tests stay green.

## Acceptance criteria

- [ ] `/bookmarks` is reachable from the primary nav and lists every bookmarked
      post and media item, newest bookmark first.
- [ ] Tabs and the creator filter narrow the list without losing the other
      dimensions, and paging does not repeat or skip rows.
- [ ] Removing a bookmark from the library returns to the same view and the item
      is gone.
- [ ] A bookmark whose media disappeared upstream is still visible and
      removable, with a clear placeholder.
- [ ] The page is keyboard navigable and works without JavaScript.
- [ ] Empty states never show an empty grid or a broken image.

## Out of scope

- Bookmarking from the library (only removal; adding stays on post surfaces).
- Search inside bookmarks, bulk select/remove, reordering, notes, collections.
- Exporting bookmarks or importing cum.st's upstream bookmarks.
- New bookmark storage/endpoint work (T9.1) and the surface controls (T9.2).

## Notes

- `list_post_bookmarks` and `list_media_bookmarks` already join creators and
  provide totals; the route should call them twice for `all` and reuse the
  counts for the tab labels rather than running four queries.
- The library is creator-agnostic, so no `/c/{id}` prefix: use `/bookmarks` and
  keep `active_page="bookmarks"` in the render context.
- Keep the removal form's `next` value server-derived from the current request
  URL, never from `Referer`.

## Resolution

`GET /bookmarks` is implemented in `routes.py` with a `BookmarkFilters`
dataclass (`view`, `creator`, `page`) in `filters.py`. Unknown `view` values
fall back to `all`, an unknown creator id is ignored, and pages clamp to the
last real page. Post bookmarks page by `PER_PAGE`, media by `GALLERY_PER_PAGE`;
in `view=all` both sections are capped at those sizes and link to their
dedicated tab. The route calls each list function once (plus at most one
refetch when a hand-typed page is past the end), and their totals also feed the
tab counters.

`bookmarks.html` renders the tab strip (horizontally scrollable on mobile), a
creator `<select>` only when more than one creator has bookmarks, library-
specific post cards (thumbnail, title, creator, date, "Bookmarked <relative>")
and a gallery-style media grid. Removal reuses
`partials/bookmark_button.html` with `next` set to the current
`/bookmarks` query string. Missing media rows show "No longer attached" with a
working remove button. Global and per-view empty states are separate, so a
filtered tab never shows an empty grid.

`Bookmarks` is in `.site-nav` with `aria-current="page"` only on `/bookmarks`.
No count badge was added: it would reflow the three-item nav on narrow screens
for little benefit. Everything is a normal GET/form POST and works with
JavaScript disabled.

Tests in `tests/test_bookmarks_page.py` cover the empty database, all three
views plus fallback, ordering, creator filter propagation, tab page reset,
out-of-range paging, removal redirecting to the same query, missing media
removal, per-view empty states, nav presence/`aria-current`, and filter parsing.
