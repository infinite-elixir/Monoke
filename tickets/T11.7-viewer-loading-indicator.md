# T11.7 — Loading indicator for slow viewer media

## Goal

Some media takes a noticeable time to load, and the viewer currently shows
nothing at all while it waits. Add a small **corner progress pill** so the user
knows the viewer is working, without flashing on fast/cached media.

## Locked behaviour

- A compact pill reads **Loading…** with a small activity dot.
- It sits in the bottom-left of the stage, above the safe area and clear of the
  bottom bar/handle, the top caption and the close button.
- It appears only after a short delay (~150 ms), so cached images and instant
  video metadata never flash it.
- It applies in compact, expanded and browser-fullscreen modes.
- It is visual status only: no layout shift, no focus, no pointer capture.
- It hides as soon as the current medium is ready, errors, is replaced by
  another medium, or the overlay closes.

## Current behaviour

- `render()` swaps the image `src` / starts the video and calls
  `watchCurrentMedia`.
- `watchCurrentMedia` only flips the internal `mediaReady` flag to schedule
  preloading; nothing is rendered while the request is in flight.
- `viewer-unavailable` appears after an error, but there is no "we are still
  fetching/decoding" state.

## Scope

**Markup**

- [ ] Add one loading hook inside the stage, for example
      `<p class="viewer-loading" data-lightbox-loading role="status"
      aria-live="polite" hidden>…Loading…</p>`.
- [ ] Keep the text as the accessible status; the dot is decorative.

**Behaviour**

- [ ] Show the pill after ~150 ms when the visible media is still loading, or
      when a payload request is in flight and no current media is painted yet.
- [ ] Hide it on image `load`/`error`, video `loadeddata`/`canplay`/`error`, or
      as soon as the payload resolves and renders.
- [ ] For video, also show it while buffering (`waiting`/`stalled`) once
      playback has begun, and hide again on `playing`/`canplay`.
- [ ] Cancel the delay timer when the item changes, closes or unloads, so a
      stale load event from a previous item cannot clear a new wait.
- [ ] Clear the pill when the current medium is unavailable or when a flash
      error is shown.
- [ ] Do not show it for idle neighbour preloading or payload prefetch; only
      the visible item and its pending payload count.
- [ ] Keep the pill visible long enough to be readable if it has appeared; avoid
      a one-frame flicker when load completes at the same moment.

**Styling**

- [ ] Small translucent (`#0b1017`) rounded pill with border/shadow, matching
      the bar's visual language.
- [ ] Bottom-left placement using `env(safe-area-inset-*)`, above the bar and
      handle, with `z-index` below the bar and menu.
- [ ] `pointer-events: none`; it never blocks a swipe, click or edge zone.
- [ ] Fits at 390 px without overlapping the close target or caption.
- [ ] `prefers-reduced-motion: reduce` stops the dot animation but keeps the
      text state.

**Tests**

- [ ] Template: exactly one loading hook, with `role="status"`, `hidden` and
      accessible text.
- [ ] JS source/behaviour: delayed show, hide on load/error/close, stale-token
      guard, and no trigger from preload-only paths; cover a pure helper if one
      keeps the test small.
- [ ] CSS: absolute bottom-left, safe-area padding, z-index under the bar,
      pointer-events none, reduced-motion block.
- [ ] `node --check src/monoke/web/static/lightbox.js` and `uv run pytest` pass.

## Acceptance criteria

- [ ] A slow image/video shows a small **Loading…** pill without moving layout.
- [ ] Cached media never flashes the pill.
- [ ] Quick next/previous navigation never leaves a stale pill behind.
- [ ] The pill is absent once media is ready and after an error state.
- [ ] Visible and polite for screen readers, without stealing focus.

## Out of scope

- Percentage progress or per-byte download bars.
- Skeleton/shimmer placeholders and changing preload policy.
- Fixing the first-forward black flash (T11.4).
- Service-worker or disk caching changes.

## Notes

- Reuse the existing `watchCurrentMedia`, `mediaReady`, `unloadMedia` and
  hydration tokens; a separate `loadingToken`/timer mirrors `hydrateToken`.
- The indicator should describe the **visible** item only. Preloading the
  neighbours must stay invisible.
- Prefer toggling a class/`hidden` on one persistent node over creating nodes
  per render.
