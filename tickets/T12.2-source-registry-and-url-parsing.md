# T12.2 — Source registry, `SourceRef`, and dual URL parsing

## Goal

Make "which site is this URL from?" a first-class value instead of an
implicit cum.st assumption.

## Scope

**Types and registry**

- [ ] Add `src/monoke/sources/__init__.py`, `base.py`, `registry.py`.
- [ ] Define:

      ```python
      @dataclass(frozen=True, slots=True)
      class SourceRef:
          source: str            # "cumst" | "pawchive"
          service: str           # patreon, fansly, fanbox, discord, ...
          creator_id: str
          post_id: str | None = None
      ```

- [ ] Define a `SourceAdapter` protocol/ABC with, at minimum:

      ```python
      id: str
      label: str
      site_base: str
      api_base: str

      def creator_url(ref, *, base=None) -> str
      def post_url(ref, post_id=None, *, base=None) -> str
      def profile_path(ref) -> str
      def posts_path(ref) -> str
      def post_path(ref, post_id=None) -> str
      def posts_params(offset, page_size) -> dict
      def parse_profile(payload) -> CreatorProfile
      def parse_posts_page(payload, *, offset, page_size) -> PostsPage
      def parse_post(payload) -> PostDetail
      def creator_images(profile) -> dict
      def image_hosts() -> frozenset[str]
      ```

- [ ] Add `registry.detect(raw) -> SourceRef`, `registry.get(source_id)`,
      `registry.all()`, and `registry.ids()`.
- [ ] Keep `UrlError` (`monoke.sources.UrlError`) as the single parser error.

**Parsing**

- [ ] cum.st forms keep working exactly as in T1.1:
      `https://cum.st/creators/{service}/{id}[/post/{pid}]`.
- [ ] pawchive forms:
      - [ ] `https://pawchive.pw/{service}/user/{id}`
      - [ ] `https://pawchive.pw/{service}/user/{id}/post/{pid}`
      - [ ] trailing slash, query string, `#fragment`, `http://`, `www.`,
            uppercase host, surrounding whitespace
      - [ ] bare `pawchive.pw/patreon/user/30500811`
- [ ] Reject a cum.st path on pawchive and vice versa with a message naming the
      expected host/path.
- [ ] Keep service slugs open (`^[a-z0-9_-]+$`) but expose known-service hints
      per source (`patreon, fansly, onlyfans, ...` for cum.st;
      `patreon, fanbox, discord` for pawchive).
- [ ] Keep creator/post IDs as strings and validate digits.

**Compatibility**

- [ ] Move the cum.st URL module under `sources/cumst/urls.py` (or wrap it) and
      leave `monoke.cumst.urls` as a re-export shim for one release.
- [ ] `CumstRef` becomes an alias or is replaced by `SourceRef(source="cumst")`;
      update `crawler/crawl.py`, `web/routes.py`, `web/tasks.py` and
      `cumst/client.py` in this ticket or the follow-ups, but do not leave two
      incompatible ref types in active use.
- [ ] Update user-facing errors to mention both example URLs.

## Acceptance criteria

- [ ] Table-driven tests for both hosts, every accepted/rejected shape and both
      post/creator variants.
- [ ] `registry.detect("https://pawchive.pw/patreon/user/30500811")` returns
      `SourceRef("pawchive", "patreon", "30500811", None)`.
- [ ] `registry.detect("https://cum.st/creators/patreon/274608")` returns
      `SourceRef("cumst", "patreon", "274608", None)`.
- [ ] Existing `tests/test_urls.py` cases still pass (through the shim or an
      updated import).
- [ ] No network access in these tests.

## Out of scope

- Adapter payload parsing and media URLs (T12.5/T12.6).
- Database changes (T12.3).

## Notes

- Do not encode the source in `service` (e.g. `pawchive:patreon`). It would
  break service facets and make duplicate cleanup impossible.
- Host detection is on the registrable host, not a substring: reject
  `pawchive.pw.evil.example`.
