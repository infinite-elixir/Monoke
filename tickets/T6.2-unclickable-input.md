# T6.2 — Add-creator text field and submit button not clickable

## Goal
On the index page the creator URL input and "Archive" button cannot be clicked/typed into. Likely a stacking/overlay or JS issue.

## Scope
- [x] Reproduce in browser devtools; check for overlapping elements, z-index, pointer-events.
- [x] Check `app.js` load order: it is included in `<head>` without `defer` while `htmx.min.js` uses `defer`; verify no JS error blocks hydration.
- [x] Verify no global click handler calls `preventDefault` on the form/input.
- [x] Add a debug mode (T6.4) to capture console errors.

## Acceptance criteria
- [x] Input accepts typing and button submits the form on a clean page.
- [x] No JS console errors.

## Resolution

Reproduced in Firefox (Playwright) on a debug-mode server:

- `document.elementFromPoint()` over the input returns `#creator-url`, and over
  the button returns the button — nothing covers them. The stylesheet has no
  `pointer-events` rule and the only fixed-position element is the debug
  panel, which is hidden unless debug mode is on.
- Both scripts now load with `defer`, so `app.js` cannot run before the DOM
  exists. The click handler only calls `preventDefault()` for
  `[data-sync-form]`, `[data-copy*]`, `[data-load-media]` and
  `[data-sync-cancel]`; the add-creator form posts normally.
- The browser check types into `#creator-url`, clicks **Archive** and confirms
  the form round-trips (an invalid URL comes back as a field error).
- Console: no errors on the index, creator, post and link pages.
