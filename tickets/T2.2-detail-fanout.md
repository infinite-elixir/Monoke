# T2.2 — Detail fan-out and resumability

## Goal
Fetch, extract, and persist every post detail without hammering the API or losing progress
when the process dies.

## Scope

- [ ] `asyncio.Queue` + N worker tasks (default 4, capped by the client semaphore).
- [ ] Per-post pipeline: `post()` → `extract` (T3.1–T3.4) → single transaction writing
      `posts`, `files`, `links`, `tags`.
- [ ] A post is "complete" when `posts.fetched_at` is set **and** its links/files were written
      in the same transaction. Resume mode skips complete posts.
- [ ] `--limit N` stops after N details (useful for smoke runs and demos).
- [ ] `progress` callback signature: `progress(done, total, posts_per_s, current_title)`.
- [ ] Per-post failures are collected, not fatal: `{post_id, error}` list in the result;
      the run still finishes with `status="done"` unless > 50 % failed (then `failed`).
- [ ] On `ApiBlocked`, cancel pending tasks, flush the queue, and finish the run as `failed`.

## Acceptance criteria

- [ ] Kill the process mid-crawl (SIGINT) and re-run: it resumes, no duplicates, no double links.
- [ ] `--limit 5` writes exactly 5 posts and leaves the rest untouched.
- [ ] Concurrency is never exceeded (assert with an instrumented client in tests).
- [ ] A post that raises during extraction does not stop the other 760; it appears in
      `errors` and can be retried by a re-run.
- [ ] Database has one row per post and no orphan links/files after a full run.

## Notes
- Write per post, not at the end — that is what makes resume work.
- Extraction functions must be pure (payload in, rows out) so they are trivially testable.
