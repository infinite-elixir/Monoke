# T12.6 — Pawchive API adapter and canonical payload mapping

## Goal

Turn pawchive's Kemono-shaped payloads into the same internal models the rest
of Monoke already understands, including a correct mapping for its missing
metadata.

## Endpoints

| Purpose | Request |
|---|---|
| Profile | `GET /api/v1/{service}/user/{id}/profile` |
| Posts | `GET /api/v1/{service}/user/{id}/posts?o={offset}` |
| Post | `GET /api/v1/{service}/user/{id}/post/{post_id}` |

The posts endpoint returns a bare array of 50 items and **no total**. There is
no `n` parameter to rely on. Empty page terminates the walk.

## Mapping

**Profile**

| Pawchive | Canonical |
|---|---|
| `id` | `CreatorProfile.id` |
| `name` | `name` and `display_name` |
| `service` | `service` |
| `indexed` (ISO) | `indexed` (epoch seconds) |
| `updated` (ISO) | `updated` (epoch seconds) |
| `public_id` | keep in `raw_json` only |
| — | `content_updated`, `bookmarked`, `has_tags`, `gender` = `None` |

**Post list**

- [ ] `PostsPage.total = None`; extend the model to `int | None`.
- [ ] Each array item becomes `PostSummary`:
      `id`, `service`, `title`, `caption_text` from sanitized `content`,
      `added`, `published`, `edited` (epoch), `attachments`.
- [ ] `PostSummary.edited` is added to the canonical model and is `None` for
      cum.st.

**Post detail**

- [ ] `content` → `caption_html`; `caption` stays `None`.
- [ ] `added`, `published`, `edited` → epoch seconds.
- [ ] `tags` string → `list[Tag]`:
      - [ ] strip surrounding `{`/`}`;
      - [ ] split on commas, trim whitespace, drop empties and duplicates;
      - [ ] `slug` = a URL-safe slug derived from the label (lowercase,
            whitespace to `-`), `label` = original text;
      - [ ] tolerate `null`, `""`, a plain comma string and an already-parsed
            array if the API ever changes.
- [ ] `prev` / `next` string ids → `PostRef` or `None`.
- [ ] `links`, `linked`, `revisions` = `[]` (the API has no equivalent to
      cum.st's links array; caption extraction still does the real work).
- [ ] `raw_json` = exact response text, as today.

**Attachments**

- [ ] Merge `file` + `attachments`, cover first, positions `0..n-1`, dedupe by
      sha256. Skip a `file` that is also present in `attachments`.
- [ ] For each `{name, path, preview_only}`:
      - [ ] `original_filename = name`;
      - [ ] `storage_key = path`;
      - [ ] `sha256` = the 64-hex basename stem. If the path does not look like
            a hash, use a stable `sha256(path)` digest and emit a warning rather
            than dropping the attachment;
      - [ ] `mime_type` = `mimetypes.guess_type(name)`;
      - [ ] `kind` = coarse extension category (`image`, `gif`, `video`,
            `audio`, `file`); the shared classifier normalizes it in T12.7;
      - [ ] `bytes`, `width`, `height`, `duration_ms` = `None`;
      - [ ] `preview_only = bool(preview_only)`;
      - [ ] `variants = [Variant(name=name, bytes=None)]`;
      - [ ] `url = https://file.pawchive.pw/data{path}`;
      - [ ] `thumb_url = https://img.pawchive.pw/thumbnail/data{path}`;
      - [ ] `original_url` uses the same original URL, even when
            `preview_only` is true; the flag tells the UI not to pretend it is
            downloadable.
- [ ] Do not synthesize dimensions or durations from the filename.

**Creator art and page URLs**

- [ ] `creator_images`: avatar
      `https://pawchive.pw/icons/{service}/{id}`, header/banner
      `https://pawchive.pw/banners/{service}/{id}`, cache-busted with
      `?v={updated}` when available.
- [ ] Creator URL `https://pawchive.pw/{service}/user/{id}`.
- [ ] Post URL `https://pawchive.pw/{service}/user/{id}/post/{pid}`.
- [ ] `image_hosts() = {"img.pawchive.pw", "pawchive.pw"}`.

**Errors**

- [ ] A JSON 404 (`{"error": "Creator not found."}`) raises `ApiNotFound` with
      a useful message, not a generic decode error.
- [ ] A JSON 403 raises `ApiBlocked` (shared transport handles it).
- [ ] Unknown/invalid JSON raises `ApiDecode` with a snippet.

## Acceptance criteria

- [ ] Fixture-driven unit tests cover profile, list, detail, tags, attachments,
      preview-only, `file`+`attachments` dedupe and ISO timestamps.
- [ ] `parse_posts_page` returns `total is None` and exactly the fixture's posts.
- [ ] A 173-attachment post maps to 173 unique sha256 rows in the trimmed
      fixture (or 3/3 for the committed trim).
- [ ] `registry.get("pawchive").post_url(...)` and `.creator_url(...)` match the
      examples above.
- [ ] No network in tests.

## Out of scope

- Persisting rows, crawling, UI (T12.7–T12.9).
- Downloading files or ZIPs.

## Notes

- The API docs and KToolBox confirm `file.pawchive.pw` for post files, but the
  sampled preview-only file 404'd. Treat `preview_only` as authoritative.
- `has_full`, `preview_state`, `detail_fetched`, `origin` and `poll` stay in
  `raw_json` for now; none are needed by the current UI.
