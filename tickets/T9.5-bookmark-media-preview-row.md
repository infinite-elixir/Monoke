# T9.5 — Bookmark media previews are one compact row per creator

## Goal

On `/bookmarks?view=media` (no creator filter), each creator section currently
renders its preview tiles at full container width — one giant square per line —
so a single creator fills the whole viewport. Each creator must instead show a
single **one-line strip of medium/small cards, sized like gallery tiles**, with
a **View all** control at the end of that strip.

## Current behaviour / root cause

`bookmarks.html` builds the overview preview wrapper as:

```jinja
<div class="bookmark-preview{% if view != 'media' %} bookmark-post-list{% endif %}{% if view != 'posts' %} bookmark-media-grid{% endif %}">
```

In the **Media** tab this produces `class="bookmark-preview bookmark-media-grid"`,
but the only grid rule is the compound selector
`.bookmark-preview.bookmark-post-list.bookmark-media-grid` (style.css). Without
`bookmark-post-list`, no `display: grid` is applied, so every
`figure.gallery-tile` is a block and its `.gallery-thumb` stretches to the full
row. In the **All** tab the compound selector does match and tiles are gridded,
but they wrap into multiple rows of six.

The creator-filtered media view is unaffected because it uses
`.gallery-grid bookmark-media-grid`.

## Locked decisions (2026-10-23)

| Question | Decision |
|---|---|
| Scope | The unfiltered `/bookmarks` overview, **Media** tab sections. The creator-filtered grid keeps its current gallery layout. |
| Row shape | Exactly one row per creator, no wrapping. |
| Card size | Same visual language as gallery tiles: square thumbnail, ~150–170 px track, compact caption. Never full-width. |
| Overflow | The row scrolls horizontally when it does not fit; no second line. Keep native keyboard/touch scrolling and a thin scrollbar. |
| View all | Moved out of the section heading and into the row as a tile-sized link at the end, e.g. **View all 83 bookmarks**. |
| All tab | Media tiles there should use the same compact row; mixed post cards stay as they are. If that needs a larger template split, keep the All tab unchanged and scope the CSS strictly to the media tab. |
| Missing media | Keeps the same compact tile footprint; no full-width dashed box. |

## Scope

**Template (`bookmarks.html`)**

- [ ] Give the overview media preview an explicit modifier such as
      `bookmark-media-row` instead of relying on the accidental
      `.bookmark-post-list` combination. Do not reuse `.gallery-grid` here,
      because its `auto-fill` wrapping is exactly what must not happen.
- [ ] For `view == "media"`, render one wrapper per creator section containing
      all `section.preview` tiles plus a trailing tile-sized
      **View all N bookmarks** link (`section.view_all_url`).
- [ ] Remove the duplicate **View all** button from the section heading for the
      Media tab (keep the heading count). Other tabs keep the heading button.
- [ ] If the All tab is included, wrap only its media items in the row and keep
      post cards full-width; otherwise leave the All tab markup untouched.
- [ ] Preserve the existing tile macro, its overlay hooks and the no-JS post
      `href`.

**Styles (`style.css`)**

- [ ] Add a rule for the new preview row, e.g.:
      ```css
      .bookmark-media-row {
        display: grid;
        grid-auto-flow: column;
        grid-auto-columns: minmax(150px, 170px);
        gap: var(--step-3);
        margin-top: var(--step-3);
        overflow-x: auto;
        overscroll-behavior-inline: contain;
        scrollbar-width: thin;
      }
      ```
      Adjust track sizing and gaps to match `.gallery-grid` cards, but never
      `auto-fill` or `repeat(...)` that can wrap.
- [ ] Make the row's tiles width-constrained (`min-width: 0`) and keep the
      thumbnail at `aspect-ratio: 1`; captions clamp to the tile, not the row.
- [ ] Style the trailing **View all** link as a tile-sized control aligned to
      the row height (or a compact card) so it reads as the end of the strip.
- [ ] Delete or scope the now-unused compound
      `.bookmark-preview.bookmark-post-list.bookmark-media-grid` rule so it
      cannot re-wrap the overview.
- [ ] Add a narrow-screen rule that keeps the single row scrollable at
      `~140px` tracks; it must not collapse into one full-width column.
- [ ] Keep the missing-media placeholder at tile size (remove any
      container-width assumption).

**Tests**

- [ ] Template: `/bookmarks?view=media` emits one media-row wrapper per creator
      section, the row contains the `View all` link after the tiles, and the
      heading no longer renders a second `View all`.
- [ ] Template: every overview media tile is inside the row wrapper; no
      `gallery-tile` sits as a direct block child of `.bookmark-preview`.
- [ ] CSS source check: the overview media-row rule uses a single-line flow
      (`grid-auto-flow: column` or `flex-wrap: nowrap`) and contains no
      `auto-fill`/`auto-fit`; no overview rule sets the tiles to full width.
- [ ] Regression: the creator-filtered media view (`/bookmarks?view=media&creator=…`)
      still renders `.gallery-grid` and keeps its wrapping grid/pager.
- [ ] Regression: the Posts tab and the creator-filtered post list are
      unchanged.
- [ ] `uv run pytest` passes.

## Acceptance criteria

- [ ] `/bookmarks?view=media` shows every creator as one horizontal line of
      gallery-sized cards; no creator preview occupies the full page width.
- [ ] A **View all N bookmarks** control appears at the end of each line.
- [ ] Six or fewer previews fit without wrapping; more scroll horizontally and
      still stay on one line.
- [ ] Mobile keeps the single line with horizontal scrolling (no stacked
      giant tiles).
- [ ] Missing-media tiles are the same size as normal tiles.
- [ ] The creator-filtered Media view and both Post views look and behave as
      before.

## Out of scope

- Changing the number of preview items per creator (still the existing
  `BOOKMARKS_PER_CREATOR_PREVIEW`).
- Reordering the library or changing bookmark data/queries.
- The overlay/playlist behaviour (T11.3, T11.10).
- Redesigning post bookmark cards.
- Adding hover-only "View all" affordances.

## Notes

- This is a CSS regression made visible by the missing `.bookmark-post-list`
  class in the Media tab; fix the markup contract rather than adding
  `auto-fit` back.
- Prefer the gallery's existing tile dimensions (`~170px`) so bookmarks and
  gallery look like one product, per `STYLE.md`.
- If the All tab is deferred, add the class only under `view == "media"` so no
  mixed-content edge case is introduced.
