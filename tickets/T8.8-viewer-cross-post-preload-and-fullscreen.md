# T8.8 — Preload across post boundaries and add a fullscreen toggle button

## Goal

Remove the remaining stall in the fullscreen viewer when the user moves from
one post into the next/previous one, and give fullscreen an explicit control.

T8.7 warms images inside the **current** post. At a post's edge the viewer still
has to fetch `/c/{id}/viewer/data?post=…` and only then starts loading the first
(or last) image of the destination post, so `→` on the final image and `←` on
the first image show a blank stage for a noticeable moment.

This ticket makes the destination post's edge images known in advance, keeps
their preload objects across the post jump, and prefetches the neighbouring
post payload itself. It also adds a small fullscreen toggle button that appears
on interaction and then re-hides, so T8.5's "nothing at rest" acceptance still
holds.

## Current behaviour

- `db.viewer_state()` returns only the **current** post's media (T8.1) plus
  `previous_post` / `next_post` as service-id strings. It does not expose any
  media from either neighbour.
- `viewer.js` keeps one `preloadMap` (URL → retained `Image`) and one
  `preloadFailed` set, and `jump()` calls `clearPreloadCache()`, throwing away
  every warmed neighbour before the destination payload is rendered.
- `jump()` always fetches `/viewer/data` before it can know any URL in the
  destination post, even when the user is about to press `→` into the very next
  post.
- Fullscreen is keyboard-only (`F`) or an implicit attempt on the first
  key/pointer event. There is no visible or discoverable control, and no way to
  leave fullscreen other than the browser's own Escape gesture or `F`.
- `.viewer-close` is visually hidden until focused (T8.4/T8.5 pattern), which is
  the model a new control should follow.

## Scope

**Neighbour previews in the viewer payload (`db.py`)**

- [ ] Add a helper
      `neighbour_preload_images(conn, creator_id, post, direction, limit)` that
      returns up to `limit` **image** descriptors from the adjacent post:
      - `previous` → the last images of the newer post, ordered nearest-edge
        first (`position DESC`, then `id DESC`),
      - `next` → the first images of the older post, ordered nearest-edge first
        (`position ASC`, then `id ASC`).
      - Only `files.kind = 'image'`; skip `video`, `gif`, `audio` and rows with
        no `url` or a `data:` URL. Use the existing `VIEWER_KINDS` ordering
        rules so the payload agrees with `viewer_media()`.
      - Each descriptor contains at least `post_service_id`, `sha256`, `url`,
        `thumb_url`, `width`, `height`, `original_filename`.
- [ ] Add a `NEIGHBOUR_PRELOAD_LIMIT` constant (suggest 6) in `db.py` and include
      the result in `viewer_state()`:
      ```json
      "neighbour_images": {
        "previous": [ { "post_service_id": "...", "url": "...", "sha256": "..." } ],
        "next":     [ ... ]
      }
      ```
      Empty lists (not `null`) when a neighbour does not exist.
- [ ] Keep `previous_post` / `next_post` as strings: T8.6/T8.7 and `viewer.js`
      already rely on that shape. This is a purely additive field.
- [ ] Do not add extra queries per media item: compute both neighbour previews
      with at most two small indexed queries, and return `[]` immediately when
      there is no neighbour.
- [ ] The `/c/{creator_id}/viewer/data` endpoint automatically carries the new
      field because it returns `viewer_state()` unchanged.

**Cross-post preload and payload cache (`viewer.js`)**

- [ ] Keep T8.7's constraints exactly: only `kind === "image"`, real URLs,
      `navigator.connection.saveData` / `slow-2g` / `2g` /
      `prefers-reduced-data`, hidden tab, reduced motion, no DOM nodes, never
      delay or replace the current media element.
- [ ] Seed a separate `neighbourPreloadMap` (or one bounded map with a
      per-entry `source` marker) from `state.neighbour_images` after every
      payload render. Warm the nearest-edge image first, then the rest of each
      list, within an idle callback.
- [ ] On `jump()` **do not** call the old whole-cache reset. Replace it with a
      prune that keeps URLs belonging to the destination post's window and its
      two neighbour lists, and drops everything else. The failed-URL set may be
      pruned the same way. Keep a hard total bound (for example
      `PRELOAD_MAX * 2` including neighbour seeds) and never grow without one.
- [ ] Add a small payload cache (`Map`, max 4 entries, keyed by service id). On
      `jump(serviceId)`:
      - if the target payload is cached, render it immediately (same token and
        abort checks), update the cache, and do not wait for a network round
        trip;
      - otherwise fetch as today, then store the payload.
      - A cached payload's `bookmarked` flags must be updated when the viewer
        toggles a bookmark for that post/media (T9.2), or the cache entry must
        be invalidated. Do not show stale bookmark state after a jump.
- [ ] Leave a background revalidation of a cached payload optional, but if one
      is added it must not replace the on-screen element, reset playback or
      move the index unless the media list actually changed. State the choice in
      the Resolution.
- [ ] Keep `preloadFailed` bounded and prune it with the same rules; a failed
      neighbour seed must never block the real load after the jump.
- [ ] At the edge (`next-image` on the last item, `prev-image` on the first),
      the destination's edge image should already be in the HTTP cache/decoded
      images before the keypress whenever the browser has had idle time.
- [ ] Do not change arrow, wheel, touch or `Up`/`Down` semantics from T8.3/
      T8.6; this ticket only changes *when* bytes start loading and *where* the
      payload comes from.

**Fullscreen toggle button (`viewer.html`, `viewer.js`, `style.css`)**

- [ ] Add one `<button type="button" class="viewer-fullscreen"
      data-viewer-fullscreen aria-pressed="false"
      aria-label="Enter fullscreen">Fullscreen</button>` after the close button
      in the viewer root. The close button must remain the first focusable
      element (T8.4 test).
- [ ] Clicking it calls the existing `toggleFullscreen()` path:
      `requestFullscreen({ navigationUI: "hide" })` when not fullscreen,
      `document.exitFullscreen()` when fullscreen. Keep the existing `F`
      shortcut and the first-interaction auto-attempt; the button is an
      additional discoverable path, not a replacement.
- [ ] Update the control on `fullscreenchange`: visible label
      `Fullscreen` / `Exit fullscreen`, matching `aria-label`, and
      `aria-pressed="true"` while `document.fullscreenElement` is set. The
      label text and pressed state must agree; do not rely on colour or an icon
      alone.
- [ ] A rejected request (unsupported browser, iframe policy, denied gesture)
      must leave the label in the previous state and show the existing
      non-blocking `.viewer-flash` ("Fullscreen is not available in this
      browser."); never throw unhandled.
- [ ] **Chrome-free at rest:** the control is invisible
      (`opacity: 0; pointer-events: none`) until the same interaction that
      dismisses the hint (pointer move, touch start, keydown, focus), then
      revealed for ~2.5 s and hidden again. It must still be keyboard
      reachable while invisible: `:focus-visible` forces it visible, like
      `.viewer-close`. Under `prefers-reduced-motion: reduce` reveal/hide
      instantly instead of fading.
- [ ] Place it top-right, leaving the top-left to `.viewer-close`, the bottom
      to the toast/flash and the centre to the media; it must not overlap the
      native video control bar, the play glyph, the counter or the four
      `viewer-zone` buttons. Raise its z-index above the zones and keep it
      clickable (`pointer-events: auto` while revealed).
- [ ] The button survives in-post moves and `jump()` without being recreated;
      focus is not stolen when it auto-hides while another element is focused.
- [ ] T8.5 acceptance still wins: on first paint and after the idle timeout, the
      viewer shows only media, counter and (first run) the hint. The control is
      revealed only by interaction.

## Acceptance criteria

- [ ] A post edge no longer waits for both the neighbour payload **and** the
      first image; at most the payload remains on the critical path, and usually
      neither does.
- [ ] Neighbour previews are small, bounded, image-only, and skipped under
      data-saving conditions exactly like T8.7's in-post window.
- [ ] The preload cache survives a post jump instead of being cleared wholesale,
      with a documented hard bound and prune rule.
- [ ] The fullscreen control enters and exits fullscreen, reflects the real
      state, works by pointer and keyboard, and fails non-blockingly.
- [ ] With no interaction, the viewer still shows only media + counter (+
      first-run hint), so T8.5 remains satisfied.
- [ ] No regression in in-post preloading, T8.6 crossing, T9.2 bookmark
      shortcuts, or media playback.

## Out of scope

- Preloading video/GIF/audio bytes.
- Server-side image transcoding, responsive sizes, HTTP/2 push or a service
  worker.
- Changing the `/viewer/data` route shape beyond the additive
  `neighbour_images` field.
- Persistent viewer toolbars, captions or a redesigned control bar.
- Autoplay, fullscreen auto-entry on page load, or changes to the first-run
  hint's grid.

## Notes

- `viewer_media()` is post-scoped on purpose (T8.1): the same sha on two posts
  stays reachable from both. Neighbour previews must not dedupe across posts;
  they only carry URLs.
- The nearest-edge ordering matters: for `previous` the destination item is the
  **last** viewer item, for `next` the **first**. Warm that one before the rest
  of the preview list.
- Keep the payload additive. `previous_post` / `next_post` are strings used by
  `jump()`; do not turn them into objects.
- T8.7's `preloadWindowIndices` and its Node test are the pattern to follow:
  small pure helpers, `BEGIN/END` markers, no DOM dependency in the test.
- The fullscreen control is the one deliberate exception to "no chrome"; it is
  revealed only by interaction, matching `.viewer-close`, so the at-rest
  acceptance tests can keep asserting no visible control.
- The viewer stays dependency-free ES5-ish; use `fetch().then()`, not async
  syntax that the rest of the file avoids.

## Resolution

`viewer_state()` now carries `neighbour_images.previous` and
`neighbour_images.next`. `NEIGHBOUR_PRELOAD_LIMIT = 6`;
`neighbour_preload_images()` resolves the adjacent post through
`viewer_neighbour()` and returns still images only, nearest edge first
(`position DESC` for the newer neighbour, `position ASC` for the older one).
Videos, GIFs, audio, empty URLs and `data:` URLs are filtered in SQL. Both
lists are `[]` at the ends of the archive, and the current-post profile is
assembled from two bounded preview queries rather than one per item.

`viewer.js` keeps a pure `BEGIN/END preload-plan` helper block:
`preloadCandidates()` merges the T8.7 window with both neighbour lists,
`buildPreloadPlan()` applies the failed-URL filter and the
`PRELOAD_TOTAL_MAX = PRELOAD_MAX * 2` cap, and `prunePreloadMap()` /
`pruneFailedSet()` remove stale entries. Neighbour lists are interleaved so
the 12-image bound always includes both crossing edges. A post jump no longer
calls `clearPreloadCache()`; the destination's warm `Image` object survives
and is kept by the new plan.

The same idle scheduler warms a four-entry payload cache keyed by service id.
On `jump()`, a cached payload is rendered synchronously through
`applyPayload()`; otherwise the existing fetch path stores the response.
There is no background revalidation: the viewer treats the page-load snapshot
as authoritative for its lifetime. Bookmark toggles update every cached copy
and bump `payloadEpoch`, so an in-flight prefetch that started before the
toggle is discarded. Payload and neighbour prefetches use the T8.7
`preloadAllowed()` gate (save-data, slow connections, reduced-data, hidden
tab) and stay idle until the visible media is ready.

The fullscreen control is one `data-viewer-fullscreen` button after the close
button. It is transparent and non-interactive at rest, revealed for 2.5 s by
pointer move/down, touch, wheel or keydown, and forced visible by
`:focus-visible` even while hidden. `fullscreenchange` updates the visible
label and `aria-pressed`; explicit failures show the existing flash without
leaving the overlay. The first-interaction auto-request and `F` shortcut are
unchanged, and pointer/touch down on the button is excluded from the auto
request so it cannot enter and immediately exit fullscreen.

Tests cover edge ordering, kind/URL filtering, caps, end-of-archive empty
lists, the JSON endpoint, the Node-evaluated preload plan/prune helpers,
cached-jump preference, markup/focus order, script hooks and the transient
CSS. `viewer.js` passes `node --check`; the full suite passes
(`366 passed, 1 skipped`). The Chromium/Firefox throttled-network and
keyboard acceptance matrix remains a manual browser pass: this environment
only has a Firefox binary without an automation/display harness.
