# T9.2 — Bookmark controls on posts, attachments, gallery tiles and the viewer

## Goal

Put a bookmark control where the user already is: on creator-page post cards,
the post page, gallery tiles, and inside the fullscreen viewer. Every control
posts to T9.1's toggle endpoints and works without JavaScript.

The viewer must stay chrome-free at rest (T8.5), so its bookmark commands are
keyboard shortcuts with transient feedback rather than a persistent button.

## Current behaviour

- No bookmark UI exists.
- Creator-page rows render in `partials/post_row.html` inside `.post-main`;
  the post page header has a `.post-actions` row; post attachments render as
  `.attachment-row` with `.attachment-actions`.
- Gallery tiles are `<figure class="gallery-tile">` containing an `<a
  class="gallery-thumb">` plus a `<figcaption>`. A bookmark button must be a
  sibling of the anchor, not a child, so the HTML stays valid.
- The viewer (`viewer.html` + `viewer.js`) renders only media, the counter and
  the first-run hint. `viewer.js` already has `onKeydown`, an `aria-live`
  announcer, a non-blocking flash and the T9.1 JSON endpoints will be available.

## Scope

**Server-rendered button state**

- [ ] `_creator_context` decorates visible post rows with `is_bookmarked` using
      T9.1's batch helper (one query per page, no N+1).
- [ ] The post page passes `is_bookmarked` for the post and per-file bookmark
      state for each attachment (batch by sha).
- [ ] `_gallery_context` / `_decorate_gallery_image` adds `is_bookmarked` per
      tile from the batch helper.
- [ ] The viewer data payload marks the current post and each media item with
      `bookmarked` so `viewer.js` starts in the right state after every jump.

**Controls**

- [ ] Reusable Jinja include/macro `partials/bookmark_button.html` renders a
      `<form method="post" action="…">` with:
      - a `<button type="submit">` whose visible label is **Bookmark** or
        **Bookmarked** (not an unlabelled icon);
      - `aria-pressed="true|false"` matching the state;
      - a hidden `next` field containing the current path **and query string**
        (filters, page, sort, viewer `?post=&i=`) so the redirect returns to the
        exact view;
      - an accessible name that names the target, e.g.
        `aria-label="Bookmark post: <title>"` /
        `aria-label="Bookmark image: <filename>"`.
- [ ] Post cards (`partials/post_row.html`): compact button in the card, does
      not become the card's primary action or steal focus from the title link.
- [ ] Post page (`post.html`): toggle in `.post-actions`.
- [ ] Attachment rows (`post.html`): per-file media toggle in
      `.attachment-actions` for `image`, `gif` and `video` (audio is optional;
      keep it consistent with the gallery if skipped).
- [ ] Gallery tiles (`gallery.html`): media toggle positioned over the tile as a
      **sibling** of `.gallery-thumb`, keyboard reachable, with a filled state
      for bookmarked items.
- [ ] Buttons work with JavaScript disabled: plain POST → 303 → the page
      re-renders with the new state.
- [ ] Optional progressive enhancement: intercept submit, POST with
      `Accept: application/json`, and swap the button text/`aria-pressed`
      without reload. If this is skipped, say so in the Resolution; the form
      path is the contract.

**Viewer shortcuts (no persistent chrome)**

- [ ] `b` toggles the bookmark for the **current media item**.
- [ ] `Shift+B` (event key `B`) toggles the bookmark for the **current post**.
- [ ] Ignore these shortcuts when `Ctrl`/`Alt`/`Meta` are held and when focus is
      in a form control or on the native video UI, matching the existing guard.
- [ ] Toggling POSTs to the T9.1 endpoint with the viewer's current
      `?post=&i=` preserved; do not navigate, reload or unload the media.
- [ ] Feedback is transient: update the `aria-live` announcer ("Image
      bookmarked" / "Bookmark removed"), and show a neutral toast that fades
      after ~1.5 s. No button, icon or badge is present at rest (T8.5).
- [ ] A failed toggle leaves the previous state and shows the existing
      non-blocking flash.
- [ ] The first-run hint note may mention `B`/`Shift+B`; do not enlarge the hint
      grid or add a toolbar.
- [ ] The post/media state stays correct across in-post moves and post jumps.

**Styles**

- [ ] `.bookmark-button` and `.is-bookmarked` states: visible at rest on cards,
      post page and gallery; focus-visible ring reuses the app's button styles.
- [ ] Filled/active state must not rely on colour alone (text changes to
      "Bookmarked" and `aria-pressed` flips).
- [ ] The gallery overlay control must not sit on top of the tile's play glyph,
      duration badge or the lightbox click area used by T4.7.

**Tests**

- [ ] Creator page: bookmarked post renders `aria-pressed="true"` and
      "Bookmarked"; unbookmarked renders "Bookmark".
- [ ] Post page: post toggle and one per attachment; hidden `next` preserves
      filters/query string.
- [ ] Gallery: one toggle per tile, no `<button>` nested inside `<a>`, selected
      state matches the DB.
- [ ] POST from each surface toggles the DB and redirects back to the same URL.
- [ ] Viewer payload includes `bookmarked` for the post and each media item.
- [ ] Viewer JSON toggle endpoint changes state; a second call reverts it.
- [ ] `node --check src/monoke/web/static/viewer.js` passes.
- [ ] Browser acceptance in Chromium and Firefox:
      - `b` on an image marks it, shows the toast/announcement, and leaves the
        media index and video playback untouched;
      - `Shift+B` marks the post;
      - reloading the viewer and the gallery shows the preserved state;
      - with JS disabled, the form buttons still toggle and return to the same
        filtered page;
      - at rest the viewer still shows only media + counter (+ hint on first
        run), with no bookmark chrome.

## Acceptance criteria

- [ ] A user can bookmark/unbookmark a post from the creator page and the post
      page without JavaScript.
- [ ] A user can bookmark/unbookmark a specific image or video from the post
      page, a gallery tile, and inside the viewer.
- [ ] Every toggle returns the user to the exact same view (filters, page, sort,
      viewer index).
- [ ] Button state is server-rendered and accessible (`aria-pressed`, text, and
      a target-specific accessible name).
- [ ] The viewer remains visually chrome-free at rest and shows only transient
      feedback after a bookmark action.
- [ ] No N+1 bookmark queries on any list page.

## Out of scope

- The `/bookmarks` library page and nav entry (T9.3).
- Schema, repository and endpoint changes (T9.1).
- Bookmarking creators or links.
- Collections/folders, notes, drag-to-order, sharing.
- Toast/undo systems beyond the single transient viewer message.

## Notes

- Keep the hidden `next` value derived from the request URL on the server, not
  from `Referer`, and rely on T9.1's local-only redirect validation.
- The gallery tile anchor already wraps the thumbnail; adding a `<button>`
  inside it would be invalid HTML and break keyboard/lightbox behaviour.
- `viewer.js` is dependency-free ES5-ish; write the fetch toggle with
  `XMLHttpRequest`-free `fetch` + `.then`, matching `jump()`.
- Do not reserve a visible on-screen bookmark button in the viewer: T8.5's
  acceptance ("nothing else is visually present") still applies.

## Resolution

`partials/bookmark_button.html` exports one macro used by the post row, the
post page header, attachment rows and gallery tiles. It renders a plain
`<form method="post">` with a visible "Bookmark"/"Bookmarked" button,
`aria-pressed`, a target-specific `aria-label` and a server-derived hidden
`next` (current path + query string). All buttons also carry
`data-bookmark-form` so `app.js` can progressively enhance the submit with a
JSON POST and swap the label without a reload; with JavaScript off the form
path is unchanged.

Server state is batch-loaded: `_creator_context` uses `bookmarked_post_ids`,
the post page uses `bookmarked_media_shas` once per page plus
`post_is_bookmarked`, `_gallery_context` batches tile shas, and
`db.viewer_state` marks `post.bookmarked` and every media item's `bookmarked`
so `viewer.js` starts and jumps in the right state.

Surfaces: compact toggle on `.post-row`; post toggle in `.post-actions`;
per-attachment toggle for `image`, `gif` and `video` (audio deliberately
skipped, matching the gallery); gallery toggle is a sibling of
`.gallery-thumb`, absolutely positioned top-right so it never covers the play
glyph, duration badge or lightbox click target.

Viewer: `b` toggles the current media and `Shift+B` (key `B`) the post, through
the same JSON endpoint with the current `?post&i` sent as `next`. It never
navigates. Feedback is the existing `aria-live` announcer plus a
`[data-viewer-toast]` element that is `hidden`, `aria-hidden` and removed from
the flow at rest; it fades after 1.5 s. A failed request leaves the previous
state and uses `viewer-flash`. The first-run hint text was left unchanged
(optional in the ticket) to keep the existing grid and its regression test
intact.

Tests in `tests/test_bookmark_ui.py` cover creator/post/gallery markup and
state, post-page `next` preservation, valid HTML in gallery tiles, form POSTs
from each surface, viewer payload flags and JSON round-trips. Chromium/Firefox
manual acceptance (toast, playback untouched, JS-disabled form path) remains a
browser pass; no browser automation is wired into the repo.
