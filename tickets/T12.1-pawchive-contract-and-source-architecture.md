# T12.1 — Pawchive API contract spike and source-adapter architecture

## Goal

Pin down what pawchive.pw actually returns, capture fixtures, and lock the
architecture that adds it without forking the crawler or sprinkling
`if source == ...` through the app.

## Why

Monoke currently assumes cum.st in three separate layers: URL parsing, API
payloads, and media URL construction. Pawchive is Kemono-shaped, so its URLs,
payloads and CDN hosts are all different. Adding it as a special case inside
`cumst/` would make the next source worse. This ticket decides the seam first.

## Verified facts (probed 2026-10-23)

**Web + API**

| Thing | Value |
|---|---|
| Site | `https://pawchive.pw` |
| API base | `https://pawchive.pw/api/v1` |
| Creator URL | `https://pawchive.pw/{service}/user/{creator_id}` |
| Post URL | `https://pawchive.pw/{service}/user/{creator_id}/post/{post_id}` |
| Profile | `GET /{service}/user/{id}/profile` |
| Posts | `GET /{service}/user/{id}/posts?o={offset}` |
| Post detail | `GET /{service}/user/{id}/post/{post_id}` |
| Creator search | `GET /creators?q={text}` (array) |
| Error body | JSON, e.g. `{"error":"Creator not found."}` |

**Payload shape**

- Profile: `id, name, service, indexed, updated, public_id, relation_id,
  ever_imported`. Dates are ISO-8601 without a timezone.
- Posts list: a **bare JSON array**, 50 items per page, no `total` field.
  `o` is the only pagination parameter observed. `q` is supported by the API
  (gallery-dl reports tag filtering is not).
- Post summary/detail: `id, user, service, title, content, embed, shared_file,
  added, published, edited, file, attachments, tags, origin, preview_state,
  has_full, detail_fetched`; detail adds `poll, captions, next, prev`.
- `content` is HTML (the caption). There is no separate `captionHtml`.
- `tags` is a **brace-delimited string**, e.g. `"{Benefits,NSFW,SSSS.GRIDMAN}"`,
  not an array.
- `file` is the cover attachment; `attachments` is the rest. Both use
  `{name, path, preview_only}`.
- `path` looks like `/bd/c6/bdc6ff…f47.jpg`; the 64-hex basename stem is the
  sha256, and the first two path segments match its first four characters.
- `preview_only: true` is common. The full file at
  `https://file.pawchive.pw/data{path}` returned **404** for a sampled
  preview-only attachment; `https://img.pawchive.pw/thumbnail/data{path}`
  returned 200. The post page offered a generated ZIP on `n2.pawchive.pw`
  instead.
- Creator art: `https://pawchive.pw/icons/{service}/{id}` (200) and
  `https://pawchive.pw/banners/{service}/{id}`.
- No width, height, byte size, duration or mime type is supplied. These fields
  must degrade to `NULL` in the UI.
- A handful of rapid probes eventually produced `403` behind DDOS-Guard.
  Crawls must pace conservatively and treat a JSON 403 as blocked too.

## Scope

- [ ] Write `docs/SOURCES.md` with:
      - [ ] the source table above and links to the captured fixtures;
      - [ ] the canonical internal model contract;
      - [ ] the adapter boundary (what a source owns vs. what the shared
            transport/crawler owns);
      - [ ] known pawchive limitations (preview-only files, no dimensions,
            no total, tag string, rate limiting).
- [ ] Capture small, legal-to-store fixtures under `tests/fixtures/pawchive/`:
      - [ ] `profile_30500811.json`
      - [ ] `posts_30500811_o0.json` (trim to 3 posts, keep the shape)
      - [ ] `posts_empty.json`
      - [ ] `post_173104724.json` (trim to 3 attachments, keep the shape)
      - [ ] `error_404.json`
      - [ ] `error_403.json` if a JSON 403 body can be captured
- [ ] Record the capture URL and date in a short `tests/fixtures/pawchive/README.md`.
- [ ] Lock the adapter seam:
      - [ ] `SourceRef(source, service, creator_id, post_id)` is the only type
            the crawler/web layer passes around.
      - [ ] One adapter per source owns URL parsing/building, API paths, payload
            normalisation, creator art, file/thumb URLs and caption image hosts.
      - [ ] One shared HTTP transport owns cache, retry, pacing, cooldowns and
            error classes; it knows nothing about payload shape.
      - [ ] One canonical set of pydantic models (`CreatorProfile`,
            `PostsPage`, `PostDetail`, `Attachment`) is the boundary.
      - [ ] No source-specific conditionals in `crawler/`, `extract/`, `web/`
            or `db/`.
- [ ] List the schema changes the adapter needs (detailed in T12.3):
      - [ ] `creators.source` + uniqueness on `(source, service, service_id)`.
      - [ ] `posts.upstream_edited_at` for incremental sync.
      - [ ] `files.preview_only`.

## Acceptance criteria

- [ ] `docs/SOURCES.md` exists and contains no guesses: every row is backed by
      a fixture or a captured response.
- [ ] Every fixture parses with `python -m json.tool`.
- [ ] The field-mapping tables in T12.6 and the schema changes in T12.3 match
      the fixtures.
- [ ] The protocol in T12.2 compiles as a written contract and covers every
      source-specific decision found during the spike.
- [ ] No production code is changed by this ticket.

## Out of scope

- Implementing the adapter, migrations, crawler or UI.

## Notes

- Sources are not interchangeable in product terms: cum.st is a full-metadata
  API; pawchive often exposes only thumbnails. The UI must be honest about that
  rather than pretending a preview-only file is loadable.
- If the API turns out to change shape during implementation, update the
  fixture and `docs/SOURCES.md` first, then the adapter.
