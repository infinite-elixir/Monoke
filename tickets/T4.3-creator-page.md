# T4.3 — Creator page with facets and search

## Goal
Every post, filterable in one screen, with the links summarised per card.

## Scope

- [x] `GET /c/{creator_id}`:
      - post list (rows, not a masonry grid — scannability first), 50/page.
      - each row: date, title, badges (`Drive ×2`, `MEGA ×1`, `MP4 ×3`, `file unavailable`),
        link count, tag chips, thumbnail (blurred by default per toggle).
      - paginator (prev/next + page numbers for ≤ 10 pages).
- [x] Filters (all in the query string, all composable):
      `q` (title + content_text + URL, case-insensitive), `category`, `tag`, `dead`,
      `has_links`, `from`, `to`, `sort=published_desc|published_asc|title`.
- [x] `GET /c/{creator_id}/rows` — htmx partial returning just the list + paginator; used by
      filter changes without a full reload.
- [x] Facet sidebar: category counts, top 20 tags with counts, dead count.
- [x] Summary header: posts, links, Drive/MEGA/direct-media totals, last sync, "Sync" button.
- [x] Empty state distinguishes "no posts yet" from "no matches for these filters" (with
      a clear-filters link).

## Acceptance criteria

- [x] 782 posts paginate at 50/page = 16 pages, stable order, no duplicates across pages.
- [x] `?category=mega&dead=0&q=pin` returns only matching rows and the count matches a direct
      SQL query.
- [x] Filter changes update the list without a full page reload; the URL updates and is
      bookmarkable/reloadable.
- [x] `?category=shortener` shows unresolved short links (nothing is hidden).
- [x] Page renders in < 300 ms on 782 posts locally.
- [x] Every category is reachable from the facet sidebar, including `other`.

## Notes
- Facet counts respect the other active filters except their own dimension (standard faceted
  search behavior).
- Keep the SQL in the repository layer (`list_posts`) — no query building in templates.
