# T7.3 — Surface media types on the creator page and post cards

## Goal

A creator page must answer "does this profile have videos?" without opening a
post. Show image/video/gif counts in the header, show kind badges on each post
card, and let the user filter the post list to posts containing a given media
kind.

## Why

On creator 2 the header currently reads `Files 19139` and `Direct media 0`.
"Direct media" is a *caption-link* category, not an attachment count, so a
creator with 756 video files looks like it has no video. Post cards show only
`N files`, and the card badges are link categories only (`_POST_PRIORITY`), so
image and video posts are indistinguishable. There is also no `?media=video`
filter, even though `_post_where` already supports `has_attachments`.

## Scope

**Repository (`db.py`)**

- [ ] Extend `creator_summary()` with attachment counts:
      `images`, `videos`, `gifs`, `audio`, `other_files`, plus existing link
      counts. Count distinct `files.sha256` per creator, or document why file
      rows are the right unit.
- [ ] Add `file_kind_counts` to `post_cards()` in the same batched query style
      (no N+1): one grouped query `SELECT post_id, kind, count(*) ... GROUP BY`.
- [ ] Add `media_kind: str | None` to `_post_where()`:
      `EXISTS (SELECT 1 FROM files f WHERE f.post_id = p.id AND f.kind = ?)`.
      Use the normalized kind from T7.1 and rely on `files_kind`.
- [ ] Add `media` to `_FILTER_NAMES` so facet counts compose with it.
- [ ] `list_posts(..., media_kind=...)` passes it through; keep sorting and
      pagination unchanged.

**Filters (`web/filters.py`)**

- [ ] `PostFilters.media` parsed from `?media=image|video|gif|audio`, invalid
      values → `None` (any). Include it in `db_kwargs()`, `facet_kwargs()`,
      `active`, `pairs()`, and `_FILTER_FIELDS` (changing it resets to page 1).
- [ ] Add a `MEDIA_LABELS` map for display (`Images`, `Videos`, `GIFs`,
      `Audio`).

**Creator page (`creator.html`, `partials/facets.html`,
`partials/post_row.html`, `style.css`)**

- [ ] Stat strip: keep `Posts`, `Links`, `Files`; add `Images`, `Videos`,
      `GIFs` (omit zero-valued media stats or render `0` consistently). Rename
      `Direct media` to `Direct links` (or `Direct media links`) so it cannot be
      confused with file attachments. Drive/MEGA stay link counts.
- [ ] Each media stat links to `?media=<kind>` (e.g. Videos → `?media=video`)
      so the page has a discoverable video view even without the gallery.
- [ ] Add a `Media` select to the filter form: Any / Images / Videos / GIFs /
      Audio. It composes with search, category, tag, availability, links and
      dates, and is copied into htmx URLs by the existing query-string helper.
- [ ] Post card: alongside the link-category badges, render attachment badges
      from `file_kind_counts`, e.g. `Image × 12`, `Video × 3`. Use compact
      labels and hide zero counts.
- [ ] Do not show a media badge for posts with no attachments.
- [ ] Keep the card fast: one additional grouped query for up to 50 posts, no
      per-post query.

**Dashboard (`index.html` / `list_creators`) — optional but preferred**

- [ ] If cheap, show `N videos` on the creator card using the same aggregate;
      otherwise leave the dashboard unchanged and note it.

**Tests**

- [ ] Seed image-only, video-only, mixed and attachment-free posts; assert
      `creator_summary` returns the right images/videos/gifs counts.
- [ ] Assert `list_posts(media_kind='video')` returns only posts with a video,
      and composes with `tag`/date/has_links.
- [ ] Creator page renders `Videos` with the correct number and links to
      `?media=video`.
- [ ] Post cards render `Video × N` only for video posts.
- [ ] `?media=video` pagination preserves the filter.
- [ ] Existing creator-page and htmx facet tests stay green.

## Acceptance criteria

- [ ] On creator 2 the header reports `756` videos, `18380` images (or distinct
      `sha256` counts if deduped) and `3` gifs, or clearly labels the unit.
- [ ] `GET /c/2?media=video` returns 264 posts (the number with at least one
      video) and no image-only posts.
- [ ] A post with five videos shows `Video × 5` on its card.
- [ ] `Direct media` no longer reads `0` next to 756 video files without a
      label making clear it counts links.
- [ ] No N+1 queries: rendering 50 cards issues a constant number of DB
      statements.
- [ ] All creator-page tests pass.

## Out of scope

- The gallery grid itself (T7.2).
- Post-page attachment rendering (T7.4).
- Changing link categories or the link explorer.
- Deriving tags from captions (T7.5).

## Notes

- `has_attachments` already exists in `_post_where` but is not exposed in the
  UI. The `media` filter is the better primitive; leave `has_attachments` for
  internal callers unless a generic "Has attachments" option is also wanted.
- Keep the stat strip from wrapping badly on mobile; six to eight small stats
  are acceptable, a wide table is not.
