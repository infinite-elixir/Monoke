# T4.2 — Dashboard and add-creator flow

## Goal
The only page the user needs to start: paste a URL, watch the archive appear.

## Scope

- [x] `GET /`: form with a single URL input + "Archive" button; below it, creator cards.
- [x] `POST /creators`:
      1. parse with T1.1, inline error on failure (never a 400 page),
      2. upsert creator (display name, avatar and counts filled after the first sync),
      3. create a run and start the crawl as an `asyncio.Task`,
      4. redirect `303` to `/c/{creator_id}`.
- [x] Duplicate creator → redirect to the existing page, do not create a second row.
- [x] Creator card: name, service, `post_count`, `last_synced_at` (relative: "2 h ago"),
      counts (posts / links / files / drive+mega+media), thumbnail from the newest post,
      buttons: Open · Sync.
- [x] `DELETE /c/{creator_id}` (POST + confirm) removes creator and cascade, with a confirm
      dialog.
- [x] Empty state: "Paste a Kemono creator URL to start."

## Acceptance criteria

- [x] Pasting `https://cum.st/creators/patreon/274608` creates one creator and lands on its page.
- [x] Pasting it again does not duplicate; it redirects to the existing creator.
- [x] Invalid input (`https://example.com/foo`, `patreon/user/abc`) shows the parser's message
      under the field and keeps the typed value.
- [x] Cards render in ≤ 200 ms with 20 creators and no network fetches.
- [x] Deleting a creator removes its posts/links/files (verify via `monoke db stats`).

## Notes
- The crawl must not block the request: start it in a task, redirect immediately, let T4.6
  show progress.
- Relative time formatting is a small JS or Jinja filter — pick one, keep it in one place.
