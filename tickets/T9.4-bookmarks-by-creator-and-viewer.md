# T9.4 — Group bookmarks by creator

## Goal

Make `/bookmarks` read like a library of creators rather than one flat archive
dump: every creator gets a section with a **short preview of their bookmarks**
(6 items), plus a clear "view all" link for that creator.

Media bookmarks stay ordinary links to their underlying post. This ticket does
**not** add a bookmark-only viewer; the target fullscreen viewer is
post-scoped and is left untouched.

## Current behaviour

- T9.3 renders one flat **Posts** section and one flat **Media** section for
  every creator, capped by `PER_PAGE` / `GALLERY_PER_PAGE`, with a creator
  filter `<select>`.
- Media bookmark tiles are plain links to the remote file
  (`target="_blank"`).
- `media_bookmarks` is keyed by `(creator_id, sha256)` and carries
  `created_at`; `list_media_bookmarks()` already returns the fields the tiles
  need, plus `missing` when the attachment disappeared upstream.

## Decisions

- **6** is the preview cap: `BOOKMARKS_PER_CREATOR_PREVIEW = 6` in
  `web/filters.py`.
- The cap applies only to the **unfiltered overview** (`/bookmarks` with no
  `creator`). Selecting a creator removes the cap and shows that creator's full
  paginated list using the existing tabs and pagers.
- `view=all` previews mix post and media bookmarks, newest bookmark first.
  `view=posts` previews only post bookmarks; `view=media` previews only media
  bookmarks. A creator section only appears if it has an item in the active
  view.
- Media bookmark tiles link to `/c/{creator_id}/p/{service_id}`, not to
  `/bookmarks/viewer`.

## Scope

**Repository and grouping (`db.py`, `web/filters.py`)**

- [x] Add `BOOKMARKS_PER_CREATOR_PREVIEW = 6`; do not change `PER_PAGE` or
      `GALLERY_PER_PAGE`.
- [x] Add a repository function for the overview: given
      `view=all|posts|media`, return the creators that have qualifying
      bookmarks, their total count for that view, and at most 6 preview items
      per creator. A single windowed query (or at most two queries for posts
      and media merged in Python) is acceptable; **no query per creator**.
- [x] Preview items expose the same shapes the existing post cards and media
      tiles consume, plus a stable `bookmark_id` and `kind` (`post` or
      `media`). Media previews reuse `_decorate_library_media()`.
- [x] Creator sections are ordered by their newest qualifying bookmark
      (`created_at DESC, id DESC`), then creator name, then creator id. This
      deliberately differs from the alphabetical filter list.
- [x] Keep `bookmark_creator_facets()` for the filter dropdown.

**Overview page (`/bookmarks`)**

- [x] With no `creator` filter, replace the flat Posts/Media sections with
      **creator sections**:
      - header: creator name (linked to `/c/<id>`), per-view count, and a
        "View all N bookmarks" link;
      - body: up to 6 bookmark items for the active view, newest bookmark
        first;
      - `view=all` mixes post cards and media tiles; `view=posts` shows post
        cards; `view=media` shows media tiles.
- [x] The "View all" link preserves the active tab and targets
      `/bookmarks?view=<view>&creator=<id>` (`view=all` may omit the view
      parameter). It must land on the creator's full, paginated list, not
      another 6-item preview.
- [x] With a `creator` filter, keep T9.3's full **Posts** and **Media**
      sections and their independent pagers. The preview cap is lifted.
- [x] Keep the `view` tabs, creator filter, counts, empty states and removal
      forms. Removing a bookmark re-renders the same view/filter/page.
- [x] A creator whose 6 previews include a missing media bookmark still shows
      the existing "No longer attached" placeholder.
- [x] Mobile: one creator section per row; previews scroll or wrap without
      horizontal page overflow.

**Media bookmarks link to their post**

- [x] A media bookmark tile links to `/c/{creator_id}/p/{service_id}` in every
      tab, with the post title linked the same way.
- [x] No `/bookmarks/viewer` route, `bookmark_viewer_state()` payload,
      `viewer_url` field or viewer mode is added.

**Tests**

- [x] Unfiltered overview with three creators renders one section per creator,
      ordered newest bookmark first.
- [x] Every section shows at most 6 items; a creator with 7 shows 6 plus a
      "View all 7" link.
- [x] `view=all` previews mix post and media bookmarks; `view=posts` and
      `view=media` preview only their own kind.
- [x] Following "View all" lands on that creator's full list, keeps the tab,
      removes the cap and pages correctly.
- [x] A creator with no bookmarks in the active view gets no section.
- [x] Missing media previews render the placeholder and remain removable.
- [x] The overview uses a bounded number of queries (assert with the existing
      query-count helper/pattern; no per-creator queries).
- [x] Media tiles link to their post; no bookmark-viewer URL is rendered.
- [x] Existing bookmark, gallery and creator-viewer tests stay green.

## Acceptance criteria

- [x] `/bookmarks` is a per-creator overview with at most 6 bookmarks per
      creator and a working "view all" link for each creator.
- [x] The tabs still narrow all three views, and the creator filter shows the
      full list rather than a capped preview.
- [x] Media bookmark tiles open their underlying post.
- [x] The page still works without JavaScript (removal, tabs, filter, section
      links).

## Out of scope

- New bookmark tables or toggle endpoints (T9.1), and adding bookmarks from
  the library.
- A bookmark-only viewer, a `/bookmarks/viewer` route, or any viewer mode
  changes (excluded by T10.1).
- Search inside bookmarks, bulk select/remove, collections or notes.
- Paginating a viewer playlist.

## Notes

- `list_media_bookmarks()` keeps missing rows and marks them with `missing`.
  The preview keeps the existing placeholder rather than hiding the item.
- Do not sum `PER_PAGE` and `GALLERY_PER_PAGE` for the 6-item mixed preview.
  Trim the merged, ordered items to 6 in Python or with the window function.
