# T12.4 — Extract a source-neutral HTTP transport

## Goal

Keep the hard-won cache/retry/backoff/cooldown behaviour, but let each source
supply its own base URL, headers and pacing instead of hard-coding cum.st.

## Scope

- [ ] Move the transport out of `cumst/client.py` into a shared module (for
      example `src/monoke/net/client.py`):
      - [ ] `JsonApiClient(base_url, source_label, settings, conn, ...)`.
      - [ ] Same cache-first `get_json(path, params, fresh=...)` contract and
            `api_cache` table.
      - [ ] Same global semaphore, min-interval pacing, jitter, retries,
            `Retry-After`, cooldown and `MAX_CONSECUTIVE_429` behaviour.
      - [ ] Full URL (including the source base) remains the cache key.
- [ ] Make error classes source-neutral (`ApiError`, `ApiNotFound`,
      `ApiServerError`, `ApiTimeout`, `ApiDecode`, `ApiBlocked`,
      `ApiRateLimited`) and include the source label in messages. Keep the old
      names as aliases while callers migrate.
- [ ] Treat both of these as blocked, not as a normal 404:
      - [ ] `403` with an HTML DDOS-Guard challenge.
      - [ ] `403` with a JSON body (pawchive does this after rapid probes).
      Apply the existing cooldown; do not hot-retry.
- [ ] Per-source defaults:
      - [ ] cum.st: base `https://cum.st/api/v1`, min interval `0.25 s`,
            concurrency 4.
      - [ ] pawchive: base `https://pawchive.pw/api/v1`, min interval `1.0 s`
            (conservative), concurrency 2, timeout `30 s`.
- [ ] Configuration:
      - [ ] Keep `MONOKE_API_BASE`, `MONOKE_CONCURRENCY`,
            `MONOKE_TIMEOUT`, `MONOKE_CACHE_TTL` working for cum.st.
      - [ ] Add `MONOKE_PAWCHIVE_API_BASE`,
            `MONOKE_PAWCHIVE_MIN_INTERVAL`,
            `MONOKE_PAWCHIVE_CONCURRENCY`,
            `MONOKE_PAWCHIVE_TIMEOUT`.
      - [ ] Expose both through `Settings` without making the dataclass
            cum.st-only.
- [ ] `CumstClient` becomes a thin compatibility wrapper/subclass so existing
      tests and imports keep working until T12.5 completes.

**Tests**

- [ ] Existing client tests pass unchanged through the shim.
- [ ] The same cache/retry/backoff/429 tests run against a second base URL.
- [ ] A 403 HTML response raises `ApiBlocked`.
- [ ] A 403 JSON response raises `ApiBlocked` and does not retry.
- [ ] `Retry-After` is honoured on 429.
- [ ] Cache entries from two bases do not collide.
- [ ] No network in tests; `respx` only.

## Acceptance criteria

- [ ] No source-specific URL or label is left in the transport module.
- [ ] A pawchive client can be constructed with its own base and pacing while
      using the same cache and retry code.
- [ ] `uv run pytest` remains green offline.

## Out of scope

- Payload parsing, media URLs and the crawl loop (T12.5–T12.8).

## Notes

- The current client intentionally does not follow redirects. Keep that.
- Rate limiting is a first-class product concern on pawchive, not a polish
  item: the probe was blocked after only a handful of requests.
