# T11.5 — Slim viewer bar, top caption and overflow menu

## Goal

Make the merged viewer's bottom bar **thinner** by replacing the labelled post
buttons with icon-only arrows, and moving the secondary actions into a **three
dot** disclosure menu. Move the post title out of the bar to a **light, single
line caption** at the top of the overlay.

The bar keeps its T11.2 lifecycle: visible on open, auto-hides after 2.5 s idle,
can be pinned hidden, and the handle restores it.

## Locked layout

```
┌──────────────────────────────────────────────────────────────┐
│  Post title, muted, one line …                      [Close]  │
│                                                              │
│                  media / video stage                         │
│      [invisible left zone]        [invisible right zone]     │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ [↑] [↓]      3 / 12            [⋯] [⛶] [hide]          │  │
│  └────────────────────────────────────────────────────────┘  │
│                    [Show controls ˄]  (only when hidden)     │
└──────────────────────────────────────────────────────────────┘
```

- The bar is one slim row on desktop and must not grow taller than the icons.
- Post arrows are icon-only: `↑` / `↓` (or chevron glyphs), with tooltips and
  accessible names **Newer post** / **Older post**. No visible text labels.
- The three-dot button opens a disclosure containing **Go to post**,
  **Open original** and the **post bookmark** toggle.
- Expand, fullscreen and hide stay as icon buttons in the bar, in that order
  after the three-dot button.
- The title moves to the top-left chrome, above the stage, muted and truncated
  to one line.
- Close stays at the top-right so the bar can be hidden entirely.

## Current behaviour

- T11.2 renders visible **↑ Newer post** / **↓ Older post** labels and a
  status area with the title, counter, *Go to post* and *Open original* links.
- The bookmark toggle is a standalone icon in the bar.
- There is no overflow menu and no top caption.
- The bar's height is driven by two-line content on narrow screens.

## Scope

**Markup**

- [ ] Replace the labelled `data-lightbox-post-prev` / `data-lightbox-post-next`
      button text with icon-only glyphs. Keep the data hooks, `aria-label`,
      `title`, and `disabled` edge states.
- [ ] Remove the post title, *Go to post* and *Open original* links from
      `data-lightbox-controls`. The bar keeps only the post arrows, the media
      counter, the overflow trigger, expand, fullscreen and hide.
- [ ] Add a three-dot trigger inside the bar:
      - `aria-haspopup="true"`, `aria-expanded="false"`, `aria-controls`;
      - accessible name **More actions**;
      - opens a menu with, in order, *Go to post*, *Open original* and the
        post bookmark toggle.
- [ ] The menu contains exactly one bookmark control, reusing
      `partials/bookmark_button.html` (T4.9 contract) with its POST action,
      hidden `next`, target-specific accessible name and `aria-pressed`.
- [ ] Add a top caption hook (`data-lightbox-caption-title` or reuse
      `data-lightbox-title`) at the top-left of the overlay. Move the existing
      `data-lightbox-title` binding there; keep `data-lightbox-counter` in the
      bar.
- [ ] Keep `data-lightbox-post` and `data-lightbox-original` hooks, now inside
      the menu, so the controller can still update their `href`s.

**Menu behaviour**

- [ ] The menu is a disclosure, not an ARIA menu: a normal container with
      links/buttons, opened and closed by the trigger.
- [ ] Opening sets `aria-expanded="true"`, unhides the menu and moves focus to
      its first item (*Go to post*).
- [ ] Escape closes the menu and returns focus to the trigger before Escape
      can close the overlay.
- [ ] An outside click, another navigation action, or hiding/pinning the bar
      closes the menu.
- [ ] The menu opens **above** the bar and stays inside the viewport at 390 px.
- [ ] Menu actions that navigate or toggle bookmarks close it.

**Caption**

- [ ] The top caption shows the current post title, muted, at most one line,
      with `text-overflow: ellipsis` and `white-space: nowrap`.
- [ ] It exposes the full title via a `title` attribute.
- [ ] It appears in compact, expanded and browser fullscreen.
- [ ] It hides and returns with the same auto-hide/pin state as the bar.
- [ ] It never overlaps the close button; at 390 px its width leaves room for
      the close target.

**Styling**

- [ ] Reduce bar padding and control size on fine pointers: target roughly
      2.25–2.5 rem bar height with 1.75–2 rem icon buttons.
- [ ] Keep at least 44 × 44 px targets on coarse pointers.
- [ ] Keep the solid theme background, border, shadow, rounded corners and
      `z-index` above media and edge zones.
- [ ] Keep `env(safe-area-inset-bottom)` padding in the bar and handle.
- [ ] Keep focus-visible rings on every control, including the overflow
      trigger and menu items.
- [ ] The bar stays a single row on desktop; at 390 px the arrows, counter and
      three icon controls fit without horizontal scrolling.
- [ ] Expanded/fullscreen still reserves bottom space for the bar.
- [ ] `prefers-reduced-motion: reduce` keeps show/hide instant with no layout
      shift.

**Behaviour**

- [ ] Post arrows call the same `prev-post` / `next-post` actions and disable at
      the first/last post.
- [ ] The bookmark in the menu keeps the same post target and updates its
      pressed state when the post changes or the toggle succeeds.
- [ ] Keyboard `b` / `Shift+B`, arrow keys, edge zones, wheel, touch and Escape
      behaviour are unchanged.
- [ ] The hide timer still does not fire while focus is inside the bar/menu or a
      video is using native controls.
- [ ] Hiding the bar also closes the menu; the handle restores the bar and
      focuses the first control as in T11.2.

**Tests**

- [ ] Template: one overflow trigger, one menu, two icon-only post buttons with
      labels only in `aria-label`/`title`, one bookmark inside the menu, no
      post/original links outside the menu, one top caption hook.
- [ ] Template: the post arrow buttons still render `disabled` at the edges and
      the menu bookmark keeps the form POST / `next` contract.
- [ ] JS source/behaviour: toggle sets `aria-expanded`, opening focuses the
      first menu item, Escape closes and restores focus to the trigger, outside
      click closes, hiding the bar closes the menu.
- [ ] JS: title updates still land in the top caption, counter still updates in
      the bar, and post/original `href`s are still updated.
- [ ] Accessibility: overflow trigger and menu items have names and focus
      rings; the caption is not an accessible duplicate of the media label.
- [ ] CSS: slim bar dimensions on fine pointers, 44 px coarse-pointer targets,
      one-line ellipsis caption, menu positioned above the bar, no horizontal
      overflow, reduced-motion block.
- [ ] `node --check src/monoke/web/static/lightbox.js` and `uv run pytest` pass.

## Acceptance criteria

- [ ] The viewer bar is visibly thinner and shows only arrows, counter,
      overflow, fullscreen and hide.
- [ ] **Newer post** / **Older post** are discoverable through icon tooltips and
      screen-reader names, not visible text.
- [ ] *Go to post*, *Open original* and the post bookmark live behind the
      three-dot button and work with mouse, touch and keyboard.
- [ ] The post title sits lightly at the top, truncates to one line, and does not
      crowd the close button at 390 px.
- [ ] Auto-hide, pinned hide, handle restore and all existing keyboard/touch
      navigation behave exactly as in T11.2.

## Out of scope

- Changing the auto-hide timeout, hide/show state machine or fullscreen
  entry/exit (T11.2).
- Media (image/video) bookmark placement; only the post bookmark moves into the
  menu.
- Bookmark-library entry points (T11.3) and black-flash painting (T11.4).
- Per-user bar position or other preferences.

## Notes

- Prefer a plain disclosure (`aria-expanded` + `hidden`) over `role="menu"`;
  the items are ordinary links and a form button.
- Keep the T11.2 lifecycle helpers (`chromeCanHide`, `chromePinned`,
  `restoreControls`) intact; this ticket changes layout and adds one popover
  state, not the visibility model.
- Add a pure helper for the menu state if that keeps the Node tests small and
  the controller readable.
