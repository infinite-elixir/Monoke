# T4.10 — Gallery tile opens the viewer at that exact media item

## Goal

A click (or keyboard activation) on any gallery thumbnail — image, GIF or
video — opens the existing fullscreen viewer at **that exact media item**.
The gallery's T4.7 lightbox is removed, because the viewer replaces it.

## Current behaviour

- `gallery.html` renders `.gallery-thumb` as an `<a>` whose `href` is the
  raw edge media URL (`target="_blank"`). `data-gallery-item` and the
  `data-full` / `data-title` / `data-post-url` attributes feed the T4.7
  lightbox in `app.js`.
- `app.js` has the whole lightbox implementation (open, prev/next, arrow
  keys, `Esc`, click-outside) and `style.css` has `.lightbox*` and
  `body.lightbox-open` rules.
- `db.list_gallery_images()` returns one row per distinct `sha256` with the
  representative `post_id`, but **not** the post's `service_id` and **not**
  the file's index among the post's viewer-eligible media.
- The viewer already accepts `?post=<service_id>&i=<zero-based index>`
  (T8.1) and clamps the index. It renders `VIEWER_KINDS` in
  `COALESCE(position, 0), id` order.
- `_viewer_return_url()` understands only `from=gallery` and always returns
  the unfiltered gallery root, losing the current filters and page.
- `app.js` remembers `[data-viewer-open]` as a generic selector. That cannot
  distinguish one gallery tile from another.
- T4.8 proposed a three-dot menu with "Start viewer here" while keeping the
  lightbox. It is superseded; this ticket makes the tile itself the viewer
  entry.

## Scope

**Repository: a deterministic viewer target per tile**

- [ ] Extend the gallery row used by the page so every tile can build a real
      viewer URL:
      - `post_service_id` — the representative post's `posts.service_id`;
      - `viewer_index` — zero-based index of this file among that post's
        `VIEWER_KINDS` rows ordered by `COALESCE(position, 0), id`.
- [ ] When the same `sha256` exists on several posts, pick one deterministic
      representative: newest by `COALESCE(p.published, 0) DESC, p.id DESC`,
      then the file's `COALESCE(position, 0), f.id`. It must agree with the
      post title/link the tile currently shows.
- [ ] Compute `viewer_index` in SQL or in one batched follow-up query. A
      60-tile page must not issue one extra query per tile.
- [ ] Add the index for all three kinds (`image`, `gif`, `video`), not just
      images. Audio and other file kinds must not shift the index.
- [ ] Keep the existing dedupe, filters, sort and pagination semantics
      unchanged for now. T4.11 changes the grouping; it must not have to
      rediscover how to compute the viewer index.
- [ ] Expose a decorated `viewer_url` shaped like:
      `/c/{creator_id}/viewer?post={post_service_id}&i={viewer_index}&from=gallery&next={encoded gallery URL}`
      where the gallery URL is the current page including `q`, `tag`, `kind`,
      `orientation`, `min_bytes`, `from`, `to`, `sort`, `page` and the tile's
      focus fragment.

**Template**

- [ ] Change `.gallery-thumb` to a normal link to `image.viewer_url` with
      `data-viewer-open` and `data-viewer-focus="#gallery-{sha256}"`.
      Remove `target="_blank"`; the viewer is same-tab by design.
- [ ] Give each tile a stable id (`gallery-{sha256}`) so the viewer can
      return focus to it.
- [ ] Accessible name: `Open in viewer: {post title or filename}` with a
      `(video)` / `(gif)` suffix when useful. The existing visible play
      glyph, duration/kind badges and thumbnail stay.
- [ ] Do not nest the bookmark form or any other interactive control inside
      the anchor. The icon-only bookmark control (T4.9) remains a sibling.
- [ ] Remove the T4.7 lightbox markup from `gallery.html`:
      `#gallery-lightbox`, `[data-lightbox-*]`, its dialog role and caption.
- [ ] Keep the top-level "Open viewer" button in the gallery header
      (`?from=gallery&next=…`) so a user can still enter the viewer at the
      post's first item.
- [ ] When the gallery is empty or filtered to zero, the existing empty
      states stay; no viewer link is rendered for a missing tile.

**Viewer return path and focus**

- [ ] Extend `_viewer_return_url()` so an explicit local `next` path is
      accepted only through `_safe_next()` and only when it starts with
      `/c/{creator_id}/gallery`. Reject `//host`, absolute URLs, backslashes,
      CR/LF, encoded slashes/backslashes and any non-gallery path; fall back
      to the normal gallery root.
- [ ] Preserve the full gallery query string and the `#gallery-{sha256}`
      fragment in the return URL, so closing the viewer returns to the same
      filtered/paged gallery and scroll position.
- [ ] `app.js` must store the exact tile selector when
      `data-viewer-focus` is present, instead of always storing
      `"[data-viewer-open]"`. Keep the existing `[data-viewer-open]` /
      `[data-viewer-return]` fallbacks for the creator page and direct loads.
- [ ] `viewer.js` already restores the stored opener through
      `sessionStorage`; verify that closing the viewer from a gallery tile
      focuses that tile's anchor and that the hash also lands there when
      storage is unavailable.
- [ ] Opening a tile directly (deep link) still renders the viewer, and a
      direct viewer load without a valid `next` returns to the gallery root.
- [ ] The viewer keeps `?post`/`?i` in the URL via `replaceUrl()` as the user
      moves, so browser Back and a refresh preserve the current item.

**Remove the lightbox**

- [ ] Delete the gallery-lightbox functions and event handlers from
      `app.js`, including the arrow-key/`Esc` branches and the click-outside
      handling that only served the lightbox.
- [ ] Delete `.lightbox*`, `.lightbox-image`, `.lightbox-video`,
      `.lightbox-caption` and `body.lightbox-open` rules from `style.css` if
      no other page uses them.
- [ ] Remove `data-gallery-item` and lightbox-only `data-*` attributes, or
      rename them to the viewer-entry names above. Do not leave dead hooks.
- [ ] Keep the gallery thumbnail's "no full-size bytes on page load" rule.
      The anchor now points at a viewer page, so the raw edge URL must not be
      fetched by the grid.
- [ ] Update the gallery copy/help text that mentions a lightbox or "Open"
      semantics to say "Open in viewer".

**Video and GIF behavior**

- [ ] A video tile opens the viewer, where the existing `<video controls>`
      plays it. The gallery must not start inline playback or autoplay.
- [ ] A GIF opens the viewer as an animated image, same as today's viewer.
- [ ] Keyboard activation (Enter/Space) follows the link exactly like a
      pointer click.
- [ ] The thumbnail remains an `<a>`; do not add a JavaScript-only click
      handler as the primary path.

**Tests**

- [ ] Repository test: duplicate `sha256` across two posts resolves to the
      newest post, and `viewer_index` matches the index the viewer actually
      renders for image + GIF + video + audio rows.
- [ ] Route/template test: each tile renders one link whose `href` contains
      the expected `post`, `i`, `from=gallery` and encoded `next`; it has
      `data-viewer-open` and a unique `data-viewer-focus`/id.
- [ ] No-lightbox test: `gallery-lightbox`, `data-lightbox-*` and lightbox
      hooks are absent from the gallery response.
- [ ] Return-path test: an accepted local gallery URL with filters and a
      fragment is preserved; `//host`, absolute URL, backslash/CRLF and
      non-gallery paths fall back to the gallery root.
- [ ] Focus test: `app.js` stores `data-viewer-focus` when present and falls
      back to the old selector otherwise.
- [ ] Viewer test: `/viewer?post=…&i=N` renders media item N; an out-of-range
      index clamps as today.
- [ ] Update existing gallery tests that assert `data-gallery-item` or the
      lightbox to assert the viewer URL instead.
- [ ] `node --check src/monoke/web/static/app.js` and
      `node --check src/monoke/web/static/viewer.js` pass.
- [ ] Browser acceptance in Chromium and Firefox:
      - click the 1st, 5th and last tile in a filtered gallery and land on
        that exact item;
      - close the viewer and return to the same filters/page with focus on
        the originating tile;
      - a video tile plays inside the viewer, not inline;
      - Back/refresh preserves the current viewer item;
      - with JavaScript disabled, a tile still opens the viewer page (the
        viewer's existing JS navigation is unchanged).

## Acceptance criteria

- [ ] Clicking any gallery image, GIF or video opens the viewer at that exact
      item, not the post's first item.
- [ ] The T4.7 lightbox is gone; no tile opens a lightbox or a raw media URL
      in a new tab.
- [ ] The viewer return path preserves the gallery filters, page and sort,
      and restores focus to the originating tile.
- [ ] Invalid/malicious `next` values cannot redirect off the site.
- [ ] Gallery page load still requests only `img.cum.st` thumbnails; no
      full-size edge media is loaded until the viewer asks for it.
- [ ] Bookmark controls remain siblings of the thumbnail link and keep
      working with and without JavaScript.

## Out of scope

- Grouping tiles by post and paginating by post (T4.11).
- Making the viewer a client-side overlay inside the gallery page.
- Slide/swipe animation and preload changes (T8.7–T8.10).
- Changing the viewer's close/fullscreen semantics.
- Removing the post page's own media viewer or the bookmarks library grid.
- Download, copy-link, hide or delete actions on tiles.

## Notes

- The viewer is post-scoped; the gallery is media-deduped until T4.11. The
  representative post and the viewer index must come from the same row.
- `filters.url_for(creator_id)` already builds the current gallery path and
  query string. Use it for both the encoded `next` and the viewer return path,
  then append the tile fragment.
- The gallery's top "Open viewer" link uses the same return-path mechanism
  and should focus the header link, not a tile.
- T4.8's "Start viewer here" requirement is satisfied by the tile link; do
  not implement T4.8's disclosure menu.
- T4.11 will make each tile's post the actual section owner, so the
  representative-post logic in this ticket becomes trivial then. Keep the
  viewer-index calculation in one shared helper so T4.11 does not duplicate
  it.
