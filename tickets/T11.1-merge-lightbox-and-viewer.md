# T11.1 — Merge the gallery lightbox and the fullscreen viewer

## Goal

Make the gallery tile lightbox and the fullscreen viewer **one surface**. A tile
opens the lightbox in place; expanding it turns the same DOM into the
full-viewport viewer. There is no separate `/c/{creator}/viewer` page any more.

The merged surface keeps the target lightbox's no-JS link fallback, the viewer's
post-scoped navigation, bookmark toggles, keyboard shortcuts, focus handling and
image preloading, but presents them through one controller and one template.

## Locked decisions

| Question | Decision |
|---|---|
| All viewerports | Tile opens the compact lightbox; an expand action turns it into an in-page full-viewport viewer; the fullscreen action can then request real browser fullscreen. Escape unwinds one layer at a time. |
| Existing HTML viewer route | Delete `/c/{creator}/viewer`, `viewer.html` and `viewer.js`. No links to that page remain. |
| JSON data | Keep `/c/{creator}/viewer/data` as an internal read-only JSON endpoint for post playlists, neighbour payloads and preloading. It is not a viewer page and must not render HTML. |
| Gallery tile playlist | Tile opens the player on its post; left/right stays inside the post, up/down crosses posts. |
| Lightbox root | Reuse `#gallery-lightbox` and its `data-lightbox-*` hooks rather than introducing a second competing root. |

## Current behaviour

- `gallery.html` renders `#gallery-lightbox` with only `data-lightbox-image`,
  `data-lightbox-video`, title, counter, post/original links and prev/next/close
  buttons.
- `app.js` `gallerySetup()` / `galleryOpen()` collect `[data-gallery-item]` from
  `[data-gallery]`, set `src` on one visible `<img>` and swap it on every step.
  There is no post payload and no cross-post navigation.
- `viewer.html` renders a separate page with `viewer.js`, which owns
  post-scoped render/unload, payload fetching and caching, neighbour preload,
  keyboard/wheel/swipe handling, bookmarks, hint, toast and fullscreen.
- `creator.html` links **View latest** to `/c/{id}/viewer`; `gallery.html`
  links **Open viewer** to `/c/{id}/viewer?from=gallery`.
- `routes.py` `creator_viewer()` renders `viewer.html`; `creator_viewer_data()`
  returns the JSON state at `/c/{creator}/viewer/data`.
- The gallery already computes a post playlist order (`COALESCE(position, 0),
  id`) but the tile markup does not expose the post service id, sha or index.

## Scope

**One overlay and one controller**

- [ ] Extend the existing `#gallery-lightbox` markup into the merged surface:
      keep `#gallery-lightbox`, `data-lightbox-image`, `data-lightbox-video`,
      `data-lightbox-title`, `data-lightbox-counter`, `data-lightbox-post`,
      `data-lightbox-original`, `data-lightbox-prev`, `data-lightbox-next` and
      `data-lightbox-close`. Add the viewer-only hooks (`data-lightbox-stage`,
      `data-lightbox-announcer`, `data-lightbox-toast`,
      `data-lightbox-fullscreen`, `data-lightbox-expand`) as needed.
- [ ] Move the gallery lightbox controller out of `app.js` into a dedicated
      `static/lightbox.js` loaded on pages that render the overlay. It must own
      both the compact and expanded states; do not keep two navigators.
- [ ] Port the still-needed viewer logic into that controller: post payload
      fetch/cache, post crossing, payload prefetch, image preloading, bookmark
      toggle, `b` / `Shift+B`, toast and announcer. Delete `viewer.js` after
      the port.
- [ ] Delete the `GET /c/{creator_id}/viewer` HTML route, `viewer.html`, the
      `viewer.js` script block and the viewer-page-only CSS. Keep
      `GET /c/{creator_id}/viewer/data` exactly as the JSON payload API.
- [ ] Remove every link or redirect to the deleted page: change gallery
      **Open viewer** to a button that opens the overlay at the first tile;
      change creator **View latest** to **Gallery** (or to
      `/c/{id}/gallery`). Do not leave a dead `/viewer` href.
- [ ] Update `tests/test_viewer.py` into tests for the merged surface and JSON
      endpoint; add route tests asserting the old HTML route is gone (404/405)
      while `/viewer/data` still answers JSON.

**Tile bootstrap**

- [ ] Add tile attributes without adding viewer-page links:
      `data-post-service-id`, `data-sha256` and the viewer index. The gallery
      query already has the playlist order; use it so a tile can open at the
      exact item.
- [ ] Opening a tile must paint its thumbnail or full URL immediately from the
      tile data, then hydrate the post playlist from `/viewer/data` in the
      background. Do not block the first paint on the JSON request.
- [ ] While the payload is loading, left/right may step through the tiles
      already present in `[data-gallery]`; up/down waits for the post payload.
      A failed payload request keeps the current item visible and flashes a
      non-blocking error.
- [ ] Preserve the no-JS contract: the tile is still an `<a>` to the original
      media URL, so without JavaScript it opens the file directly.

**Fullscreen model**

- [ ] Three states with one control path: `compact` (in-page modal), `expanded`
      (in-page viewport overlay) and `browser` (real Fullscreen API on the
      overlay root).
- [ ] Desktop opening: tile → `compact`. The expand control → `expanded`.
      The fullscreen control → `browser` (requesting fullscreen from the
      current state). Pressing Escape exits `browser` first, then `expanded`,
      then closes the overlay.
- [ ] Mobile opening: tile click → `expanded` and request fullscreen
      synchronously inside the gesture. Denial/unavailability silently keeps
      `expanded`.
- [ ] Track `compact`, `expanded` and `browser` as classes/attributes on the
      root so CSS and tests can assert the state. Only one state is active.
- [ ] Preserve body scroll lock, focus trap, `Esc`, `F`, arrow keys, wheel and
      touch navigation; return focus to the originating tile on close.
- [ ] Browser fullscreen must not hide the sticky control bar; in-page
      `expanded` and browser fullscreen use the same bottom bar from T11.2.

**Entry points**

- [ ] Gallery tiles open the merged overlay.
- [ ] The gallery's page-level **Open viewer** button opens the overlay on the
      first tile of the current page without navigating.
- [ ] The creator page no longer links to a dead viewer route.
- [ ] Video tiles keep native controls; image/GIF tiles keep the lightbox
      original-file link.

**Tests**

- [ ] Route: `/c/{id}/viewer` is gone, `/c/{id}/viewer/data` still returns
      JSON, and no template renders `/c/{id}/viewer` as an href.
- [ ] Template: `#gallery-lightbox` still contains all legacy lightbox hooks
      plus the stage/fullscreen/expand hooks.
- [ ] Controller source tests: no `viewer.html`/`viewer.js` references remain;
      gallery and viewer use the same root; the old page controller is not
      loaded.
- [ ] Payload tests: opening a tile selects the requested item, left/right
      steps within the post, up/down crosses posts, and a failed payload keeps
      the current item.
- [ ] Keyboard/focus tests: Escape unwinds browser → expanded → closed, `F`
      toggles browser fullscreen, focus returns to the originating tile.
- [ ] No-JS test: a gallery tile still has a working `href` to the media file.
- [ ] `node --check` passes for `app.js` and `lightbox.js`; `uv run pytest` is
      green offline.

## Acceptance criteria

- [ ] A gallery tile opens one overlay; expanding it becomes the viewer; there
      is no page navigation and no second lightbox implementation.
- [ ] On desktop the sequence compact → expanded → browser fullscreen works;
      on mobile the overlay requests fullscreen immediately and gracefully
      falls back to expanded.
- [ ] The old `/c/{id}/viewer` page, template and script are deleted; JSON
      data still powers post navigation.
- [ ] Prev/next media, prev/next post, bookmark shortcuts, focus return and
      preloads behave as they did in the old viewer.
- [ ] No gallery or creator page links to a dead viewer URL.
- [ ] The target lightbox no-JS fallback is preserved.

## Out of scope

- The sticky bottom control bar layout (T11.2) and the hide/show button.
- Bookmark-library entry points (T11.3).
- The first-forward black-flash paint fix (T11.4).
- A creator-wide manifest or filter-aware viewer.

## Notes

- Do not hand-copy `viewer.js` into `app.js`; extract only the behaviour the
  merged surface needs and delete the rest.
- The JSON payload is already post-scoped. Keep its shape stable so T11.3 and
  T11.4 can build on it.
- The gallery tile's `viewer_index` must count the same raw `VIEWER_KINDS` rows
  the post payload returns; do not compute it from the filtered tile subset.
