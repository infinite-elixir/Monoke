# T4.9 — Icon-only bookmark controls and viewer fullscreen icon

## Goal

Replace the visible text on every bookmark control with a bookmark icon, and
replace the viewer's **Fullscreen** / **Exit fullscreen** text with a
fullscreen icon. The controls keep their current form POST / keyboard
contracts and their accessible names; only the visible presentation changes.

## Current behaviour

- `partials/bookmark_button.html` renders one macro used by:
  - creator-page post rows (`partials/post_row.html`),
  - the post page header and per-attachment rows (`post.html`),
  - gallery tiles (`gallery.html`),
  - the bookmarks library post and media tiles (`bookmarks.html`).
- The macro renders a text label, `Bookmark` or `Bookmarked`, inside
  `.bookmark-button`. `T9.2` deliberately made the text change part of the
  accessible state ("filled/active state must not rely on colour alone").
- `app.js` (`toggleBookmarkForm`) progressively enhances the form and writes
  `button.textContent = on ? "Bookmarked" : "Bookmark"` after a JSON POST.
- The gallery tile's bookmark-only action menu and the bookmarks-media tiles
  position `.gallery-bookmark` near the tile's top-right corner. The text
  button is wider than the icon will be.
- The viewer's chrome is `viewer.html`:
  `<button class="viewer-fullscreen" data-viewer-fullscreen>Fullscreen</button>`.
  `viewer.js` (`updateFullscreenControl`) rewrites its `textContent` and
  switches it between `Fullscreen` and `Exit fullscreen`. T8.8 hides the
  control until the user moves the pointer, presses a key or focuses it;
  that behaviour must stay.
- The bookmarks empty state tells the user to use the "Bookmark" button.

## Scope

**One bookmark icon component**

- [ ] Change `partials/bookmark_button.html` only: every surface that calls
      the macro gets the icon automatically. Do not fork the markup per page.
- [ ] Render an inline `<svg>` bookmark glyph inside the submit button, with
      `aria-hidden="true"` and `focusable="false"`. No icon font, CDN, sprite
      fetch or build step.
- [ ] Remove the visible `Bookmark` / `Bookmarked` text node. The button
      becomes icon-only visually.
- [ ] Keep the existing target-specific `aria-label` (`Bookmark post: …`,
      `Bookmark image: …`, etc.) as the accessible name. Add a `title` with a
      short action name for pointer users; it must not replace the
      `aria-label`.
- [ ] Keep `aria-pressed="true|false"` and `data-bookmark-target`.
- [ ] Keep the `<form method="post">`, the hidden `next` value,
      `data-bookmark-form` and the no-JavaScript contract unchanged.
- [ ] Render the active state with a **filled** glyph and a visible button
      background/border change. Inactive is an outline glyph. Do not rely on
      colour alone: the fill, `aria-pressed` and the accessible name must all
      change together.
- [ ] Provide a visually hidden `<span>` with the state word
      (`Bookmarked` / `Bookmark`) only if it is needed for non-AT text
      fallback; it must not be visible and must not create a second
      accessible name that contradicts `aria-label`. Prefer `aria-pressed`
      plus `aria-label` if a hidden span is not necessary.
- [ ] The button must remain keyboard-reachable and keep a visible
      `:focus-visible` ring.
- [ ] Size the icon control with square padding and a stable width/height so
      swapping state does not shift the layout. Aim for a 44 × 44 CSS px hit
      area on coarse pointers and at least 32 × 32 on mouse layouts; do not
      cover the gallery play glyph, kind badge, duration badge or post-card
      title link.

**JavaScript enhancement**

- [ ] `app.js` must no longer write the words `Bookmark`/`Bookmarked` into the
      button. On success it toggles `is-bookmarked` and `aria-pressed` only.
- [ ] Keep the button disabled during the request and restore it afterwards.
- [ ] A failed request leaves the previous icon state and shows the existing
      flash, exactly as today.
- [ ] No page-load DOM work is added; the enhancement still binds through the
      existing delegated submit handler.

**Gallery and bookmarks-library tiles**

- [ ] The icon-only control stays a sibling of `.gallery-thumb` inside the
      tile's bookmark-only action menu, absolutely positioned top-right. It
      must not overlap the anchor's click target or the badges.
- [ ] The smaller control must not cover a meaningful part of a 2-column
      phone tile. Check the 390 × 844 viewport.
- [ ] The bookmarks media tile keeps `is-missing` tiles without a bookmark
      control, as today.

**Viewer fullscreen icon**

- [ ] Replace the text in `viewer.html` with two inline SVG glyphs:
      expand/corners for **Enter fullscreen**, contract/corners for
      **Exit fullscreen**. Only one is visible at a time; the hidden one is
      `aria-hidden="true"`.
- [ ] Keep the element `data-viewer-fullscreen`, its
      `aria-pressed="false"` initial value, and the dynamic
      `aria-label` (`Enter fullscreen` / `Exit fullscreen`).
- [ ] Update `viewer.js` `updateFullscreenControl()` to toggle a state class
      or `data-fullscreen-state` and swap which glyph is visible. Do **not**
      write `textContent`.
- [ ] Keep the T8.8 chrome rules: hidden at rest, revealed on interaction,
      `is-revealed` on focus, and the existing `F` shortcut.
- [ ] Icon size and background must preserve the current contrast over light
      and dark media; the button must retain a visible focus ring.
- [ ] The first-run hint's `F for fullscreen` note stays.

**Copy**

- [ ] Update the bookmarks empty-state text that currently says
      "Bookmark button" to refer to the bookmark icon (and, where relevant,
      "bookmark icon on a tile").
- [ ] Do not rename endpoints, routes, CSS classes used by tests unless the
      test is updated in the same change.

**Tests**

- [ ] Template test: every rendered bookmark control contains an `<svg>`,
      has a target-specific `aria-label`, keeps `aria-pressed`, and contains
      no visible text `Bookmark`/`Bookmarked`.
- [ ] Assert the bookmarked state has `is-bookmarked="true"`-equivalent
      markup (class and `aria-pressed="true"`) and that the filled glyph is
      the active one.
- [ ] Cover all surfaces: creator post row, post page header, attachment row,
      gallery tile and bookmarks-library post/media tile.
- [ ] No-JS form POST still toggles and redirects to the hidden `next` URL.
- [ ] `app.js` test/source check: the JSON success path does not assign
      `textContent` on the bookmark button; it toggles class and
      `aria-pressed`.
- [ ] Viewer template test: exactly one fullscreen control, two glyphs, the
      enter glyph visible initially, the exit glyph hidden, and the
      accessible label present.
- [ ] `viewer.js` source/behaviour test: `updateFullscreenControl` toggles
      the state and label but does not set `textContent`.
- [ ] `node --check src/monoke/web/static/app.js` and
      `node --check src/monoke/web/static/viewer.js` pass.
- [ ] Browser acceptance in Chromium and Firefox:
      - bookmark/unbookmark from every surface with JavaScript enabled and
        disabled;
      - the icon visibly changes state without layout shift;
      - keyboard focus shows the ring and the accessible name is announced;
      - gallery and bookmarks tiles at 390 px do not cover badges or the
        thumbnail click target;
      - the viewer's fullscreen icon enters and exits fullscreen and is still
        hidden until the user interacts.

## Acceptance criteria

- [ ] No bookmark control on any page shows the words `Bookmark` or
      `Bookmarked` visually.
- [ ] Every bookmark control still toggles the same backend state, works
      without JavaScript, preserves `next`, and exposes a target-specific
      accessible name and `aria-pressed`.
- [ ] The bookmark state is obvious without colour: outline vs filled glyph
      plus `aria-pressed`.
- [ ] The viewer fullscreen control shows an icon in both states and has no
      visible `Fullscreen` / `Exit fullscreen` text.
- [ ] T8.8's reveal-on-interaction behaviour, the `F` shortcut, bookmark
      keyboard shortcuts and all existing gallery/post behavior still work.
- [ ] No new network requests, dependencies or page-load observers are added.

## Out of scope

- Redesigning the bookmark state model or endpoints (T9.1).
- Adding labels back on hover-only via CSS tooltips other than the native
  `title`.
- Changing the icon set for other controls (theme, blur, copy, download).
- Moving bookmark controls to different positions.
- The gallery click behavior and post grouping (T4.10, T4.11).

## Notes

- Use one SVG path for the bookmark shape and drive fill through CSS:
  `.bookmark-icon { fill: none; stroke: currentColor; }` and
  `.is-bookmarked .bookmark-icon { fill: currentColor; }`. This keeps the
  macro small and makes the state change testable.
- The visible text was the only non-colour cue in T9.2. The filled glyph is
  the replacement cue; `aria-pressed` carries it to assistive technology.
- Gallery and bookmarks tiles use the same macro; do not add a separate
  `icon_only` flag unless a surface genuinely needs a different accessible
  name.
- `viewer.js` is dependency-free; keep the icon swap as class/DOM-attribute
  toggling, not string-built SVG.
- `app.js` currently runs `button.textContent = ...`; leaving that line in
  place would delete the SVG after the first toggle. This is the most likely
  regression in the ticket.
