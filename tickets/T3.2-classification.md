# T3.2 — Normalization and classification

## Goal
Every link gets a stable identity and a category the UI can facet on.

## Scope

- [x] `normalize(url) -> str`:
      - lowercase scheme + host, strip default ports
      - strip fragment, `utm_*`, `fbclid`, `gclid`
      - keep all other query params, sorted
      - strip trailing `/` on path except root
- [x] `classify(url, label=None) -> Category` with the taxonomy from PLAN §7:
      `google_drive`, `mega`, `direct_media`, `video_host`, `shortener`, `social`,
      `cloud_other`, `site_asset`, `image`, `other`.
- [x] Label fallback: if the host is unknown but the anchor text says MEGA/DRIVE/MP4, keep the
      host-based category and record `label` — do not invent a category from a label alone.
- [x] `direct_media` recognizes extensions case-insensitively: `.mp4 .webm .mov .m4v .gif .gifv`.
- [x] Dedupe per post on `normalized_url`; keep the first label, prefer a labelled row over an
      unlabelled duplicate.
- [x] Category is a Python `Enum`; DB stores `.value`.

## Acceptance criteria

- [x] `https://mega.nz/file/abc#frag` → `mega`; fragment dropped in `normalized_url`.
- [x] `https://files.catbox.moe/x.mp4?utm_source=a` → `direct_media`, `utm_source` stripped.
- [x] `https://drive.google.com/file/d/ID/view?usp=sharing` → `google_drive`.
- [x] `https://redgifs.com/watch/x` → `video_host`.
- [x] `http://bit.ly/49A802v` → `shortener` **before** resolution; after T3.3 it becomes `mega`.
- [x] Same link twice in one post → one row.
- [x] Table-driven tests, ~30 cases including malformed URLs (must not raise).

## Notes
- Classification is intentionally host-first and deterministic. No ML, no guessing.
- `other` is a valid, visible category — we store and show everything (`PLAN` decision #2).
