# T3.1 — Link extraction from captions

## Goal
Pull every URL out of a post caption, with its label and origin, without losing anything.

## Scope

- [x] `extract_links(post_detail) -> list[LinkRow]` (pure function, no DB).
- [x] Sources, in order:
      - `<a href>` in `post.caption` (raw HTML) → `origin="caption"`,
        `label` = anchor text (trimmed, entities decoded, whitespace collapsed).
      - bare URLs in text nodes → `origin="caption"`, `label=None`.
      - `<img src>` in the caption → `origin="caption"`, category hint `image`.
      - `post.links[]` **if non-empty** (it is empty on every post sampled; merge defensively)
        → `origin="api_links"`.
- [x] Parse with BeautifulSoup + `lxml`; never string-replace HTML.
- [x] Resolve relative URLs against `https://cum.st`.
- [x] Ignore `javascript:`, `mailto:`, `data:`; keep `magnet:`.
- [x] Cap: 500 links per post; if exceeded, keep the first 500 and return a warning on the post
      result rather than failing.
- [x] Label fallback: if the anchor text is empty, use the hostname.

## Acceptance criteria

- [x] `post_172189145` → the two download links: `drive.google.com/...` (label `Link`)
      and `mega.nz/...` (label `Backup Link`). The live post also carries five credit
      links (smutba.se, x.com, twitter.com), which are kept as required by "store every link".
- [x] `post_151983862` → 0 links, caption parses without error.
- [x] A synthetic caption with `<a href="javascript:alert(1)">x</a>` → 0 links.
- [x] Bare URL in plain text is captured with `label=None`.
- [x] Duplicate `href` within one post is collapsed by T3.2 (one row).
- [x] Pure-function tests over fixtures; no network.

## Notes
- Use `caption`, not `captionHtml`, for extraction: the raw version has the original hrefs and
  fewer injected attributes. Use `captionHtml` for rendering.
- The site's own `links` array is unreliable/empty — never treat it as the source of truth.
