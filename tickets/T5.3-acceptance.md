# T5.3 — Acceptance run, README, packaging

## Goal
Prove the thing works end to end on the reference creator and hand over a repo someone can run
in one command.

## Scope

- [x] Acceptance run, recorded in `docs/ACCEPTANCE.md` with real numbers:
      - fresh DB → `monoke sync https://cum.st/creators/patreon/274608`
      - assert 782 posts, 16 list pages, all caption links, attachment count
      - second sync timing and call count
      - export CSV and JSON, row counts
      - one full rescan, identical counts.
- [x] README: what it is, screenshots, install (`uv sync`), run (`uv run monoke serve`),
      sync from CLI, data location, `--workers 1` requirement, limitations
      (no media mirroring or auto-fetch, per-attachment Load button, 60 s upstream cache,
      refresh window, shortener resolution).
- [x] `docs/DECISIONS.md`: the 12 locked decisions from PLAN §1, one line each with rationale.
- [x] `data/` never committed; `.gitignore` verified.
- [x] Backup/restore note: `cp data/monoke.db` is a complete backup; `sqlite3 .backup` for live.
- [x] Version `0.1.0`; `monoke --version` works.
- [x] Optional: `scripts/demo.py` that seeds 20 posts from fixtures so the UI can be shown
      offline.

## Acceptance criteria

- [x] Clean clone + `uv sync` + `uv run monoke serve` works with no manual steps.
- [x] The acceptance numbers in `docs/ACCEPTANCE.md` are reproducible and match the DB.
- [x] `uv run pytest` green offline; `MONOKE_LIVE=1 uv run pytest -m live` green.
- [x] No secrets, no absolute personal paths, no `data/` in git.
- [x] README states the private-use scope and the no-mirroring limitation plainly.
