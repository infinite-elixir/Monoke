# T12.7 — Source-aware extraction and media persistence

## Goal

Stop the extractor from assuming cum.st's media URL scheme, and persist the
extra attachment facts pawchive supplies (`preview_only`, absolute URLs) without
losing cum.st's richer metadata.

## Scope

- [ ] Move the pure classifier out of `cumst/media.py` into a shared
      `src/monoke/media.py`:
      - [ ] `classify_media_kind(...)`, extension helpers, `ext_for(...)`.
      - [ ] Update imports in `extract/post.py`, `db.py` and tests.
      - [ ] Keep a re-export in `cumst/media.py` only if needed for one release.
- [ ] Extend the canonical `Attachment` model with:
      - [ ] `url: str | None`
      - [ ] `thumb_url: str | None`
      - [ ] `preview_only: bool = False`
      - [ ] (existing `variants` may carry per-variant URLs)
- [ ] Refactor `extract/post.py` so it never calls `cumst.media.media_url` or
      `thumb_url` directly:
      - [ ] use `attachment.url` / `attachment.thumb_url` when the adapter
            supplied them;
      - [ ] fall back to the source adapter's URL builder only when they are
            absent;
      - [ ] keep dedupe by sha256 and lowest-position selection;
      - [ ] add `preview_only` to each file row;
      - [ ] keep `raw_kind` and the normalized `kind`;
      - [ ] keep `variants_json` populated (one original variant is enough for
            pawchive).
- [ ] `db._write_files` persists `preview_only`; `db.list_files`,
      `db.list_media_bookmarks` and gallery queries return it.
- [ ] `extract/classify.py`: add `file.pawchive.pw`, `img.pawchive.pw` and
      `n2.pawchive.pw` (and any edge pattern) to the `site_asset` rule, or make
      the host set source-provided. Do not classify pawchive CDN URLs as
      `other`.
- [ ] `extract/sanitize.py` stays source-neutral; the caller passes the
      adapter's `image_hosts()` to `lazy_images`.
- [ ] No media bytes are downloaded. Preview-only files still have a URL row;
      the UI decides what to do with it.

## Acceptance criteria

- [ ] A cum.st fixture still produces exactly the same file rows (URL, thumb,
      variants, kind, raw_kind) as before; assert with a snapshot.
- [ ] A pawchive fixture produces one row per unique sha with:
      `url=file.pawchive.pw/...`, `thumb_url=img.pawchive.pw/thumbnail/...`,
      `preview_only=1` where applicable, and `NULL` dimensions/duration.
- [ ] Duplicate attachments in a post are stored once.
- [ ] `classify_media_kind` still passes its existing table tests from T7.1.
- [ ] `uv run pytest` is green offline.

## Out of scope

- Crawling and sync (T12.8).
- Gallery/viewer presentation changes for preview-only media (T12.9).
- Downloading or unpacking archives.

## Notes

- Keep `files.sha256` as the stable local identity; pawchive's hash stem is the
  natural value, and the bookmark tables already key on it.
- `preview_only` must survive re-syncs and media bookmarks, like the rest of
  the file row.
